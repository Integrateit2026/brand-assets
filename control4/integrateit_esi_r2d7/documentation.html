1 Start here

IntegrateIT ESI R2D7 Shades turns one Control4 serial port into full command of an ESI R2D7 shade interface (also sold as the Draper R2D7 / IntelliFlex RS232) — open, close, and stop for any system address and any of the 60 RP60 motor channels per system, with a configurable travel duration, an all-systems emergency stop, and an advanced raw-frame sender. Frames follow the manufacturer-published R2D7 V4.1 protocol; a paced transmit queue that also honors the unit's XON/XOFF flow control keeps the R2D7's 120-byte buffer healthy.

The R2D7 link is acknowledgement-only. The unit answers LF for a good command and U for a bad one — but it has NO position query and NO status report. Every state this driver shows is assumed from the last command it sent. A wall switch or handheld radio control moving a shade is invisible to the driver. No software update can add position feedback to this hardware; anything claiming otherwise would be faking it.
Ready for controlled commissioning. The package, Lua 5.1 runtime, frame grammar, duration model, flow control, acknowledgement parser, raw-frame validation, command pacing, license gate, persistence, and documentation pass automated QA. A qualified dealer must still complete a fresh install and an observed shade-control test against a real R2D7 + RP60 stack on the target controller.

What you get

  • Open / Close / Stop for the selected system address (0-99) and channel (1-60, or ALL)
  • Travel duration: run to the calibrated motor limits (default) or an explicit 1-50 s burst
  • Stop All Systems — the documented *0s everything-halts frame, one action away
  • A paced transmit queue that honors the R2D7's documented XOFF/XON flow control, with a lost-XON recovery guard
  • Acknowledgement diagnostics: acks counted, U rejections raised as a Command Rejected event, buffer purges reported
  • A validated raw-frame sender for explicit address/channel/duration frames (*3c05015)
  • Honest assumed-state tracking: Command Sent plus Shade Assumed Open / Closed / Stopped events and programming variables

2 The acknowledgement-only contract

The R2D7 is a serial-to-RP-bus bridge: your controller talks to it, it relays to the RP60 motor controllers, and the only things that ever come back are acknowledgement bytes, flow control, and the occasional text banner — never a position. This driver is deliberately honest about that:

  • The Assumed State property and ASSUMED_STATE variable are dead-reckoned from the commands this driver sent — nothing more.
  • After a controller reboot every channel restarts at Unknown. No travel is observable across a reboot on an acknowledgement-only link, so nothing else would be truthful.
  • With Active Channel at 0 (ALL) the display aggregates: one shared state when every channel agrees, Mixed when they do not.
  • There is no Navigator shade proxy promising position on purpose. Programming reacts to the events and variables below; position sliders would be fiction.

3 Wire and commission

  1. Wire the RP60 motor controllers to the R2D7's RP bus and calibrate each motor's limits per ESI's instructions. The driver's run-to-limits default relies on those limits.
  2. Wire a controller or IO-extender RS-232 port to the R2D7's RJ14 jack through a DB9F-to-RJ14 adapter (Yellow=Rx, Green=Tx, Black=GND, Red unused): 9600 baud, 8 data bits, no parity, 1 stop bit.
  3. Add IntegrateIT ESI R2D7 Shades to the project and bind R2D7 Serial Port (binding 1) to that port in Connections.
  4. Set System Address to the system port the target motors live on (BUS ports are 1-7; radio addresses 7-99 need an ESI RFTM in the port 7 jack; 0 addresses ALL systems).
  5. Set Active Channel to a motor channel and run Shade Open / Shade Close / Shade Stop from the Actions tab. Watch the shade — the driver cannot.
  6. Confirm the wire with Query Version: a healthy R2D7 answers into Interface Report (e.g. 4.1 plus r/b for radio-vs-bus mode).
Draper markets the R2D7 specifically to "provide third party control" over RS-232 ASCII commands; this driver implements that published serial contract with original IntegrateIT engineering.
The R2D7 itself has NO authentication — anything with a wire to its jack controls every motor on all 7 system buses. If you front it with an IP-to-serial bridge (Global Cache iTach etc.), that bridge exposes unauthenticated shade control to the LAN. Put it on a secured VLAN.

4 Frames on the wire

Each frame is plain ASCII: *, the system address, one command letter, a two-digit channel, an optional three-digit duration in 20ths of a second, and the terminator (; or CR — configurable, both documented). Examples:

Wire frameMeaning
*1o01000;System 1, open channel 1, run to the motor limits (000 = forever)
*3c05015;System 3, close channel 5 for 0.75 s (15 twentieths)
*1c00000;System 1, close ALL channels to their limits
*1s01;System 1, stop channel 1
*0s;Stop EVERYTHING on every system
*V;Report the R2D7 firmware version (an administration command — no subsystem number)

Travel Duration maps to the duration field: 0 (default) sends the documented forever code 000 so the motor runs to its calibrated RP60 limit; 1-50 seconds send that duration in the protocol's 20ths-of-a-second field (5 s → 100, always three digits). Command Spacing paces the queue (default 150 ms), and the driver additionally parks the queue the moment the R2D7 signals XOFF, resuming on XON — or after a 5-second guard if the XON is lost. Commands issued faster than the wire allows are queued in order, never dropped.

6 Raw frames (advanced)

Put one full R2D7 frame in the Raw Command property and run Send Raw Command. The driver validates before anything touches the wire:

  • A normal frame is exactly *<address 0-99><letter>[CC][DDD] — channel 00-60, duration only after a channel, three digits
  • The version query is the administration frame *V — V replaces the subsystem number, so it is *V, never *1V
  • Commands are case-sensitive and lowercase (o is not O): movement letters o/c/s, wind w, and quit q are accepted
  • Omit the terminator; the driver appends the configured one
  • The motor-programming letters p/a and the port-7 mode letters R/B are refused — programming and radio/bus mode belong to a commissioning tech at the hardware, not to a control-system command path

A refused frame never transmits; Last Error and Status name the reason. An accepted o / c / s frame addressed to this driver's system (directly or via address 0) updates the assumed state for its channel; w (wind) and q (quit a forever-send) transmit but claim no state.

To drive several shades from programming, set Active Channel first, then invoke Shade Open / Shade Close / Shade Stop — Composer can write the property and call the command back-to-back; the pacing queue keeps the wire happy. Stop All Systems is the panic button: every motor on every system halts.

Three recipes using this driver's real surfaces:

  • Goodnight → set Active Channel to 0 (ALL) and run Shade Close; one frame closes every channel on the system and fires Shade Assumed Closed exactly once.
  • Wake scene → set Active Channel to the bedroom motor and run Shade Open; use the Shade Assumed Open event as the hook that raises that room's lighting in the same program.
  • Malformed-frame alert → on Command Rejected, surface Last Error to the installer. A U means a wrong-case or malformed frame reached the unit — on an acknowledgement-only link that event is the only wire-level signal you get.

Control commands are gated by the license: under Strict enforcement an unlicensed controller writes nothing to the serial port; the default Lenient mode allows commissioning while License Status carries the nag. The acknowledgement parser is never license-gated — a power-up banner, a U, or a buffer purge still lands in Interface Report / Last Error, because reading the wire is not a licensed feature.

It does not bundle another vendor's runtime, source code, brand assets, trial system, or license. ESI, R2D7, and IntelliFlex are trademarks of their respective owners (Electronic Solutions, Inc. / Hunter Douglas and Draper, Inc.); IntegrateIT is not affiliated with them, and this driver is not an ESI, Hunter Douglas, or Draper product. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

The driver sends shade commands to your R2D7 and nothing anywhere else. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks all serial control until the Ops Portal has minted and validated a key for that controller. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

  • Command validation is now case-sensitive, per the spec's "case is important: o is different from O." V/R/B are field-2 administration commands that replace the subsystem number; `*1V` was parsed by the unit as subsystem 1 plus an illegal command letter and answered with a bare `U`. The raw sender now accepts `*V`, refuses the `*R`/`*B` port-mode switches, and steers `*1V` to the correct `*V` form.
  • Documentation and the Command Spacing help now state the R2D7's 120-byte input buffer (spec footnote 14), correcting the previous "256 bytes."
  • Tests: added wrong-case-refusal and `*V`/`*1V` administration-frame cases; updated the Query Version case to assert the `*V` frame.
