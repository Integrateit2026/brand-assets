1 Start here

IntegrateIT MantelMount MM815 turns any Control4 surface — phone, iPad, T5, or Halo Touch — into a PTZ-style pad for a motorized MantelMount MM815 TV mount. It drives the mount over the Bond Bridge Local API (v2), relaying the same RF bursts the physical remote sends, so it works alongside any existing Bond fan or shade driver on the same bridge. One driver instance controls one mount. Nine Navigator UI buttons plus a full set of programming commands cover nudging, driving to a limit, true hold-to-move, six memory favorites, and TV-follow.

The Bond Bridge speaks plain HTTP on the LAN. The Bond Local Token travels as an unencrypted BOND-Token header, and /v2/sys/version — what discovery and the health poll read — answers any host on the LAN with no token at all. Keep the bridge on a trusted, segmented network: physical/LAN access is the whole security model of a local-RF bridge.
Ready for controlled commissioning. The package, Lua runtime, Bond Local-API framing, the assumed-position model, hold-repeat cadence, subnet discovery, health polling, the license gate, and this documentation pass automated QA. This build is simulation-verified, not bench-tested: a qualified dealer must still complete a fresh install and an observed movement test against a real MM815 learned by a real Bond Bridge.

What you get

  • Nine Navigator UI buttons — Up, Down, Swivel Left/Right, Stop, Home, Favorite 1, Favorite 2, and a Drive Mode toggle
  • Three motion styles: Nudge (one RF burst for fine trim), Drive to limit (Run + arrow, latched — the mount's own native self-drive), and true hold-to-move that re-fires at Hold Repeat Interval until release
  • The Navigator Drive Mode button arms drive-to-limit for the *next* arrow tap only and then disarms itself; Arrow Tap Behavior sets what a plain tap does the rest of the time
  • Six memory favorites — Go Favorite 1–6 each fire Run + the matching Memory N command
  • TV-follow: Deploy / Stow wired to TV or room power lower the mount to the Viewing Position favorite and raise it back to the wall
  • Bond convenience: Discover Bond Bridges subnet scan, Test Connection, List Bond Commands, and a reachability poll driving a Bond Status property with Online/Offline events
  • POSITION_STATE, IS_MOVING, and BOND_ONLINE variables plus Deployed / Stowed / Bond Online / Bond Offline events for programming
  • Per-controller licensing and in-place Composer self-update that preserves properties, bindings, and programming

2 The assumed-position contract

The MM815 is driven by one-way RF relayed through Bond. The bridge acknowledges the HTTP call; it never reports where the mount actually is. There is no absolute position telemetry, so this driver models position best-effort and labels it honestly — anything reporting an exact angle or height would be faking it.

  • POSITION_STATE is assumed, not measured. At boot it is Unknown: nothing that happened while the driver was down is observable.
  • A move sets IS_MOVING true, then waits Move Settle Time — the mount's real travel time, which you calibrate. When that timer elapses the move is *assumed* complete, POSITION_STATE lands on the target, and any matching event fires. It is a timer, not a sensor.
  • A nudge, a drive-to-limit, or any Stop drops POSITION_STATE to Custom — the mount is somewhere between known points and the driver will not pretend to know where.
  • A fresh gesture supersedes a move still in flight: the pending settle is cancelled so a stale timer can never overwrite Custom with a false Deployed/Stowed.
  • An unmapped command does not stop the settle. If the button behind a go-to is unmapped — the Memory N under a Go Favorite N or Deploy, the Up Command under Go Home or Stow — the Run burst still goes out, Status reads Map '<button>' in driver properties, and the settle still lands the target state and fires its event. The driver reports a position the mount never travelled to. Map every button you wire, and read Status on the first run of each.

3 Wire and commission

  1. Add the driver, then show its buttons in Navigator. Add this driver to the mount's room. The nine controls are Control4 experience buttons (UI Button shortcuts), not a remote keypad: select the mount's room → Navigator properties → for each menu you want them in (e.g. Watch or Comfort) set the TV Mount … buttons to Visible, then Refresh Navigators. They will not appear until you do — do this before you configure anything else so you can test as you go.
  2. In the Bond app, confirm the mount's directional, Run, and Memory buttons are learned cleanly on the bridge. Note the Bond's IP and Local Token.
  3. Enter Bond IP Address and Bond Local Token. No IP to hand? Run Discover Bond Bridges from the Actions tab — it sweeps the controller's /24 and prints every bridge it finds; paste one in.
  4. Run Test Connection with Bond Device ID blank — it lists the Bond device ids. Paste the mount's id into Bond Device ID, then run Test Connection again to confirm it names the device.
  5. Run List Bond Commands — it prints each learned command as cmd:<id>. Paste them into the matching Up/Down/Left/Right/Run Command properties. Map a Memory N Command for every favorite you use — Memory 1–6 back the Favorite go-to buttons (Home and Stow are Run + Up and need no Memory) and, critically, the favorite named in Viewing Position, because Deploy sends that favorite's Memory command. Leave it unmapped and Deploy still sends Run and still claims Deployed — see the assumed-position contract. Optionally map Stop Button Command if the mount has a dedicated Stop RF button — otherwise Stop falls back to Run.
  6. Set Arrow Tap Behavior (Nudge or Drive to limit), calibrate Run Prefix Delay (ms) and Move Settle Time (ms) against the real mount, and set Bond Health Check (min) (0 disables the poll). Optionally enter a License Key — the driver runs in Lenient mode without one.
  7. Prove it. Tap a Navigator arrow and watch the mount move, then run Check Bond Health Now and confirm Bond Status reads Online (Online - fw <version> when the bridge reports its firmware).
Bond stores each learned button as a fixed RF burst. Tune the Bond signal's reps so one nudge is a comfortable half-second of travel.

4 Protocol on the wire

Every call the driver makes carries the BOND-Token header, and the token is never placed in a URL or body. The one exception is the discovery sweep, which probes the unauthenticated /v2/sys/version with no header at all. On the transmit paths the device and command ids are percent-encoded so a stray space can't malform the path. The calls:

CallPurpose
PUT /v2/devices/<id>/commands/<cmd>/txFire a learned RF burst — a cmd:<id> mapping
PUT /v2/devices/<id>/actions/<name>Fire a Bond action — an action:<name> (optional :<int> argument)
GET /v2/devicesList device ids (Test Connection with a blank id)
GET /v2/devices/<id> and .../commandsRead the device name and enumerate learned commands
GET /v2/sys/versionReachability + firmware (health poll and discovery; the endpoint needs no token)
PUT /v2/devices/<id>/actions/StopGeneric abort backstop, sent on every Stop

A mapping value is cmd:<id>, action:<name>, or bare text — bare text that begins with a known Bond action name is treated as an action, otherwise as a command id. fail_on_error is off, so the real HTTP code comes back to the driver instead of a generic transport failure and surfaces in the driver Status as Bond error (HTTP <code>) on <button> — e.g. Bond error (HTTP 401) on Up. 401 = wrong Local Token; 404 = wrong Device ID or command id. (The readonly Bond Status property is separate — it carries the health poll's reachability, not per-command errors.)

A mount learned purely as fixed RF may not expose actions/Stop; that abort call then 404s harmlessly. The mapped Stop/Run button is what actually halts the mount — always map one — the generic abort is only a backstop.

5 Program the project

For keypads, remotes, and macros the driver exposes device commands:

Nudge Up/Down/Left/Right · Drive Up/Down/Left/Right · Start Hold Up/Down/Left/Right · Stop Hold · Stop · Go Home · Go Favorite 1–6 · Deploy · Stow · Send Run

Each Go Favorite N fires Run + Memory N, so map the matching Memory N Command for every favorite you wire. For true hold-to-move on a hard button, wire PRESS → Start Hold <dir> and RELEASE → Stop Hold.

EventFires when
DeployedA Deploy completed its settle (TV lowered to the Viewing Position)
StowedA Stow completed its settle (TV raised to the wall)
Bond OnlineThe health poll found the bridge reachable after it was not
Bond OfflineThe bridge stopped responding

Deployed and Stowed fire only from Deploy / Stow (TV-follow), not from Go Home or Go Favorite — those move the mount but announce no completion event.

VariableTypeMeaning
POSITION_STATESTRINGThe assumed position — see the assumed-position contract
IS_MOVINGBOOLA move is in flight (1) or the mount is at rest (0)
BOND_ONLINEBOOLThe last health poll reached the bridge

Three ways these wire into Composer programming:

  • When the TV or room turns ON → Deploy; when it turns OFF → Stow. One event lowers the mount to the Viewing Position favorite and another raises it home; Deployed / Stowed fire once the mount has had time to travel.
  • PRESS → Start Hold Up, RELEASE → Stop Hold on a hard keypad button gives press-and-hold travel; the release also aborts any go-to still counting down.
  • When Bond Offline fires → announce it, and gate motion programming on BOND_ONLINE so macros don't fire RF at an unreachable bridge.

Control commands are license-gated: under Strict enforcement an unlicensed controller sends no mapped button at all — no arrow, no Run, no Memory — and Start Hold won't even arm its repeat timer. The generic actions/Stop abort behind Stop and Stop Hold is deliberately never gated, so a halt always reaches the bridge. Health polling, discovery, and the setup actions keep working regardless. The default Lenient mode allows commissioning while License Status carries the nag.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation of Bond's documented Local HTTP API. It does not bundle another vendor's runtime, source code, brand assets, trial system, or license. MantelMount, MM815, and Bond are trademarks of their respective owners; IntegrateIT is not affiliated with either, and this driver is not a MantelMount or Bond product. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

The driver sends RF commands to your Bond Bridge on the LAN and nothing anywhere else — no cloud, no device-vendor telemetry, no customer or project identity leaves the controller. The Bond Local Token lives in a password-masked property, travels only as an HTTP header, and is never written to the log or to Print Configuration. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks all mount control until the Ops Portal has minted and validated a key for that controller; health polling and discovery continue either way. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.
