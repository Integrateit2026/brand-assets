1 Overview

IntegrateIT Lutron HomeWorks QS puts a classic HomeWorks QS system on Control4 through Lutron's own published Integration Protocol (LIP) — the telnet server every HQP6 / HQP7 processor exposes on port 23. The driver performs the prompt-based login with credentials the installer creates in Lutron Designer, asserts zone monitoring, and then controls and monitors up to eight mapped integration IDs: set a dimmer to a level (with fade), or raise / lower / stop a Sivoia QS shade. Every level report from the Lutron system — whether caused by this driver, a keypad, or the Lutron app — lands in a per-zone Control4 variable and fires a *Zone Level Changed* event your programming can react to.

The session is self-healing: an unexpected drop reconnects with exponential backoff (base delay doubling up to 5 minutes), while a rejected login latches — the driver will not hammer a processor with bad credentials; fix the username/password and it reconnects on its own.

This driver is for classic HomeWorks QS (LIP) only. HomeWorks QSX, Athena, and RadioRA 3 speak the newer LEAP API and are not supported here.

2 Install & setup

  1. Give the HomeWorks QS processor a static IP (disable DHCP on the processor, per Lutron's own integration guidance).
  2. In Lutron Designer: *Tools > Configure Integration > Telnet Logins* — create a login for this driver. Then open the Integration Report and note the numeric Integration ID of each output (dimmer zone or shade) you want on Control4.
  3. Add this driver to the project. Set Processor IP Address, Telnet Username, and Telnet Password (Telnet Port stays 23).
  4. Map up to eight outputs: Zone N Integration ID (from the Integration Report) and an optional Zone N Label.
  5. Watch Connection Status reach Online (logged in) — the driver queries every mapped zone at login, so Zone Levels and the ZONE_N_LEVEL variables go live immediately.
  6. In Programming, drive zones with Set Zone Level (params ZONE 1-8, LEVEL 0-100), Raise Zone, Lower Zone, Stop Zone (param ZONE), and react to *Zone Level Changed* using LAST_ZONE / LAST_ZONE_LEVEL.
  7. Optionally enter a License Key (see Licensing) — the driver runs in Lenient mode without one.

4 Safety & limits

  • Telnet is plaintext. LIP has no TLS — credentials and commands cross the wire in the clear. Keep the processor on a trusted LAN segment; the driver refuses URLs and IPv6 literals as targets.
  • Credentials stay out of the log. The password is never printed, never stored in a variable, and never appears in debug output — even with Debug Mode = Print.
  • A failed login latches. After a re-prompt or an explicit rejection the driver stops trying, fires *Login Failed*, and waits for you to change the credentials (or press Connect). No lockout-inducing retry storms.
  • System-level LIP verbs are blocked on the raw escape hatch: #ETHERNET, #RESET, #PASSWD, #INTEGRATIONID, #MONITORING cannot be sent from programming.
  • Shades run at fixed speeds. Lutron documents fade/delay as having no effect on shades — Dimmer Fade (s) only shapes dimmers.
  • Level reports are rounded to whole percent (LIP reports like 75.00).

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means

Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.

Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

V Version history

v0.1.0 current2026-07-21
  • Initial release: Lutron Integration Protocol (LIP) telnet client for classic HomeWorks QS processors (HQP6-x / HQP7), built against Lutron's published protocol reference (P/N 040249).
  • Prompt-based telnet login (login: / password: / session prompt) with installer-provisioned credentials from Lutron Designer; a rejected login latches instead of retrying.
  • Control of up to 8 mapped OUTPUT integration IDs: Set Zone Level (action 1, with fade), Raise / Lower / Stop (actions 2 / 3 / 4).
  • Zone monitoring asserted at login (#MONITORING,5,1) plus a per-zone prime query; live per-zone level variables, LAST_ZONE / LAST_ZONE_LEVEL, and a Zone Level Changed event.
  • Reconnect with exponential backoff (base delay doubling to 5 min, reset on login); connect and login watchdogs; bounded pre-login command queue.
  • Guarded raw LIP escape hatch (system-level verbs refused); credentials never written to the Control4 log; ~ERROR replies decoded into a Protocol Error event.
  • Login hardening (pre-ship review): a password prompt that arrives AFTER the password was already answered is now treated as a rejection and latches — the same guarantee the "login:" re-prompt already gave — so a wrong password can never be resent in a loop that risks locking the Lutron telnet account.
  • Login hardening (pre-ship review): the unterminated-tail prompt detector now requires that authentication has begun before it accepts a "…>" prompt as logged-in, matching the glued-prompt line path; a stray ">"-terminated banner arriving before "login:" can no longer spoof a Connected session and then latch a false Login Failed when the genuine prompt arrives.
