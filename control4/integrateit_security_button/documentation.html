1 Start here

IntegrateIT Security Button is one branded Control4 Navigator experience button that shows — and toggles — whether the security system is armed. Blue shield = Disarmed (off). Red shield = Armed (on). It is a native UI button proxy (proxy type uibutton, primary binding 5001); there is no device, wire, or vendor protocol behind it. It lives inside Director, takes the SELECT/DO_CLICK a homeowner's tap produces, and publishes the resulting state back to Composer as events and variables. The shield flips the instant the state changes — from a press, or from your programming.

CONVENIENCE INTEGRATION ONLY — NOT AN ALARM PATH. This is a Navigator indicator and a programming surface, not listed alarm-signaling, monitoring, or life-safety equipment, and it must never be presented to a homeowner as one. Read Safety boundary before you commission it on a site with a real panel.
Ready for controlled commissioning. The package, Lua 5.1 runtime, state engine, press debounce, the three loop-guard layers, persistence, licensing, and documentation pass automated simulation QA. This is a release candidate: nothing here is bench-tested, so a qualified dealer must still add it to a real project and confirm the shield art, the press behavior, and the accessible description on the actual Navigator touch screens and app before handoff.

What you get

  • Two states, one tile: a glossy platinum-bordered IntegrateIT shield, blue with an open padlock when Disarmed, red with a closed padlock when Armed
  • Three press behaviors set by Press Action: Toggle Armed / Disarmed, Request Only (Programming Confirms), and Disabled
  • Set Armed / Set Disarmed / Toggle Armed / Disarmed / Refresh Navigator State as programming commands and as Actions-tab buttons
  • Pressed, Arm Requested, Disarm Requested, Armed, Disarmed, and Loop Guard Tripped events
  • SECURITY_STATE, IS_ARMED, and LAST_CHANGE_SOURCE variables for one-line programming conditions
  • Silent reboot restore — a Director restart can never arm or disarm anything
  • Press debounce that collapses the duplicate SELECT/DO_CLICK one tap produces, plus a three-layer loop guard
  • MAC-locked IntegrateIT licensing, Lenient or Strict

Three press behaviors, chosen by Press Action:

  • Toggle Armed / Disarmed (default) — a press flips the state immediately and fires the events. The fastest way to a working demo: drop the driver in a room and the shield toggles blue ↔ red out of the box. It shows what was toggled, not what a panel did.
  • Request Only (Programming Confirms) — a press fires Arm Requested / Disarm Requested and the shield does not move. Your programming arms or disarms the real panel, then confirms with the Set Armed / Set Disarmed commands driven from the panel's own arm-state feedback. In this mode the shield follows the panel's confirmation rather than the press that asked for it, and that is what keeps it honest — within the three refusal conditions named in Safety boundary, any of which can leave it STALE. This is the mode for production installs with a real panel.
  • Disabled — presses are ignored and the button is a status-only mirror your programming drives.

2 Safety boundary

Do not build life-safety or security-critical behavior on this driver. It is a Navigator convenience layer, not a listed alarm-signaling, monitoring, or life-safety path, and it must never be sold, labelled, or explained to a homeowner as one. The panel, its keypads, and its listed communicators remain the system of record.
  • It drives no panel. Publishing state is the whole job. Every arm, disarm, scene, lock, or announcement that happens because of this button is Composer programming a dealer wrote. A malformed input here can at worst show the wrong color; it can never arm or disarm anything by itself.
  • A reboot is not a press. The shown state is restored at boot silently — no event fires — so restarting Director can never run arming programming.
  • The shield can be STALE. Request Only mode is honest because the shield waits for the panel's confirmation, but a confirmation can be refused, and a refused confirmation leaves the old color on screen. There is no later re-sync: nothing re-asks the panel, and Refresh Navigator State only re-broadcasts whatever value is already held. Three conditions refuse a confirmation, and each one names itself in the read-only Status property:

3 Wire and commission

  1. Add IntegrateIT Security Button to the room that should show the shield. It is a primary UI button, so Navigator renders it as a tile named Security. There is nothing to bind in Connections — the button drives nothing.
  2. If the room menu does not show it, check the room's Navigator menu visibility (Room → Navigator → reorder / hide experience menu items), then refresh Navigators.
  3. Set Default State (the state a fresh install starts in, and the state every boot uses when Restore On Reboot is No) and leave Restore On Reboot at Yes unless the site wants a fixed boot state.
  4. Choose Press Action. Use Toggle Armed / Disarmed for a bench demo. Use Request Only (Programming Confirms) for any install with a real panel — see the confirmation recipe below.
  5. Leave Press Debounce (ms) at 400. The minimum is 250 ms: a shorter window let one physical press arm and immediately disarm again, because Navigator can deliver one tap as both SELECT and DO_CLICK.
  6. If programming will react to this button's own events, tune Loop Guard Changes and Loop Guard Window (s) (defaults 12 changes / 10 s). Setting Loop Guard Changes to 0 disables the guard.
  7. Optionally enter a License Key (see Licensing) — the driver runs in Lenient mode without one.
  8. Prove it: open the room on a Navigator and tap the shield. In Toggle mode the icon flips blue ↔ red on each tap and Armed / Disarmed fire. In Request Only mode the icon holds still, Arm Requested / Disarm Requested fire, and Status reads Arm requested - waiting for programming to confirm. Watch SECURITY_STATE and IS_ARMED follow in Programming — that is the proof the whole path works.

Updates come from the IntegrateIT relay's read-through mirror at https://relay.integrateit.dev/channel/control4/integrateit_security_button/version.json; automatic checking is a property you control, and self-update staging needs Control4 OS 3.3.1 or newer.

4 Presses, restore, and the loop guard

  • Reboot persistence — the shown state is written on every accepted change and restored silently at OnDeviceInit. No event fires, so a reboot can never arm or disarm anything. A corrupted persisted value falls back to Default State rather than letting a coercion pick a direction. Set Restore On Reboot to No to always boot into Default State. A driver removed and re-added starts at Default State.
  • Press debounce — one physical press can arrive twice, once as SELECT and once as DO_CLICK. The pair is collapsed by identity first: taking one delivery arms a one-shot token for its complement, which is swallowed whenever it turns up (up to 3 s later). Press Debounce (ms) is the second line of defence and catches two identical deliveries in a row.
  • Loop guard, layer 1 — silent re-selection. Setting the state already shown refreshes the surfaces and fires nothing. This is what makes panel-feedback wiring idempotent, and what stops "on Armed → Set Armed" from cycling forever.
  • Loop guard, layer 2 — re-entrancy. A change requested from inside this driver's own event dispatch is refused outright. See Safety boundary.
  • Loop guard, layer 3 — rate ceiling. More than Loop Guard Changes accepted changes inside Loop Guard Window (s) trips the guard, fires Loop Guard Tripped, and refuses further changes for a full window measured from the trip. Set Armed / Set Disarmed are forced ground truth and skip this ceiling. If Loop Guard Tripped fires in the field, treat it as a bug report about your programming, not a setting to raise.
  • Accessibility — Navigator receives the state and what a press will do as the icon description (what a screen reader announces), mirrored in the read-only Accessible Description property.

5 The shield art

Two icons ship inside the package: a platinum-bordered shield with a glossy IntegrateIT-blue face and an open padlock for Disarmed, and the same shield in alarm red with a closed padlock for Armed. Navigator picks the size it needs from a 70-1024 px ladder, so the tile stays sharp on a T4 touch screen, a phone, and a tablet alike.

The padlock is deliberate: arm state is carried by the glyph as well as the colour, so the tile still reads for anyone who cannot rely on red-vs-blue.

If the tile ever looks wrong on a screen — stretched, blank, or the wrong state — run Refresh Navigator State first; that re-sends the icon without changing anything. Nothing here is dealer-configurable: the art is fixed in the package and updates with the driver.

6 Program the project

Command / ActionWhat it does

Toggle Armed / DisarmedFlip the state from programming, exactly as a Navigator press would in Toggle mode. Originates a change, so it keeps the licence gate and the full loop guard.

All four control verbs exist in both key spaces: as Composer programming commands and as Actions-tab buttons. Last Change records which surface acted — Programming for a programming command, Composer action for an Actions-tab press.

Events: Pressed (every mode except Disabled, before any state change), Arm Requested (pressed while Disarmed), Disarm Requested (pressed while Armed), Armed, Disarmed (the state actually moved, from any source), Loop Guard Tripped.

Three recipes, wired with this driver's own names:

  • Mirror a real panel (the important one). Set Press Action to Request Only (Programming Confirms). Then wire four lines: When Arm Requested fires → send the arm command to the panel. When Disarm Requested fires → send the disarm command. When the panel reports ARMED → call this driver's Set Armed. When the panel reports DISARMED → call Set Disarmed. The shield now moves only when the panel says so. Confirming a state the shield already shows is silent — it fires no event — so the two feedback lines are safe to fire as often as the panel repeats itself, including on every status poll. Confirm from the panel's feedback, never from this driver's own Armed / Disarmed event: that is the re-entrant case, and it is refused.
  • Run the house off the state. When Armed fires → lock the doors, close the shades, run Goodnight. When Disarmed fires → run the welcome-home scene. These fire on a real move from any source, so one program covers a Navigator press, a programming toggle, and a panel confirmation alike.
  • Gate other automation on the state. When the front door contact opens, if IS_ARMED is true → announce on the kitchen touch screen and turn on the driveway lights. IS_ARMED is a boolean written in the same block as the icon, so a condition read never catches the surfaces mid-update.

Control is gated by the licence: under Strict enforcement an unlicensed controller moves nothing — presses, programming toggles, and panel confirmations alike are refused — while Lenient mode allows commissioning with the License Status nag.

9 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation built on the documented Control4 UI-button proxy and variable/event contracts. It does not bundle another vendor's runtime, source code, brand assets, trial system, or licence. Driver engineering, Control4 integration, documentation, visual design, QA, licensing, updates, and support are provided by IntegrateIT.

Nothing about the button leaves the controller. The state, the change history, and the accessible text live only in Director and the driver's own PersistData — the button's runtime has no network path of its own, so no state or press ever leaves the LAN. The shared IntegrateIT licence and update services are the only outbound path; they use the controller identity, driver slug, version, configured licence key, and update channel as documented in the reference below, and check https://relay.integrateit.dev/channel/control4/integrateit_security_button/version.json for new versions. The licence key is never printed by Print Configuration and never written to the log.

Lenient mode is the default: it allows commissioning without an activated key and keeps License Status visible. Strict mode blocks all state control — presses, programming toggles, and panel confirmations alike — until the Ops Portal has minted and validated a key for that controller; that refusal is one of the three conditions under which the shield can go STALE, which is why Strict belongs only on a site whose licence is known good. Installing this package does not itself mint or activate a controller licence.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means

Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.

Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

D Diagnostics and self-test

Every IntegrateIT driver carries two read-only Actions for the field. Run Diagnostics prints a report of what the driver has already observed — version and Lua runtime, license mode and cached activation, update channel and any staged build, every armed timer with its interval, which dealer-supplied properties are still empty, and the last few Status messages. It probes nothing, sends nothing, and changes nothing, so it is safe on a live job. Run Self-Test checks the shared layer itself — string and URL encoding, version comparison, the non-finite number guard, the timer registry, and the persistence store — and ends with SELF-TEST PASS or a per-check failure. It stays local: no network, no device commands.

Neither Action is license gated, on purpose: you reach for them when a site is broken, and the license may be the broken thing. Values are never printed — a key or secret is reported only as set or NOT SET, so the output is safe to paste into a support ticket. Both print to the Lua output window (Composer → the driver's Lua tab).
