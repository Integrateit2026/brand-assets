1 Start here

IntegrateIT Somfy URTSI II turns one Control4 serial port into full command of a Somfy Universal RTS Interface II — up, down, and stop on any of its 16 motor channels, 10-step tilt in both directions for RTS tilt blinds, and an advanced raw-line sender for choreographed multi-command sequences. Frames follow Somfy's own published URTSI II protocol; a paced transmit queue keeps consecutive RTS radio transmissions from piling into each other.

The URTSI II link is strictly ONE-WAY. The unit returns nothing over serial — no acknowledgement, no status, no shade position. Every state this driver shows is assumed from the last command it sent. A handheld Telis remote or wall switch moving a shade is invisible to the driver. No software update can add position feedback to this hardware; anything claiming otherwise would be faking it.
Ready for controlled commissioning. The package, Lua 5.1 runtime, serial framing, tilt character tables, raw-line validation, command pacing, license gate, persistence, and documentation pass automated QA. A qualified dealer must still complete a fresh install and an observed shade-control test against a real URTSI II on the target controller.

What you get

  • Up / Down / Stop for the selected URTSI II channel (1-16)
  • Tilt Up / Tilt Down in 1-10 increments, using Somfy's documented tilt characters
  • A configurable inter-command spacing queue so back-to-back commands never collide on air
  • RS-232 and RS-485 framing: unit address 01-16 and optional CR termination
  • A validated raw-line sender for multi-command lines with waits (0103U;W1;0205D)
  • Honest assumed-state tracking: Command Sent plus Shade Assumed Up / Down / Stopped events, per-channel labels, and programming variables

2 The one-way contract

The URTSI II is a serial-to-RTS-radio bridge: your controller talks to it, it transmits to the motors, and nothing ever comes back. This driver is deliberately honest about that:

  • The Assumed State property and ASSUMED_STATE variable are dead-reckoned from the commands this driver sent — nothing more.
  • After a controller reboot every channel restarts at Unknown. No travel is observable across a reboot on a one-way link, so nothing else would be truthful.
  • Tilt commands nudge the slats without running the shade to an endpoint, so they leave the assumed Up/Down/Stopped state untouched.
  • There is no Navigator shade proxy promising position on purpose. Programming reacts to the events and variables below; position sliders would be fiction.

3 Wire and commission

  1. Pair each motor to a URTSI II channel on the unit itself, per Somfy's instructions. The driver cannot discover or pair channels.
  2. Wire a controller or IO-extender RS-232 port to the URTSI II: 9600 baud, 8 data bits, no parity, 1 stop bit, no flow control.
  3. Add IntegrateIT Somfy URTSI II to the project and bind URTSI II Serial Port (binding 1) to that port in Connections.
  4. RS-232 (typical): leave Unit Address at 1 and Line Termination at None (RS-232). RS-485 multi-drop: set Unit Address to the unit's rotary switch position and Line Termination to CR (RS-485).
  5. Set Active Channel to a paired channel and run Shade Up / Shade Down / Shade Stop from the Actions tab. Watch the shade — the driver cannot.
  6. Optionally name each channel with the Channel 1 Label … Channel 16 Label properties and confirm the setup with Print Configuration.
Somfy ships the URTSI II specifically so third-party control systems can drive RTS motors; this driver implements that published serial contract with original IntegrateIT engineering.

4 Frames on the wire

Each command is fixed-width printable ASCII with no checksum: two-digit unit address, two-digit channel, one command character. Examples with unit address 01:

Wire frameMeaning
0101UChannel 1 up
0107DChannel 7 down
0112SChannel 12 stop
01043Channel 4 tilt UP 4 increments
0104#Channel 4 tilt DOWN 4 increments

Tilt characters, exactly per Somfy: digits 0-9 tilt UP 1-10 increments; the shifted digits ) ! @ # $ % ^ & * ( tilt DOWN 1-10 increments. Each increment runs the motor roughly 1/10 second. With CR (RS-485) termination every line gains a trailing carriage return; RS-232 frames are sent bare.

Command Spacing (ms) paces the queue: the driver never writes two lines closer together than the configured gap (default 250 ms, range 100-2000), because each line triggers an RTS radio transmission that needs time on air. Commands issued faster are queued in order and transmitted in order — the driver drops the queue in exactly one case, described under license enforcement below.

5 Raw lines (advanced)

Put a full URTSI II line in the Raw Line property and run Send Raw Line. The driver validates before anything touches the wire, enforcing Somfy's documented limits:

  • Maximum 5 commands per line, semicolon-separated
  • Of those, maximum 3 movement/tilt frames and 2 waits
  • Frames must be exactly AACCX — two-digit address 01-16, two-digit channel 01-16, one legal command character
  • Frames are contiguous ASCII — a space or tab anywhere in the line is refused, because the line is sent verbatim and interior whitespace would corrupt the fixed-width frames on the wire
  • Waits must be exactly W1-W9 — the digit is the number of 0.5 s steps the URTSI II pauses (W1 = half a second, W9 = 4.5 s)

A refused line never transmits; Last Error and Status name the reason. An accepted line is sent verbatim as one write, fires one Command Sent, and updates the assumed state for every U/D/S frame addressed to this unit.

Example — open channel 3, wait half a second, close channel 5 on unit 2: 0103U;W1;0205D.

To drive several shades from programming, set Active Channel first, then invoke Shade Up / Shade Down / Shade Stop — Composer can write the property and call the command back-to-back; the pacing queue keeps the radio happy. For fixed scenes, a validated Raw Line moves up to three channels in one line.

Three recipes using this driver's real surfaces:

  • Goodnight → set Active Channel to the bedroom channel and run Shade Down; hang the rest of the scene off the Shade Assumed Down event, which fires on the transition and not on a repeat of the same command.
  • Afternoon glare → set Tilt Steps to 5 and run Tilt Down. The slats close five increments and the channel's assumed Up/Down/Stopped state stays exactly where it was — a tilt is a slat nudge, not travel, so nothing pretends the shade moved.
  • Two shades, one write → put 0102U;W1;0103U in Raw Line and run Send Raw Line: channels 2 and 3 open a half-second apart from a single serial write, one Command Sent fires, and both channels update their assumed state because both frames carry this unit's address.

Control commands are gated by the license: under Strict enforcement an unlicensed controller writes nothing to the serial port; the default Lenient mode allows commissioning while License Status carries the nag. The gate is re-checked at wire-write time, not only when a command is enqueued: if enforcement flips to Strict while frames are still sitting in the pacing queue, the pending queue is dropped rather than held — stale shade commands firing minutes later on a re-license would be a surprise, not a convenience.

9 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation of Somfy's published URTSI II serial protocol (the unit exists precisely so third-party systems can drive RTS motors). It does not bundle another vendor's runtime, source code, brand assets, trial system, or license. Somfy, URTSI, and RTS are trademarks of Somfy Systems, Inc.; IntegrateIT is not affiliated with Somfy, and this driver is not a Somfy product. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

The driver sends shade commands to your URTSI II and nothing anywhere else. The URTSI II protocol has no login, password, or encryption — physical access to the serial port is the entire security model, one more reason the port belongs inside your rack. There are no device credentials to store, and the configured license key is never written to the log or the Print Configuration output. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks all serial control until the Ops Portal has minted and validated a key for that controller. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.
