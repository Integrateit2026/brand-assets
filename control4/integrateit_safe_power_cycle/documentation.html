1 Start here

IntegrateIT Safe Power Cycle turns one to four Control4 relay outputs into a single guarded power group, so an AV rack, a network switch, a media server, or any headless appliance can be rebooted from Control4 without wiring the reboot logic by hand. A power cycle is a deliberate three-step operation: the driver powers the load off, waits a configurable Off Duration (s), then powers it back on. Two guards stand in front of that — a two-step Arm Cycle → Power Cycle confirmation and a rolling hourly rate limit — and every action fires an audit event so programming and logs show exactly what happened. The driver is headless: there is no Navigator tile. It is driven entirely from Composer programming and the Actions tab.

This driver switches relays; it does not measure the load. It cannot confirm the downstream device actually lost and regained power. Power cycling live equipment can interrupt in-progress work and can damage gear that dislikes abrupt power loss. Wiring, relay/contactor ratings, and any inrush protection are the installer's responsibility.
Ready for controlled commissioning. The package, Lua 5.1 runtime, relay drive, the confirmation and rate-limit guards, cancel, reboot recovery, the license gate, persistence, and documentation pass automated QA in simulation. A qualified dealer must still complete a fresh install and an observed power-cycle test against real relay hardware and the actual load on the target controller. Nothing here is bench-tested yet.

What you get

  • One to four bound relay outputs power-cycled together as one group: off, wait the configured duration, back on
  • A two-step Arm Cycle → Power Cycle confirmation with a 30-second window that blocks a single stray press from rebooting the rack
  • A rolling one-hour rate limit (Max Cycles Per Hour) that caps how often the same group can be cycled
  • Latching or Momentary relay drive for loads that hold power directly or latch it from a front-panel button press
  • Cancel Pending that aborts a cycle mid-off and restores power, plus automatic reboot recovery of a cycle interrupted by a controller restart
  • Five audit events — Cycle Started / Completed / Blocked, Powered Off / On — and the IS_CYCLING, LAST_CYCLE, CYCLES_THIS_HOUR, POWER_STATE variables for programming

2 Safety boundary

What this driver can and cannot know, and exactly what each guard buys you:

  • This driver switches relays; it does not measure the load. A relay CLOSE or OPEN is only a dry-contact command. The driver never observes the load's real power, current, or boot state — anything claiming it did would be faking it. Power State is the last commanded state, not a measurement.
  • Two-step confirmation is the primary guard. With Require Confirmation = Yes, a Power Cycle that was not preceded by an Arm Cycle within the last 30 seconds fires Cycle Blocked and touches no relay. Re-enabling the guard immediately drops any stale arm, so the next cycle must re-confirm.
  • The rate limit is a hard ceiling. Once Max Cycles Per Hour cycles have run in the trailing hour, further cycles are blocked until a slot frees. Each cycle frees its own slot exactly one hour after it ran — a rolling window, not a clock-hour reset. The count is held in memory only and resets to zero whenever the driver restarts (a controller reboot or a driver reload). That reset is deliberate: a restored count could never decrement and would wedge the limit permanently, so a reboot is the immediate recovery if you hit the ceiling and cannot wait for the window to clear.
  • Power restore is never blocked. Aborting a cycle mid-off never leaves equipment dark — Cancel Pending powers the load back on, and a controller that restarts mid-off restores power on the next boot and clears the interrupted cycle rather than resuming it. Neither path consults the license gate, so a revoked key cannot strand a rack dark; both fire Powered On. Because Cancel always powers on, Power Cycle then Cancel Pending on a load that was already off will turn it on; with no cycle in flight, Cancel Pending is a no-op that touches no relay.
  • Strict licensing blocks every command path. Under Strict enforcement an unlicensed controller refuses Arm Cycle, Power Cycle, Power Off, and Power On: no relay is driven and no device event fires — not even Cycle Blocked, which is reserved for the confirmation guard, a double-start, and the rate limit and never leaks under Strict. Default Lenient mode runs control and lets License Status carry the reminder.

3 Wire and commission

  1. Add IntegrateIT Safe Power Cycle to the project and to the room that owns the equipment.
  2. Set Number of Relays to how many outputs feed the load, then bind Relay 1 Output … Relay N Output in Connections to your relay channels. All relays switch together.
  3. Choose Relay Mode. Latching holds the relay energized (CLOSE) for On and releases it (OPEN) for Off — use it when the relay directly makes and breaks the load's power. Momentary pulses the relay like a front-panel button — use it when the load latches its own power state.
  4. Set Off Duration (s) — how long the load stays dark during a cycle (1–300 s; 10 s is a safe default for most gear).
  5. Leave Require Confirmation on Yes for the destructive-action guard, and set Max Cycles Per Hour (default 6) to a sane ceiling for the equipment.
  6. Optionally give each output a Relay N Label (shown in status and logs), and enter a License Key if you have one — the driver runs in Lenient mode without one.
  7. Prove it: from the Actions tab run Power Off and watch the relay act — in Latching it opens and holds, in Momentary it pulses for Momentary Pulse (ms) — with Power State reading Off. Run Power On, then, with confirmation on, Arm Cycle followed by Power Cycle, and watch Cycle Status move through armed, off, and completed.
Turn on Debug Mode → Print to watch every arm, block, power change, and cycle step in the Lua output window during commissioning.

4 Relay behavior

What a dealer sees on the wire, and why the two modes differ:

ModeOnOffUse when
Latchingrelay CLOSE, heldrelay OPEN, heldthe relay directly switches the load's power
MomentaryCLOSE then OPEN after Momentary Pulse (ms)same single pulsethe load toggles its own power from a button press

In Momentary mode a Power Cycle presses each relay twice — off phase, then on phase — and each pulse releases independently, so two presses never merge into one long relay hold. A cycle captures its relay set and mode at the moment it starts, so editing Number of Relays or Relay Mode mid-cycle can never strand the relays the off phase opened; the re-energize restores every one of them.

Three ways these wire into Composer programming:

  • Guarded reboot button. Program a keypad button to fire Arm Cycle, then a second press to fire Power Cycle. The 30-second window means one stray press can never reboot the rack.
  • Unattended watchdog recovery. Set Require Confirmation to No and let a network-monitor macro fire Power Cycle when the switch stops answering. The hourly rate limit still protects the equipment from a flapping trigger.
  • Audit and notify. When Cycle Blocked fires, compare CYCLES_THIS_HOUR to Max Cycles Per Hour and announce why the reboot was refused; when Cycle Completed fires, log it with LAST_CYCLE.

Control is gated by the license: under Strict enforcement an unlicensed controller refuses every command path — no relay, no event. The default Lenient mode allows commissioning while License Status nags.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation built on documented Control4 relay contracts. It does not bundle another vendor's runtime, source code, brand assets, trial system, or license. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

The driver drives only the local Control4 relay bindings it is wired to. It sends no load state, project identity, or Control4 credentials to any device vendor — nothing about the switched equipment leaves the controller. The shared IntegrateIT license and update services use the controller identity, driver slug, version, license key, and update channel as documented in the reference below; the license key is never written to the log. A transient license-server error will not de-license a controller that has already validated.

Lenient mode (the default) allows commissioning without an activated key and keeps License Status visible. Strict mode blocks every command path until the Ops Portal has minted and validated a key for that controller; only the two power-restore paths above still run, so licensing can never leave a rack dark. Installing this package does not itself mint or activate a license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

D Diagnostics and self-test

Every IntegrateIT driver carries two read-only Actions for the field. Run Diagnostics prints a report of what the driver has already observed — version and Lua runtime, license mode and cached activation, update channel and any staged build, every armed timer with its interval, which dealer-supplied properties are still empty, and the last few Status messages. It probes nothing, sends nothing, and changes nothing, so it is safe on a live job. Run Self-Test checks the shared layer itself — string and URL encoding, version comparison, the non-finite number guard, the timer registry, and the persistence store — and ends with SELF-TEST PASS or a per-check failure. It stays local: no network, no device commands.

Neither Action is license gated, on purpose: you reach for them when a site is broken, and the license may be the broken thing. Values are never printed — a key or secret is reported only as set or NOT SET, so the output is safe to paste into a support ticket. Both print to the Lua output window (Composer → the driver's Lua tab).
