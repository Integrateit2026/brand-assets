1 Start here

IntegrateIT JVC D-ILA Projector turns one Control4 serial port, or the projector's network port, into two-way control of a JVC D-ILA projector over RS-232 or LAN, speaking JVC's own published external-control protocol (the binary 21 89 01 … 0A command family in JVC's External Control Command specification and D-ILA remote control guide on support.jvc.com). It was built for the DLA-RS49U and its siblings, the DLA-RS4910 and DLA-X500R, which report model code XHK1 / XHK2.

Control Method picks how the driver reaches the projector:

Control MethodWhat it does
RS-232 (default)Two-way control over the serial port. Installed sites keep this.
RS-232 + IR Power OnThe same, and every Power On also sends JVC's discrete IR Power On code through an emitter, so a projector whose port sleeps in standby (ECO Mode On) still turns on.
LANThe same two-way control over TCP port 20554 to Projector IP Address, behind JVC's PJ_OK / PJREQ / PJACK handshake. No serial cable, baud rate or port gender to get wrong.
LAN + IR Power OnLAN, with the IR Power On assist.
IROne-way fallback: the same commands go out as JVC remote codes through an IR emitter, with power modeled instead of read.

The projector joins the room as a real Control4 video endpoint. Watch powers it up and lands on the right HDMI input once the lamp is warm, Room Off puts it in standby, the room remote's menu and cursor keys reach the JVC menu, and an input change made with the JVC remote shows up in the room.

For RS-232 or LAN, set the projector's Function > ECO Mode to Off. JVC's RS49 / X500R user guide (https://manual3.jvckenwood.com/projector/mobile/dla/lch60830-001en/QUDFSYuraxfcif.php) says to set ECO Mode to Off if RS-232C or LAN communication is performed in Standby mode, and a controller that has to turn the projector on from standby is exactly that. If the site must keep ECO Mode On, use an IR Power On Control Method (see IR Power On assist). If the menu also has Communication Terminal, it must read RS-232C for RS-232 and LAN for LAN: on the models JVC's LAN guide lists the two are exclusive. That guide does not list the RS49 / X500R, so check on the projector whether your menu has the item rather than assuming it.
Ready for controlled commissioning. The package, Lua 5.1 runtime, exact wire frames, ACK pacing, power-state machine, held power and input commands, TV-proxy contract, poll miss accounting, license gate, persistence, and documentation pass automated QA against a simulated projector that answers as JVC's specification describes. A qualified dealer must still complete a fresh install and an observed control test against a real projector on the target controller.

What you get

  • A Control4 video endpoint: Watch, Room Off, and discrete HDMI 1 / HDMI 2 selection through the room, with input changes from the JVC remote reported back to the room
  • Two-way control over RS-232 or over the network (LAN), with the same command set, ACK pacing and power-state machine on both
  • An optional IR Power On assist for sites that keep ECO Mode on, where the projector's port cannot hear a Power On from standby, with a Test IR action to prove the emitter
  • JVC's ACK pacing: one command in flight at a time, the next sent only after the projector acknowledges the last, as JVC's specification requires
  • Power On / Off with warmup modeling and cooldown read from the projector: a Power On during cooling and a Power Off during warmup are held, then released when the projector can accept them
  • Input changes held through warmup, so a Watch press on a cold projector still ends on the right input
  • Picture mode, lens memory 1-5, anamorphic Off / A / B, aspect, and lamp power as programming commands, each written with JVC's documented frame
  • Lamp hours, picture mode, and the projector's model code read back into properties and variables
  • Read-backs of ECO Mode (flagged when On, because it silences the port in standby), the video input signal (with Signal Present / Signal Lost events), anamorphic, aspect, lamp power and the projector's own remote code, a Set ECO Mode command, an installer Lamp Alert Hours threshold with a Lamp Hours Alert event, and a Diagnose Link action that ranks the likely causes of a silent link
  • The room remote's menu, cursor, OK, back, info, and aspect keys passed through, plus a Send Remote Key command for the JVC remote's setup keys

2 The feedback contract

This driver never invents state. Everything it reports comes from what the projector answers:

  • The power poll (3F 89 01 50 57 0A) reads Standby, Lamp On, Cooling, or Error straight from the projector, every Power Poll (s) and every 5 s while a power change is in progress. Cooling is reported by the projector, so a held Power On is released the moment it reports Standby.
  • Warmup is the one thing the driver models. This generation is assumed to report Lamp On as soon as the lamp strikes (JVC's 2015 command table lists the warming code only as Reserved and says nothing about warmup, so confirm this on the bench), so after a Power On the driver holds input and power-off commands for Warmup Time (s), then reads the input, picture mode, and lamp hours. The window is never shorter than 25 s, whatever Warmup Time (s) says: the 15 s grace window and the 10 s Power On ACK wait have to fit inside it.
  • Every input change is followed by an input query, and the room hears about the input the projector reports, not the one that was asked for.
  • The projector answers nothing for a command it cannot act on: an unsupported value, or anything except power and the null command while in standby. The driver reports that as No ACK in Last Error. Only power polls that draw no ACK at all count toward Communication = Lost, so one ignored command never takes the projector offline.
  • While someone is working the JVC's own menu, it ACKs queries at once but holds the answers. The driver treats that as alive and busy and stays quiet about it. A held power or input answer that arrives late is still applied; a late picture-mode, lamp-hours or model answer is dropped, and Refresh Status asks again.
  • A frame that starts with the controller's own header (21 or 3F) is the controller's command coming back, from a loopback plug or an echoing adapter. It is never counted as a projector reply, so it cannot make Communication read Responding.
  • A Power On or Power Off that draws no ACK is sent again, up to four more times, 6 s after each unanswered try (the ACK wait is 10 s) and only while it is still the latest press; a lamp that is still warming ignores Power Off, for example. A Power Off the projector ACKs but leaves the lamp lit (or a Power On it ACKs but leaves in standby) is sent once more after the 15 s grace window. Last Error only reports it when the tries run out.
  • While the projector is On the driver also reads what it has set: ECO Mode, Input Signal, Anamorphic, Aspect, Lamp Power and Projector IR Code (see Read-backs and alerts). Each is a quiet query: a projector that does not answer one never raises Last Error for it, and a setting written to it is followed by a read, so a write the projector ignored leaves the property showing what it really holds. Lens memory is not read back, because JVC's 2015 command table lists no reference for it.
  • After a controller reboot Power State and Current Input restart at Unknown and, while the state is still Unknown, one power poll goes out about 1.5 s after the driver starts, so they fill in within seconds even with a slow Power Poll (s). Only Lamp Hours (and the fact that the lamp alert has fired) is restored from persistence; Serial Received, Last Response, Last Command, Projector Model, Picture Mode, ECO Mode, Input Signal, Anamorphic, Aspect, Lamp Power, Projector IR Code and Link Diagnosis restart too, so they only ever describe this session.

3 Wire and commission

  1. Choose Control Method. The steps below are for RS-232 (two-way over the serial port); for the others see LAN control and IR Power On assist below, and IR control (the fallback) for IR alone.
  2. On the projector, open Function and set ECO Mode to Off (JVC's user guide, linked above). If the menu has Communication Terminal, set it to RS-232C. Note the Remote Code setting (A or B) on the same menu.
  3. Wire a controller or IO-extender serial port to the projector's RS-232C D-Sub 9 port with a crossover (null-modem) cable or adapter. JVC's pinout is pin 2 RXD, pin 3 TXD, pin 5 GND, and its guide says a PC (DTE) needs a cross-connected cable. If your controller's port is wired the other way round (check its documentation), the straight cable is the right one: the loopback test in The projector never answers below tells you which end is at fault.
  4. The controller port must run 19200 baud, 8 data bits, no parity, 1 stop bit, no flow control. The driver declares those settings, but the sources behind this driver do not say when Composer applies them to the port, so read the port's live setting in Composer and set 19200 8N1 by hand if it differs. If the driver was just updated, unbinding and binding Projector RS-232 Port again (or removing and re-adding the driver) is a cheap thing to try. A wrong baud looks exactly like a projector that never answers.
  5. Add IntegrateIT JVC D-ILA Projector to the room. In Connections, bind Projector RS-232 Port to the serial port.
  6. On the AV tab, bind your sources or matrix outputs to HDMI 1 and HDMI 2, and confirm the room's video endpoint is the projector (the Room Selection - Video binding).
  7. Set Remote Code to match the projector, and set Warmup Time (s) to how long your projector takes from Power On to a usable picture (default 60 s, minimum 25 s).
  8. Run Test Connection from the Actions tab. The projector ACKs JVC's null command in standby or on, so Status reads Test Connection passed when the cable, port settings, and Communication Terminal are right. If it fails, follow The projector never answers below. With an IR Power On method this tests the two-way link only: press Test IR as well, with the projector on, and watch for its information screen (see IR Power On assist).
  9. Run Refresh Status and confirm Communication reads Responding, Power State matches the projector, and Projector Model shows XHK1 (RS49U / X500R) or XHK2 (RS4910). With the projector On, also check that ECO Mode reads Off (if it reads On, Last Error explains why Control4 will not be able to turn the projector on from standby) and that Projector IR Code matches your Remote Code setting.
  10. Press Watch on a source in the room with the projector off. Expect Power On, then the input switch once warmup ends. Press Room Off and expect Cooling Down, then Off.

4 LAN control

Set Control Method to LAN (or LAN + IR Power On) to drive the projector over the network instead of the serial port. The commands, the ACK pacing, the power-state machine, the held Power On / input, the polls and the room's video endpoint are exactly the ones RS-232 uses; only the transport differs.

Set up

  1. On the projector, open Function > Communication Terminal and change it from RS-232C (the default) to LAN. JVC's LAN guide describes this for the models it lists (DLA-X7, X9, X30, X70, X90, RS50, RS60, RS45, RS55, RS65): it enables the Network menu, and the RS-232C port is no longer the control port, so LAN and RS-232C are not both live. That list does not include the RS49 / X500R. If your projector's Function menu has no Communication Terminal item, look in its manual for how it selects LAN rather than hunting for the item.
  2. In the projector's Network menu set its IP address (and DHCP, Subnet Mask, Default Gateway if your network needs them). Give it a DHCP reservation or a fixed address so it never moves, and ping it from the same network.
  3. Set Function > ECO Mode to Off if the projector must be controlled from standby: JVC's user guide (https://manual3.jvckenwood.com/projector/mobile/dla/lch60830-001en/QUDFSYuraxfcif.php) gives that rule for RS-232C and LAN alike. With ECO Mode On, use LAN + IR Power On.
  4. In the driver, set Control Method to LAN, Projector IP Address to that address, and leave LAN Port at 20554 (the only port the projector uses). The serial port and Projector RS-232 Port are not used; Serial Port reads Not used.
  5. Run Test Connection: Status reads Test Connection passed, Communication reads Responding, and LAN Status reads Idle - last exchange OK. Then follow steps 6 to 10 of Wire and commission.

What the driver does for every command. JVC's guide requires the same handshake in front of each command, and the projector closes the socket about 5 s after one, so the driver gives each queued command its own connection:

  1. It creates a dynamic network connection to Projector IP Address and connects to LAN Port. Director is told not to reconnect or probe it, because JVC closes the socket by design. No connection within 5 s is a timeout; a connection that is refused or closed at once is reported as refused.
  2. The projector sends PJ_OK. The driver answers PJREQ at once (JVC allows the controller 5 s). If instead it sends PJ_NG it is busy (JVC allows one LAN connection, so another controller or app, such as JVC's phone app, holds it): the driver closes, waits 0.5 s, then 1 s, 1.5 s and 2 s, and tries up to four more times. After that it gives up on that command and says so in Last Error; the next command or poll tries again. PJREQ is never sent to a busy socket. PJ_NG is the projector answering, so it is not counted as a missed poll: a busy projector does not go Communication Lost, its Power State is not forgotten, and no second Power On event fires when the other client lets go. The first valid reply clears the busy note from Last Error.
  3. The projector answers PJACK. Only now is the command frame written, the same binary frame the serial port carries. The ACK clock (ACK Timeout (ms), or the longer 10 s and 30 s waits for power, input, picture-mode and lens commands) starts from this write, so a slow connection never eats into it.
  4. The ACK and any response are parsed by the same code RS-232 uses. The moment the reply is complete, the driver closes the socket itself, so the projector is free for the next connection.
  5. New connections are kept at least 0.75 s apart after a query and 1 s after an operation. A burst of menu cursor presses is therefore slower over LAN than over RS-232, where presses go out about 0.1 s apart: over LAN they are at least a second apart. The driver does not reuse an open socket, because JVC's guide requires the handshake before each command, and an open socket could leave the projector answering PJ_NG (busy) to the next connection.
  6. Each power poll is one such connection and handshake, and while the projector is On the input and signal queries that go with it are two more. Keep Power Poll (s) at its default or longer.

No password. The driver sends a bare PJREQ. JVC's LAN guide does not describe a password for the models it lists, but an open-source JVC client (pyjvc) sends one in PJREQ when it is set, and answers PJNAK with a retry, so some projectors do ask for one. If a projector answers a bare PJREQ with PJNAK, the driver reports that in Last Error and LAN Status and does not try to answer it: a projector with a LAN password set (or a model whose handshake differs) is not supported over LAN. Nothing supplied says whether the RS49 / X500R has a password, so if you hit PJNAK, check the projector's Network menu for one.

Slow commands. JVC ACKs an input switch, a picture-mode change and a lens recall only when the operation is done, which can be longer than the projector keeps a LAN socket open. If the socket closes before such an ACK, the driver reports the projector closed the connection before it ACKed ... may still have landed rather than claiming it was ignored, and asks the projector which input or picture mode it is on now. An input switch is also retried like it is over RS-232.

A lens-memory recall is different. The projector ACKs it only when the lens stops (up to 30 s), and it closes the LAN socket about 5 s after the command, so over LAN the ACK normally cannot arrive, and JVC lists no lens-memory reference, so there is nothing to read back. The driver does not call that an error: Status reads Lens Memory 2 sent; over LAN the lens move outlasts the connection, so it cannot be confirmed and Last Error is left alone. Look at the screen, or use RS-232 where you need the move confirmed.

LAN Status shows the progress of the current exchange (Connecting, PJ_OK - sent PJREQ, Handshake complete), Idle - last exchange OK after a good one, or the last failure: connection refused, no connection within 5 s, no PJ_OK, closed before PJ_OK, PJ_NG (busy), no PJACK, PJNAK, closed before the ACK, or Projector IP Address is empty. An empty address sends nothing and never marks the projector Lost.

6 IR Power On assist

A projector with ECO Mode On puts its RS-232C / LAN port to sleep in standby, so it cannot hear a Power On sent over that port, and a room that powers it off from Control4 can never power it back on. JVC's user guide gives the rule for sites that can: set ECO Mode to Off. Sites that must keep it on use RS-232 + IR Power On or LAN + IR Power On.

  • Where to wire it. Bind Projector IR to a controller IR output and put the emitter over the projector's IR window, as for IR control, and bind the serial port or set the LAN address as for the two-way method. Remote Code selects the A (73) or B (63) code.
  • What it sends. Every time the driver sends a Power On to the projector, it also sends JVC's discrete IR Power On code, once, through Projector IR. Only Power On uses IR: inputs, Room Off, picture modes and the rest stay on the two-way link, so everything is still read back while the lamp is on.
  • The warmup. The warmup window starts from the IR press, because IR is the one command a sleeping port cannot refuse. The two-way Power On is sent right behind it and is best effort: it is not retried, and no ACK for it is not an error (a sleeping port is the whole case). A held input is released when the warmup closes, by which time the port should be awake and answering. If the projector then reports Standby after the 15 s grace window although the two-way Power On was ACKed, the driver sends Power On once more, IR included.
  • When it does not send IR. A Power On that finds the projector already On or Warming Up sends nothing, with one exception: if nothing has answered over the two-way link yet (a dead port, or an IR code that never arrived), the driver sends the IR code again and restarts the warmup, because that On could never be repaired otherwise. While the state is Unknown (just after a reboot) the driver first asks the power state over the link, as it always does; if nothing answers, it sends the Power On and the IR code, so a Watch on a sleeping projector takes a couple of seconds longer than on a known one.
  • Standby reads as Off. After a Room Off the projector cools down and then goes to sleep. If it stops answering while the state is Cooling Down, or after it has already answered standby (a projector may answer one standby poll before its port goes dark), these Control Methods read that as standby: Power State becomes Off (not Unknown) and Communication reads Lost, with a note in Last Error about ECO Mode. A Watch held during that cooldown is released and powers the projector on by IR. Polls keep running, and the first answer returns Communication to Responding. The other Control Methods keep reading a silent projector as Unknown.
  • Dead serial line. If the two-way link never works, the room is not stranded: Watch still powers the projector on by IR and models the warmup, while Communication shows the dead line and its advice.
  • IR that never reaches the projector. While the modeled warmup runs, unanswered polls do not declare the projector Lost and a held input is kept: a sleeping port can take a while to wake. If nothing has answered over the two-way link when the warmup closes, the IR code most likely never arrived (emitter mis-aimed, wrong Remote Code), so Power State returns to Unknown instead of claiming On, a held input is dropped, and Last Error says to check the emitter, the binding and Remote Code. Watch again sends the IR code again, and so does Watch pressed during such a warmup.
  • Room Off right after Watch. The IR Power On leaves the moment Watch is pressed, so a Room Off pressed while the two-way Power On is still waiting behind another exchange cannot cancel the IR code. The queued two-way Power On is dropped and the Power Off is held until the warmup closes, then sent, so the lamp does not stay lit.
  • Prove the emitter. Press Test IR on the Actions tab with the projector on. It sends JVC's Info key once through Projector IR, and the projector's information screen should appear. Nothing comes back over IR, so the screen is the proof; do this before relying on the assist. Test Connection does not do it under these methods, because it tests the two-way link. Under RS-232 and LAN, Test IR sends nothing and says IR is not used. If Projector IR is not bound, Last Error says so.
  • License. The IR code is gated by the license like every other control path.

Changing only between a two-way method and its IR Power On version (for example RS-232 to RS-232 + IR Power On) keeps what the driver has learned; changing between RS-232, LAN and IR starts again from Unknown, as does changing the address or port; the frame and handshake counters Diagnose Link reads start over too.

7 Read-backs and alerts

These are read from the projector while it is On, over RS-232 or LAN (IR reads nothing). Each is a quiet query: if the projector does not answer, nothing is written to Last Error. They are read when the projector reaches On and on Refresh Status; the ones the driver can set are also read right after the command. A change made with the JVC remote therefore shows after the next Refresh Status (or power-on), except Input Signal, which is asked with every power poll. A one-shot read (ECO Mode, anamorphic, aspect, lamp power, the projector's remote code) that drew no ACK is asked again on later polls once the projector has answered an On-only command, up to three misses each, so a lamp that was still settling at power-on does not leave them at Unknown (or lose the ECO Mode warning).

ECO Mode. ECO Mode shows the projector's Function > ECO Mode setting (JVC command FUEM). With ECO Mode On the projector's RS-232C / LAN port goes dark in standby, so Control4 can switch it off but never on again, and nothing shows that while it is lit. JVC's user guide says to set ECO Mode to Off if RS-232C or LAN communication is used in Standby mode (https://manual3.jvckenwood.com/projector/mobile/dla/lch60830-001en/QUDFSYuraxfcif.php). When the driver reads On it says so in Last Error and Status, and every refresh or power-on repeats the warning; reading Off clears it. With an IR Power On Control Method ECO Mode On is the case the assist exists for, so only Status says so. The Set ECO Mode command (Off or On, projector On, RS-232 or LAN) writes the setting and reads it back; the driver never changes ECO Mode by itself. If the projector later goes quiet in standby while ECO Mode was read On, the dead-line advice names it as the cause.

Input signal. Input Signal reads Present or No signal (JVC's source query SC), or Logo (starting) on older projectors that answer a raw 0x00 while their logo is up. It is asked with every power poll while the projector is On, and when it reaches On. The variable SIGNAL carries the same text. The Signal Present event fires when the projector starts reporting a signal (including the first answer after the driver or projector started); Signal Lost fires only when a signal it had reported goes away (a first answer of No signal is not a loss), and neither repeats while the answer stays the same. Input Signal returns to Unknown when the projector leaves On, without an event. A projector that never ACKs the source query is asked three times and then left alone (Input Signal reads Not reported); Refresh Status and the next power-on try again. The three misses only count once the projector has answered some other On-only command: right after the lamp strikes a projector can ignore everything for a while, and until it answers something the source query is simply asked again with each poll. Over LAN each query is one more connection, so a poll while On is three connections (power, input, signal): keep Power Poll (s) at its default or longer.

Lamp alert. Set Lamp Alert Hours to the lamp hours at which you want to hear about it (0 is off; JVC publishes no rated lamp life, so you choose). The Lamp Hours Alert event fires once when a lamp reading first reaches that number. The driver remembers that it fired, so a controller restart does not repeat it; a reading below the threshold (a new lamp, or a raised threshold) arms it again, and a changed threshold fires again for the new number. A changed threshold is compared with the lamp hours already read at once, so to test the alert set Lamp Alert Hours below the current Lamp Hours and the event fires straight away (once). With a threshold set, lamp hours are re-read about every hour while the projector is On, as well as at every power-on and on Query Lamp Hours; with none set they are not re-read.

Anamorphic, aspect and lamp power. Anamorphic (Off, A, B), Aspect (4:3, 16:9, Zoom, Auto, Just, Full) and Lamp Power (Normal, High) show what the projector holds, with the variables ANAMORPHIC, ASPECT and LAMP_POWER. Set Aspect offers 4:3, 16:9 and Zoom; the projector may report Auto, Just or Full if someone picked them on its remote. A code the driver does not know shows as Unknown (x). A write the projector ignores is reported as No ACK in Last Error, and the property keeps showing what the projector actually holds.

The projector's remote code. Projector IR Code shows the remote code the projector says it listens to (A is 73, B is 63; JVC command SURC), read when it is first On and on Refresh Status. If it differs from Remote Code here, Last Error and Status say so: JVC's guide says a projector switched to Code B responds only to Code B, so menu keys, Send Remote Key and IR codes sent with the other code are not accepted. Fix it by changing Remote Code (the warning clears at once) or the projector's Function > Remote Code.

8 Diagnose Link

Run Diagnose Link from the Actions tab when the projector is silent or misbehaves. It reads what the driver has counted this session and sends nothing to the projector, so it works even under Strict license enforcement (where it says that is the problem). It prints a verdict, the checks to do, most likely first, and the facts it used to the Lua output window, and stores the one-line verdict in Link Diagnosis.

  • RS-232: the binding (Serial Port), frames sent, bytes received, valid replies and echoes of the controller's own frames, and Communication. It tells apart: the port not bound; nothing sent yet (run Test Connection first); your own commands coming back (loopback or echo); bytes that are not JVC replies (baud or cable); nothing at all coming back (the checks are the controller port's 19200 8N1, re-binding after a driver update as something to try, the cable, a loopback test, Communication Terminal and ECO Mode, the projector's Function > Control4 setting if it has one, a PC test, then the IR Power On or LAN alternatives); with an IR Power On method, a quiet port after Room Off is reported as a Note (the projector is most likely asleep with ECO Mode On, which is what those methods are for) with the IR side to check, not as a problem; a projector that answered and then stopped; and a healthy link. If ECO Mode was read On, that check goes first.
  • LAN: the address and port, and how far the handshake got. It tells apart: an empty Projector IP Address; nothing tried yet; no TCP connection (Communication Terminal, address, network path, another controller holding the connection, ECO Mode); connections that only ever answer PJ_NG (another controller or app holds the projector's one connection); connections without PJ_OK; PJ_OK without PJACK (or PJNAK, a refused handshake); a working handshake with no ACK (ECO Mode); a projector that answered and then stopped; and a healthy link.
  • IR: one-way, so there is no verdict to read from the wire; it lists what can be checked (binding, emitter, Remote Code, Test Connection) and flags an unbound Projector IR.

Link Diagnosis reads OK, Problem, Not tested yet or Note, and Not run until the action is used. It is a snapshot of the counters at that moment; run it again after changing something. The counters start over when Control Method moves between RS-232, LAN and IR or the LAN address or port changes, so a serial session's replies never make a LAN link look healthy.

9 The projector never answers

This list is for the serial methods; for LAN see LAN never connects. Run Test Connection and then Diagnose Link first: it names the most likely cause from the counters and ranks the checks. If Test Connection fails and Serial Received reads Nothing yet, work down this list. Each step rules out one thing.

  1. Set Debug Mode to Print and run Test Connection again. The Lua output window shows tx: ! <00><00> (the null command) when the driver writes it, and Last Command shows the same. If nothing is written, check License Status (Strict enforcement blocks control), that Control Method is RS-232 and not IR, and Serial Port.
  2. Loopback: unplug the cable from the projector and jumper pins 2 and 3 at the controller end. Run Test Connection. It should fail with Your own command came back (loopback or echoing adapter) and Serial Received should start counting bytes (6 for each null command, and its last chunk reads 21 89 01 00 00 0A). That proves the binding, the controller port and this driver receive correctly, and that the problem is the cable, the baud or the projector. If Serial Received stays at Nothing yet, fix the binding and the port first. Remove the jumper afterwards.
  3. Check the baud. Read the port's setting in Composer and make it 19200 8N1; if the driver was just updated, re-binding Projector RS-232 Port is a cheap thing to try (step 4 above).
  4. Test the cable and projector with a PC: a USB serial adapter and a terminal program such as Hercules, on the same cable, at 19200 8N1 and a cross-connected cable. Send hex 21 89 01 00 00 0A; the projector answers 06 89 01 00 00 0A, in standby or on. If the PC gets the answer but the controller does not, the controller port, its baud or the driver binding is the problem.
  5. Try the other cable type (crossover versus straight-through).
  6. Turn the projector on with its remote, set Function > ECO Mode to Off, check Communication Terminal reads RS-232C if the menu has that item, then repeat Test Connection.
  7. If the projector has a Function > Control4 setting (JVC's command list includes one, FUCF, Off or On), look at it and try On. The sources this driver was built from do not say what that setting changes, so treat it as something to try, not a known fix; the driver does not read it.
  8. If the site must keep ECO Mode on, choose RS-232 + IR Power On: the projector is powered on by IR and the serial link takes over once the lamp is lit (see IR Power On assist).

10 IR control (the fallback)

Set Control Method to IR when RS-232 is not an option. In Connections, bind Projector IR to a controller IR output and stick the emitter over the projector's IR window (front or rear). Leave Remote Code matching the projector: Code A sends custom code 73, Code B sends 63.

The codes are JVC's own: the guide's custom code followed by the same key byte the RS-232 pass-through uses, in JVC's 16-bit IR format at 38 kHz. The driver generates them from JVC's published worked example and checks them against it. Power On, Standby, HDMI 1 and 2, picture modes, lens memory 1-5, anamorphic and aspect use JVC's discrete codes; menu, cursor and the setup keys use the remote's keys.

IR is one-way, so the driver models what it cannot read:

  • Power On starts the warmup window (Warmup Time (s)); an input picked during it is sent when it ends.
  • Power Off sends Standby twice, 1.5 s apart, because the JVC asks you to confirm. It then counts down Cooldown Time (s) from the second, confirming press; a Power On in that window is held and sent when it ends, since the projector ignores Power On while cooling.
  • Power On and Standby are discrete codes, so pressing Watch or Room Off again always sends the code again, even when the model says the projector is already on or off. That is how you repair a model that drifted (someone used the remote, or power was lost). A repeat does not restart the warmup or cooldown windows; only a Power Off during warmup and a Power On during cooldown are held.
  • After a restart or a Control Method switch the model reads Unknown. Keys, inputs and picture modes are sent anyway (nothing in IR could ever tell the model the projector is on). While the model says the projector is off, warming up or cooling down, keys and picture modes are refused with a reason, but an input is held, not refused: it is sent when the next warmup ends, and a Room Off drops it.
  • A Power On pressed while the model already says On or Warming Up sends the IR code again, and the input key that follows goes out at once, as usual. If the projector was really off (someone used the remote), it may be only starting when that key arrives and ignore it. So the same input key is sent once more when Warmup Time (s) has run, unless you chose a different input, pressed Room Off, or changed the Control Method first. The discrete input codes are harmless to repeat on a projector that was already on.
  • The input is assumed to be the one sent, and the room is told so.
  • Lamp power and lamp hours have no IR equivalent and are refused with a reason; ECO Mode, the input signal, anamorphic, aspect, lamp power and the projector's remote code are read over RS-232 or LAN only, so they read Unknown under IR, and Set ECO Mode is refused with a reason.
  • Test Connection (and Test IR) sends the Info key: with the projector on, its information screen appears if the emitter reaches it.
  • IR Port shows whether Control4 reports Projector IR as bound; while it is unbound, Last Error says nothing leaves the controller. Control4 cannot tell whether an emitter is attached to a bound output, so watch the projector.
Because nothing comes back over IR, the driver cannot see changes made with the JVC remote, and Power State can drift from reality if someone uses the remote or the projector loses power. Prefer RS-232 wherever it works.

11 Protocol on the wire

Every frame is binary: a header byte, the fixed unit id 89 01, a two-character command, optional data, and a line feed. Over LAN the same frames are carried inside JVC's connection handshake (PJ_OK, PJREQ, PJACK, then the frame; see LAN control). Operations start with 21 (!), queries with 3F (?). The projector replies 06 89 01 <command> 0A (ACK) and, for a query, 40 89 01 <command> <data> 0A right after it. Last Command and Last Response show these frames as readable text, for example ! PW1, ACK PW, and @ PW1.

12 Warmup, cooldown and held commands

JVC ignores a Power On while the projector is cooling, and the lamp is not ready for input commands the instant it strikes. The driver holds what the projector cannot take yet:

  • After the projector ACKs a Power On, Power State is Warming Up for Warmup Time (s). An input change in that window is held and sent when it closes. A Power Off in that window is held and sent when it closes.
  • If the projector ignores that input switch because the lamp is still warming past Warmup Time (s), the driver tries again twice, 5 s apart, and clears the error once it lands. A newer input choice or a Room Off cancels the retry, even one that was still on the wire when you chose.
  • After the projector ACKs a Power Off, Power State is Cooling Down until the poll reports Standby. A Power On in that window is held and sent the moment it does. A Watch pressed during cooldown keeps both its power-on and its input.
  • One power intent is held at a time, and the latest press wins, even against a power command already on its way. Room Off pressed before a queued Power On reaches the wire cancels it outright; pressed while the projector is still acknowledging it, the Off is held and sent when warmup ends. The same holds the other way round, and a Watch pressed while a Power Off is on its way keeps its input.
  • For 15 s after a power command is ACKed, poll replies that still show the previous state are ignored, so the room does not bounce between on and off while the projector changes over. If the lamp is still in the old state when the window ends, the command is sent once more.
  • A Watch or Room Off pressed while the state is still Unknown (just after a reboot) asks for the power state first and acts on the answer, so a projector that is already in standby is never sent a Power Off, and one that is already on is never re-powered. If nothing answers the query, the press is sent anyway (a Power On only once), so a dealer can tell a silent line from a silent projector.
  • Picture, lens, aspect, and remote-key commands are refused with a named reason in Last Error unless the projector is On, because it would ignore them anyway.
Power On and Power Off cycle a real projector lamp. Leave Warmup Time (s) at a realistic value instead of flooring it to make a demo feel faster.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. With Automatic Update Install set to Auto-stage (the default), a new release is downloaded onto the controller by itself and installs at the next Director restart — no re-adding the driver, and settings, bindings, and programming are preserved. Set it to Notify only to be told about updates without staging them.

  1. A new release appears as Update Available: vX.Y.Z and the driver fires its Update Available event (or run Check for Update Now).
  2. Auto-stage fetches the new .c4z onto the controller by itself; with Notify only, run the Download & Stage Update action instead. The property then reads STAGED.
  3. The staged version loads at the next Director restart (System Manager > Restart Director, or a controller power cycle). To apply immediately without a restart, update from a local copy of the new .c4z in Composer.
Composer’s right-click Update Driver reads the PC’s local driver folder, not the controller-staged file — with an old local copy it quietly reinstalls the old version. Field-confirmed 2026-08-30; trust the restart, or use a fresh local file.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

D Diagnostics and self-test

Every IntegrateIT driver carries two read-only Actions for the field. Run Diagnostics prints a report of what the driver has already observed — version and Lua runtime, license mode and cached activation, update channel and any staged build, every armed timer with its interval, which dealer-supplied properties are still empty, and the last few Status messages. It probes nothing, sends nothing, and changes nothing, so it is safe on a live job. Run Self-Test checks the shared layer itself — string and URL encoding, version comparison, the non-finite number guard, the timer registry, and the persistence store — and ends with SELF-TEST PASS or a per-check failure. It stays local: no network, no device commands.

Neither Action is license gated, on purpose: you reach for them when a site is broken, and the license may be the broken thing. Values are never printed — a key or secret is reported only as set or NOT SET, so the output is safe to paste into a support ticket. Both print to the Lua output window (Composer → the driver's Lua tab).

v0.2.0 current2026-11-01
  • LAN control: Control Method now offers RS-232, RS-232 + IR Power On, LAN, LAN + IR Power On and IR. LAN uses JVC's TCP 20554 handshake (PJ_OK, PJREQ, PJACK) per command, and Last Error names refused, silent, busy (PJ_NG) and password (PJNAK) cases. Existing RS-232 and IR projects keep their setting. A lens recall over LAN reports as sent, not as a No ACK, because the lens move outlasts the connection.
  • IR Power On assist: the + IR Power On methods send JVC's discrete IR Power On with every Power On, so a projector whose port sleeps in standby (ECO Mode On) still turns on; everything else stays two-way. A quiet port in standby reads as a note, not an error. New Test IR action sends the Info key to prove the emitter, the IR binding and the Remote Code, and "Projector IR is not bound" stays in Last Error until the output is bound.
  • Diagnosis: new Diagnose Link action and Link Diagnosis property print a verdict and a checklist, most likely cause first (port baud, binding, crossover cable, ECO Mode, Communication Terminal, Control4 setting). The driver also recognises and names echoes from a loopback plug or an echoing adapter. Counters restart at boot and on a Control Method change.
  • Read-backs: ECO Mode (plus Set ECO Mode), input signal (Signal Present and Signal Lost events), anamorphic, aspect, lamp power and the projector's own remote code are read into properties and variables. If the projector's remote code differs from the Remote Code property, Last Error names both. Lamp Alert Hours fires a Lamp Hours Alert event once per threshold. It takes effect as soon as it is changed and survives restarts.
  • Power reliability: a power command with no ACK is retried up to 4 times, 6 s apart. A command the projector ACKs but ignores is sent again after the 15 s grace window, even if Watch or Room Off is tapped again or alternated meanwhile. A Watch keeps its input through those retries. Power On from Unknown is sent even if the power query is not answered; Room Off from Unknown asks first. Set Picture Mode waits 10 s for its ACK. Warmup Time is now at least 25 s.
  • IR only: an Unknown model no longer refuses commands. Power On and Standby are always sent, so a projector switched off with the JVC remote can be brought back. After a re-sent Power On, the input key is sent again when Warmup Time ends, so the input still lands. Cooldown counts from the confirming second Standby.
  • Docs: the guide and catalog are rewritten for LAN, the IR assist, read-backs and Diagnose Link. Hardware claims the sources do not prove are hedged: Communication Terminal exclusivity, when Composer applies the serial settings, and Lamp On timing. Power On and Power Off events are documented as also firing when the state is relearned after a restart or a lost link. Correction to the 0.1.0 notes: declaring 19200 8N1 does not guarantee the bound port uses it, so check the port in Composer.
