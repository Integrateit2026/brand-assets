1 Start here

IntegrateIT Optimus AI puts a branded AI assistant, Service Requests, and a "My System" health view directly inside Control4 Navigator — the phone app, tablets, and touch screens — as a WebView experience served by the IntegrateIT relay. The driver runs an outbound-only poll loop against that relay: it never opens an inbound port, it asks the relay what the assistant decided, and it carries out each decision by firing a Control4 event that a dealer has wired to a real scene, macro, or device. It also pushes system health, and optionally selected device state, back to the relay so the customer's My System page stays live. The relay endpoint and the assistant model are configurable; the default relay is https://relay.integrateit.dev.

This driver is cloud-dependent by design. The assistant, its decisions, and every direct control depend on the IntegrateIT relay being reachable and on the selected AI provider. While the relay is down the driver backs off and keeps retrying, but no new actions arrive until it returns. Optimus is a convenience layer over Control4 programming — not a life-safety or alarm path, and it never disarms anything.
Ready for controlled commissioning. The package, Lua runtime, relay poll loop with backoff, the action executor, sensitive-action gating, the runtime WebView URL push, and the state push all pass automated QA and a device runtime simulation. This is a release candidate — a qualified dealer must still complete a fresh install and observed tests against a real controller, a live relay site, real Navigator clients, and the actual wired devices before handoff.

What you get

  • A Navigator experience button that opens the Optimus AI app (or a driver-hosted quick-control panel) with the per-site URL pushed at runtime — no address to type by hand
  • An outbound-only relay poll loop with exponential backoff (your Poll Interval Seconds, backing off 5–60 s while the relay is unreachable) and a live Relay Connection status
  • The assistant drives lighting, scenes, TV, music, thermostat, shades, fans, locks, garage, and announcements as Control4 events a dealer wires to real devices — plus volume and mute, which go straight to a room
  • A sensitive-action gate (Allow Sensitive Actions) that fails safe on unlock and garage-open
  • Optional two-way context: a configured Lock or Thermostat device's live variables ride the 30 s state push
  • Optional per-site Anthropic API Key and AI Model override, sent to the relay only
  • Per-controller licensing and in-place over-the-air updates that preserve properties, bindings, and programming

2 Safety boundary

Optimus can be wired to unlock a door and open a garage. Those are events a dealer chooses to connect — the driver never actuates hardware itself. Review the sensitive-action policy and the Composer wiring for every site before handoff, and keep the door and garage in view while you test them.

The driver treats lock, unlock, garage-open, and garage-close as sensitive and defends them three ways:

  • Explicit boolean only. A lock or garage action acts only on a real boolean. A missing or garbage field is a no-op — a malformed {"type":"lock"} never fails open to Unlock, and a bare {"type":"garage"} never opens the door.
  • The Allow Sensitive Actions gate. Set to No, the driver blocks the risky direction — unlock and garage-open — while still allowing lock and garage-close. Yes (with confirmation) permits both — but the driver itself never prompts. Any confirmation happens in the relay-hosted assistant before the action is sent; the gate is the only part of that policy this driver enforces.
  • No back door through scenes. A named scene may fire only non-sensitive events. Naming unlock, lock, garage_open, or garage_close as a scene fires nothing and is not even recorded as a custom scene — the typed, gated branches are the only path to those events.

Everything else the assistant asks for (lights, TV, music, thermostat, shades, fans, volume, announcements) runs without the gate.

3 Wire and commission

  1. Make the experience button visible first. In each room's Navigator properties set the Optimus AI button to Visible, then Refresh Navigators. It will not appear until you do — do this first so every later step can be confirmed from a real Navigator.
  2. Create the customer's site in the IntegrateIT Ops Portal Site List and copy the Site ID and Site Token.
  3. Add IntegrateIT Optimus AI to an always-on room (the Family Room is a good choice). Set Relay URL, Site ID, and Site Token. The driver pushes the fully-qualified app URL to Navigator at runtime (URL_CHANGED) as soon as these are set — there is no WebView address to enter by hand.
  4. Optionally set Default Room ID (the room the assistant raises, lowers, and mutes volume in), a Camera Snapshot URL, and a per-site Anthropic API Key / AI Model.
  5. Choose WebView Mode: Optimus AI app (the full relay-hosted assistant) or Quick-control panel (a driver-hosted controller:// page that drives Control4 directly).
  6. Review Allow Sensitive Actions with the customer, and wire each Optimus event you intend to use to a real scene or device in Composer (see Program the project).
  7. Enter the License Key and confirm License Status. Run the Test Relay action — Status should read Relay OK. Open the button in Navigator, confirm the app loads, and confirm a test command reacts.
Leave Allow Sensitive Actions at No until the lock and garage wiring has been observed on real hardware.

4 How actions reach the home

The driver polls GET /api/site/<id>/actions on the relay every Poll Interval Seconds (1–60, default 2), carrying the Site Token and the controller MAC. A healthy poll returns a JSON action list; the driver executes each item and reschedules at the normal cadence. On an HTTP error it backs off exponentially — floor 5 s, ceiling 60 s — sets Relay Connection to Reconnecting (n), and recovers to the normal cadence on the next success. Overlapping polls are collapsed by a re-entrancy guard, and a truncated relay body is parsed safely to nothing rather than hanging the Lua thread.

Each action is a small JSON object the assistant produces; the driver maps its type onto a Control4 event or command:

Action typeWhat it does
lights (on bool)All Lights On / Off
scene (name)A matching event (Good Night, Movie, …) or Custom Scene + LAST_SCENE
tv / musicTV On/Off, Music Play/Stop
thermostat (setpoint / mode / delta)Set Temperature (+ LAST_SETPOINT), Heat/Cool/Off/Auto, or a warmer/cooler step
shades / blindsOpen / Close / Stop
fanOn / Off / Higher / Lower
volume (mute / delta)MUTE_ON / MUTE_OFF or three volume pulses to Default Room ID
lock / garageSensitive — see Safety boundary
announce (text)Sets ANNOUNCEMENT_TEXT, fires Announcement Requested
camera_checkGETs the Camera Snapshot URL and posts the image to the relay

The driver's job ends at the event — volume and camera_check are the two exceptions, going straight to the room and to the camera URL — and your Composer programming makes the device move. The driver does not read back whether the light actually changed — anything the customer's My System page shows about a device comes from the optional two-way context below, never from the action merely having been sent.

5 Program the project

Wire the events you use to real scenes and devices in Composer. The full event list is in the Reference below; these are the variables the assistant sets alongside them:

VariableTypeMeaning
RELAY_STATUSSTRINGConnected, Reconnecting, or Not started
LAST_SCENESTRINGThe name for the Custom Scene event to run
LAST_ROOMSTRINGThe room id the last action targeted
LAST_SETPOINTNUMBERThe setpoint for the Set Temperature event
ANNOUNCEMENT_TEXTSTRINGThe text for the Announcement Requested event

Three starting points, wired with this driver's own events and variables:

  • When Custom Scene fires → run your scene by name. Branch on LAST_SCENE and run the matching Composer scene. This is how any assistant-named scene reaches the project without a dedicated event of its own.
  • When Set Temperature fires → set your thermostat. Read LAST_SETPOINT and drive the thermostat; the single-step Comfort Warmer / Comfort Cooler and the Heat/Cool/Off/Auto modes fire as their own events.
  • When Announcement Requested fires → speak it. Announce ANNOUNCEMENT_TEXT on the touch screens or media zones you choose.

Under Strict licensing an unlicensed controller fires no events — the app shell still loads, but every control path, including the Test Event (All Lights Off) and Test Announcement actions, is gated. Lenient mode allows commissioning while License Status carries the nag.

Two-way context is best-effort. Set Lock Device ID or Thermostat Device ID and that device's live variables ride the 30 s state push. If the id is wrong or the OS refuses to read it, the driver logs the gap once and omits it — it never invents a value. Beyond those two device ids this driver observes nothing on its own: the fixed local-state block that rides the push (front door, garages) is a placeholder the driver never updates, so treat Lock Device ID as the only live lock truth. Garage position is deliberately not reported: a generic driver cannot reliably read an external contact sensor's open/closed state, so this driver does not claim to. Garage feedback, if wanted, is a hardware-verified follow-up via a stock contact driver and a watched variable.

Print Configuration writes the relay URL, site, whether the token and API key are set (never their values), the model, poll interval, and license state to the Lua output window.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT product: the Control4 driver, the relay integration, the Navigator experience, documentation, QA, licensing, updates, and support are all built and provided by IntegrateIT. Anthropic and Claude are trademarks of Anthropic, PBC; IntegrateIT is not affiliated with Anthropic, and the choice of assistant model does not change that.

What leaves the controller goes to one place — the configured Relay URL — and nowhere else. Every request the driver makes is outbound: it polls the relay for actions, pushes a state snapshot every 30 s (controller MAC and uptime, driver version, license and relay-health flags, the fixed local-state block, and any configured Lock/Thermostat device variables), and, when the assistant asks for a camera check, GETs the dealer-supplied Camera Snapshot URL on the LAN and posts that image to the relay. No inbound port is opened. The Site Token is a password-typed credential, redacted in the debug log and never printed; the License Key is never printed.

The assistant itself runs relay-side. If you supply a per-site Anthropic API Key, it is sent to the relay (only) and the relay uses it to reach the AI provider — meaning that site's prompts run under your key and your account pays for that usage. Leave it blank to use the relay's own key. AI responses and direct controls depend on the relay and the selected provider being available.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks all Control4 control until the Ops Portal has minted and validated a key for that controller; the app shell loads either way. Installing this package does not itself mint or activate a controller license. Self-update checks the IntegrateIT channel and stages a new package in place, preserving properties, bindings, and programming.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.
