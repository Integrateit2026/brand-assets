1 Start here

IntegrateIT Bond brings a single Smart by Bond device — a ceiling fan, a light, a shade, or a generic learned remote — into Control4 over the Bond Home local HTTP API v2 (the vendor's own published local API, github.com/bondhome/api-v2). There is no cloud hop: the driver talks straight to the Bond Bridge (or a Smart by Bond radio) on your LAN, authenticated by the local token you copy from the Bond Home app, so there is no cloud round-trip and control keeps working even when the internet is down. Set the Bond's IP, its token, and the target device id, wire the commands to keypads and scenes, and a background poll publishes the device's state as Control4 variables and events — so programming reacts to a Bond handheld or the Bond app as readily as to Control4 itself.

The Bond local API is plain, unencrypted HTTP on port 80, authenticated only by the local token. Keep the Bond on a trusted LAN segment. The driver refuses a non-LAN Bond address unless Allow WAN Bond is set to Yes, and it never writes the token to the log.
Release candidate, verified against the Control4 API simulator. The package, Lua 5.1 runtime, action framing, state parsing, event diffing, the LAN guard, the license gate, persistence, and this documentation pass automated QA. A qualified dealer must still complete a fresh install and an observed control test against a real Bond Bridge and physical device on the target controller — acceptance on physical hardware is not yet attached to this release.

What you get

  • One Bond device per instance over the local v2 HTTP API — no cloud dependency (add another instance per fan, light, or shade)
  • Ceiling fan: Power On/Off, Toggle Power, Set Fan Speed, Increase/Decrease Speed, Light On/Off, Toggle Light, Set Brightness, and Summer/Winter Direction
  • Shade / blind: Open Shade, Close Shade, Hold Shade; generic remote: Toggle Power, Toggle Light
  • A configurable state poll that publishes POWER, SPEED, LIGHT, BRIGHTNESS, DIRECTION, and DEVICE_ONLINE
  • Turned On/Off, Light On/Off, and Went Online/Offline events for Composer programming
  • List Bond Devices, Test Connection, and Print Configuration actions to commission without guesswork
  • LAN-only destination safeguard, the Bond token never logged, and MAC-locked IntegrateIT licensing

2 The feedback contract

State feedback is polled, not pushed. The driver reads GET /v2/devices/<id>/state on the Poll Interval (s) (default 5), so a change made from a Bond remote or the Bond app appears on the next poll, not instantly. This is real device state — but only as fresh as the last poll.

  • Boot is silent, then honest. After a controller reboot POWER, LIGHT, SPEED, BRIGHTNESS, and DIRECTION are unknown until the first poll lands. That first poll *adopts* the device's current power and light state silently — it does not fire a spurious Turned On/Off or Light On/Off. Events fire only on a genuine change between two observed polls.
  • Reachability is a real signal. Any HTTP reply — even a 401 or 404 — proves the Bond answered, so DEVICE_ONLINE goes true and Went Online fires (including the very first time it is seen). Only a transport failure (no response at all) marks the device Offline and fires Went Offline.
  • Commands are not acknowledgements. Bond returns no new state inline with a command, so after a successful action the driver schedules a fast follow-up poll (~400 ms) to catch the published variables up. Until that poll, the variables reflect the last observed state, not the command you just sent.
  • BPUP UDP push (port 30007) and mDNS (_bond._tcp) discovery are documented by Bond but out of scope for this version — this driver is poll-only.
If the Bond controls a gas fireplace, heater, or any appliance where an unintended ON is a hazard, treat control as blind: a Toggle Power sends a command the driver cannot confirm, and polled state can lag several seconds behind reality. Keep the appliance's own listed safety controls in place and do not build unattended automation that assumes the flame or heat state.

3 Wire and commission

  1. In the Bond Home app, open the device → Settings → Advanced Settings and note the Local Token and the Bond's IP address. Reserve that IP in your router's DHCP table so it cannot change.
  2. Add IntegrateIT Bond to the device's room. Enter Bond IP Address and Bond Token, and set Device Type to match the hardware (Ceiling Fan, Light, Shade, or Generic).
  3. Run the List Bond Devices action — it prints every device id, name, and type the Bond exposes. Paste the correct id into Device ID.
  4. Run Test Connection to confirm the driver reaches that device. On success it prints the device name and populates Fan Max Speed from the device properties. Set Poll Interval (s) if the default 5 seconds is too fast or too slow.
  5. In Programming, wire the commands for your device type, and optionally react to the events or read the variables.
  6. Optionally enter a License Key (see Ownership, privacy, and licensing) — the driver runs in Lenient mode without one.
  7. Prove it: run Refresh State (or the Refresh State Now action) and watch Device Status turn Online — … and DEVICE_ONLINE go to 1, then exercise a command and confirm the real device reacts.

4 The Bond API on the wire

The transport is HTTP on port 80 with a BOND-Token request header. Every control command is a PUT /v2/devices/<id>/actions/<Action>; state and metadata are GET reads. Composer shows all commands regardless of Device Type — a command the device does not support returns a Bond error surfaced in Status.

CommandWire action (PUT …/actions/…)Body
Power On / OffTurnOn / TurnOff{}
Toggle Power / Toggle LightTogglePower / ToggleLight{}
Light On / OffTurnLightOn / TurnLightOff{}
Set Fan Speed, Increase/Decrease SpeedSetSpeed{"argument":N}
Set BrightnessSetBrightness{"argument":N}
Summer / Winter DirectionSetDirection{"argument":1} / {"argument":-1}
Open / Close / Hold ShadeOpen / Close / Hold{}
  • Set Fan Speed sends the Fan Speed property (1-10), clamped to the device's reported maximum (Fan Max Speed, learned from GET …/properties). Increase/Decrease Speed step the last observed speed by one, clamped 1..max.
  • Set Brightness sends a 1-100 argument. The Brightness property floor is 0 for UI convenience, but 0 is out of range on the Bond wire — a configured 0 is clamped up to 1. "Off" is Light Off, never brightness 0.
  • Reads: GET /v2/devices (enumerate), GET /v2/devices/<id> (name/type), GET …/properties (max_speed), GET …/state (power, speed, light, brightness, direction). 401 means a wrong token, 404 a wrong device id.

  • React to a physical remote: when someone starts the fan from a Bond handheld, the next poll fires Turned On — use it to raise the room lights or set a scene. Turned Off mirrors it.
  • Drive speed from a keypad: set the Fan Speed property (say 6), then call Set Fan Speed — the driver clamps to Fan Max Speed and sends SetSpeed. Or bind a button to Increase Speed / Decrease Speed to step the last observed speed.
  • Watch reachability: program Went Offline to push a notification or set a "needs attention" flag; Went Online (or DEVICE_ONLINE as a condition) clears it.

Control is gated by the license: under Strict enforcement an unlicensed controller sends no action to the Bond. The state poll and all feedback stay live regardless — watching your own device report is not a licensed feature. The default Lenient mode allows commissioning while License Status carries the nag.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation of Bond's published local HTTP API v2 (github.com/bondhome/api-v2, a document Olibra publishes so external equipment can drive Bond devices). It bundles no other vendor's runtime, source, brand assets, trial, or license. Bond and Smart by Bond are trademarks of Olibra LLC; IntegrateIT is not affiliated with Olibra, and this driver is not a Bond product.

Nothing leaves the LAN. The driver talks only to the Bond address you configure and to nowhere else; no device state, customer identity, or Control4 credential is sent to any device vendor. The Bond Token is treated as a secret — it travels only in the request header and is never written to the Lua log, not even with Debug Mode on. A public or routable destination is refused outright unless Allow WAN Bond is deliberately set to Yes.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks all Bond control until the Ops Portal has minted and validated a key for that controller; the state poll and feedback continue either way. Installing this package does not itself mint or activate a controller license. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.
