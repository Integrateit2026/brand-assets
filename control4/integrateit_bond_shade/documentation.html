1 Start here

IntegrateIT Bond Shade gives Control4 dedicated control of one Bond Home motorized shade (Bond device type MS) over the vendor's published local HTTP API (github.com/bondhome/api-v2). It opens, closes, stops (Hold), and recalls a preset, and it sets an exact position where the shade reports one. State arrives by BPUP push over UDP with a hash-gated HTTP poll as the fallback, published to Control4 as POSITION, STATE, and DEVICE_ONLINE. Where the generic Bond driver can only fire a button press, this driver models the shade as a shade — position, motion, and honest state.

The Bond local API is unencrypted HTTP on port 80, and BPUP push is unauthenticated UDP on port 30007. Physical LAN access is the whole security model — keep the Bond and the controller on a trusted, segmented network and never port-forward either. The driver refuses any non-LAN Bond address unless Allow WAN Bond is explicitly set to Yes.
Ready for controlled commissioning. The package, Lua 5.1 runtime, HTTP + BPUP transports, the assumed-position CourseTime model, capability discovery, the license gate, and this documentation pass automated QA in the Control4 API simulator. A qualified dealer must still complete a fresh install and an observed open/close/position test against a real Bond and shade on the target controller — nothing here has been bench-tested on hardware.

What you get

  • Open, Close, Stop (Hold), and Set Preset over PUT /v2/devices/<id>/actions/<Action>
  • Set Position (0-100) as a real SetPosition action where the shade reports position
  • An honest CourseTime assumed-position model for RF shades that report nothing back
  • Toggle Open where the shade's action list reports that capability
  • BPUP push state (UDP 30007) with automatic hash-gated poll fallback
  • POSITION, POSITION_ASSUMED, STATE, and DEVICE_ONLINE variables for programming
  • Transition-only Motion Started/Stopped, Shade Opened/Closed, Went Online/Offline events
  • LAN-only destination guard, a Bond token that is never logged, and MAC-locked IntegrateIT licensing on every actuating path

2 The position contract

A Bond MS shade reports position only where the bridge supports it — a native-position motor, or a Bond Bridge Pro configured with the shade's CourseTime travel. This driver learns which case it is from the shade's own action list (GET /v2/devices/<id>) and is deliberately honest about the difference:

  • Position-reporting shade (SetPosition in the action list): Set Position sends a real SetPosition action, POSITION is device-reported, and POSITION_ASSUMED is 0.
  • Assumed-position shade (no SetPosition): position is dead-reckoned from the Course Time property, labeled assumed (POSITION_ASSUMED = 1), and Unknown at boot. This is the same one-way honesty register the Somfy URTSI II and ESI R2D7 drivers use.
  • On an assumed shade a partial Set Position needs a known endpoint first — send Open or Close to establish one; until then a partial move is refused, because dead-reckoning from an unknown start would be fiction. A mid-travel Stop returns the assumed position to Unknown for the same reason: the driver cannot know where a moving shade halted.
  • A shade moved by a Bond remote or the Bond app is reflected by BPUP push when subscribed; an assumed shade with no push cannot report a remote move at all until the next driver command. Anything claiming otherwise would be faking it.

3 Wire and commission

  1. Enable the Bond's local API and copy its token: Bond Home app → device Settings → Advanced Settings → Local Token. Note the Bond's IP and reserve it in DHCP.
  2. Add IntegrateIT Bond Shade to the shade's room. Enter Bond IP Address and Bond Token (the token is password-typed and never logged).
  3. Run List Bond Shades from the Actions tab to enumerate the Bond's type-MS devices, then paste the target id into Device ID.
  4. Run Test Connection — it confirms the shade answers and learns whether it reports position (shown in Position Support).
  5. If Position Support reads Assumed (CourseTime), measure the full open-to-close travel with a stopwatch and set Course Time (s) to it.
  6. Leave State Feedback on Auto (BPUP push with poll fallback), then run Open Shade / Close Shade and watch the shade react and STATE follow.
Bond publishes this local API specifically so control systems and installers can integrate offline; this driver implements that published contract with original IntegrateIT engineering.

4 Protocol on the wire

Control is PUT /v2/devices/<id>/actions/<Action> with body {} or {"argument":N}, authenticated by the BOND-Token header. Actions used: Open, Close, Hold (stop), Preset, SetPosition (argument 0-100), ToggleOpen. A 401 means a bad token; a 4xx/5xx is surfaced in Status and, for a transient 429/5xx, is not retried — no retry storms.

State feedback has two paths, and Status names the active one:

  • BPUP push — the driver opens a UDP socket to the Bond on port 30007 and sends a keep-alive newline on connect and every 60 seconds. The Bond pushes frames like {"B":<serial>,"t":"devices/<id>/state","s":200,"b":{"_":<hash>,"open":1,"position":40}}. Frames are parsed tolerantly across arbitrary datagram boundaries and junk; only a frame addressed to this shade's id updates state. If no push arrives for 125 seconds, the subscription is treated as stale and (in Auto) polling resumes.
  • Hash-gated poll — GET /v2/devices/<id>/state carries a _ change hash; the driver applies a state only when the hash changed, so an unchanged shade costs nothing and fires no duplicate events.

Three recipes using this driver's real surfaces:

  • Goodnight → run Close Shade; hang the rest of the scene off Shade Closed, which fires on the transition to the closed endpoint, not on a repeat command.
  • Morning half-light → on a position-reporting shade, set Set Position to 50 and run Set Position; on an assumed shade, first Open Shade (to establish the open endpoint) then Set Position 50, and the driver drives and Holds for the computed fraction of Course Time.
  • Away check → branch on DEVICE_ONLINE; a Went Offline event means the Bond stopped answering both push and poll, which is worth a notification.

Every actuating command is gated by the license: under Strict enforcement an unlicensed controller sends nothing; the default Lenient mode allows commissioning while License Status carries the nag. The gate is re-checked at the wire-write moment — the delayed Hold that ends an assumed Set Position re-checks the license before it transmits, so if enforcement flips to Strict mid-travel the Hold is dropped and the position is honestly reported Unknown rather than a faked target.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation of Bond's published local HTTP API (the API exists precisely so control systems and installers can integrate offline). It does not bundle another vendor's runtime, source code, brand assets, trial system, or license. Bond, Bond Bridge, and Smart by Bond are trademarks of Olibra LLC; IntegrateIT is not affiliated with Olibra, and this driver is not a Bond product. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

The driver talks only to your Bond on the LAN and to nowhere else. The Bond token lives only in the BOND-Token request header and is never written to the log or the Print Configuration output; there are no cloud credentials because the driver never leaves the LAN. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks all shade control until the Ops Portal has minted and validated a key for that controller. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

V Version history

v0.1.1 current2026-07-26
  • Fix (P0, wire fidelity): Bond's `position` percentage is inverted versus this driver's Control4 convention — the api-v2 Position feature documents it verbatim as "0 = open, 100 = closed", while the driver (and the `open` flag) use 0 = closed / 100 = open. The device-reported/Bridge Pro path read and wrote the raw Bond value, so a fully open shade (`position:0`) was published as closed (firing Shade Closed), the on-frame `position` and `open` fields contradicted each other, and "Set Position 80%" transmitted `argument:80` = ~80% closed, moving the shade the wrong way. Both the state read (`100 - p`) and the SetPosition argument (`100 - target`) are now flipped on the wire. The `open`-flag and assumed-CourseTime paths were already correct and are unchanged. Added regression cases proving Bond position 0 = fully open (fires Shade Opened) and a 35%-open target ships as argument 65.
