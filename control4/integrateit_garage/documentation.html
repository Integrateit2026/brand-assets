1 Start here

IntegrateIT Garage turns standard Control4 relay outputs and contact sensors into a supervised garage-door experience. It drives a one-button operator, separate open and close inputs, or a three-relay open/close/stop topology, and reads zero, one, or two position contacts for supervision. Navigator shows live closed, open, opening, closing, partially-open, stopped, failed, and unknown states.

Ready for controlled commissioning. The package, Lua 5.1 runtime, Control4 surfaces, relay modes, state engine, timers, license gates, persistence, and documentation pass automated QA. A qualified dealer must still complete a fresh install and observed door-cycle test on the target controller, relay hardware, operator, and safety sensors.

What you get

  • One, two, or three relay-output topologies
  • Momentary, Trigger, Maintained, and Press and Hold relay modes
  • Zero, one, or two position contacts with independent polarity and debounce
  • Travel supervision, endpoint failures, contact conflict detection, and external-motion inference
  • Pre-close warning delay, left-open events with bounded repeats, and safe command blocking
  • Composer events, programming variables, button links, diagnostics, persistence, and relay-safe Test Mode
  • Eight live Navigator state icons in the IntegrateIT design system

2 Safety boundary

A moving garage door can injure people, pets, and property. Keep the door in view during commissioning. Never defeat the operator's photo eyes, force sensing, entrapment protection, manual release, or listed safety controls. This driver does not replace any operator safety function.

The relay output is only a dry-contact command to the installed operator. Before enabling control:

  1. Prove the operator and all safety devices using the manufacturer's wall control.
  2. Confirm every Control4 relay is electrically isolated and rated for the operator input.
  3. Set Integration Control to Disabled while wiring or changing relay topology.
  4. Use Test Mode to validate programming and Navigator states without energizing any relay.
  5. Re-enable control only when the work area is clear and the installer can observe a complete cycle.

For an unattended close workflow, use the operator's approved warning and safety accessories. The driver's Close Warning Delay (s) is an automation event and delay, not an audible or visual safety device by itself.

3 Wire and commission

  1. Add the garage button to a room's Navigator menu, set it Visible, and Refresh Navigators before testing. The button does not appear on a touch screen or in the app until it is made visible and Navigators are refreshed — do this first so every later step can be confirmed from a real Navigator.
  2. Add IntegrateIT Garage to the room containing the garage door.
  3. Set Integration Control to Disabled.
  4. Bind relay outputs using the connection map below. Set Number of Relays and Relay Mode to match the operator interface exactly.
  5. Bind zero, one, or two contacts. Set Number of Contact Sensors, polarity, and debounce. The default is zero contacts (relay-only, the most common install); never count an unbound contact.
  6. Run Validate Configuration. Garage Status should read Configuration ready and Last Error should read None.
  7. Turn Test Mode on. Run every simulation and confirm project programming, announcements, lighting, and Navigator icons without relay movement.
  8. Turn Test Mode off, enable Integration Control, clear the work area, and observe open, stop, close, obstruction, and feedback behavior. Confirm expected travel times before handoff. On a relay-only install, tap the Navigator button and confirm each tap sends one momentary pulse.
Start with a 500 ms momentary pulse unless the operator documentation requires a different input. A longer pulse is not a substitute for correct wiring.

With two or three relay outputs, the driver releases the opposite direction before energizing the requested direction. With one relay, Momentary, Trigger, and Press and Hold treat the output as the operator's step-by-step button. One-relay Maintained mode energizes for Open and releases for Close.

5 Choose the relay mode

ModeOutput behaviorTypical use
MomentaryActive command, then release after Pulse Length (ms)Most wall-button and dry-contact inputs
TriggerControl4 TRIGGER with exact TIME in millisecondsNative Control4 relay pulse
MaintainedHolds or releases the direction outputOperators that explicitly require maintained contacts
Press and HoldActive command, then release after 1 to 120 secondsInterfaces that require an extended button press

Invert Relay Logic swaps the active and released relay commands. Trigger mode cannot be inverted because native TRIGGER owns the pulse behavior; validation blocks that combination before any output.

Stop capability depends on topology:

  • Three relays use the dedicated Stop output.
  • One step-by-step relay sends a pulse only when motion is confirmed.
  • Maintained topologies release active direction outputs.
  • Two momentary direction relays cannot produce a physical Stop. The command is blocked and explains that a third relay is required.

6 Understand contact feedback

Each contact has independent active polarity. Contact Closed means the electrical circuit is active when closed; Contact Open means the electrical circuit is active when open. Debounce requires the new circuit state to remain stable for the configured interval.

Closed contactOpened contactSupervised state
ActiveInactiveClosed
InactiveActiveOpen
InactiveInactiveOpening or Closing when a target exists; otherwise Partially Open
ActiveActiveSensor Conflict

With one contact, Closed is verified and Open is estimated after the expected travel time. With no contacts (the default relay-only install), supervised state stays Unknown and both endpoints are inferred from the travel timers rather than measured: a commanded open or close estimates its endpoint after the expected travel time — and the driver labels that an estimate, never a measurement, because it never reports a door position it did not observe — and a Navigator tap sends a blind momentary pulse via Unknown State Toggle Action. With two contacts, a target contact that reports yet never reaches its active state before the travel timeout produces Failed to Open or Failed to Close. Contact feedback can also infer that movement started from a wall button or another integration.

STATE_CLOSED and STATE_OPENED initialize state without firing automation events. Later contact transitions fire the appropriate state events after debounce.

Contact feedback is hardware-unverified. It depends on a bound Control4 contact-sensor driver delivering CLOSED/OPENED/STATE_* to this driver on a type-1 consumer binding (4 or 5). The automated simulation injects those messages directly, so a passing simulation does not by itself prove that a given stock contact driver delivers state this way on your controller. Before you rely on any contact-driven state, event, or automation, bench-verify the actual delivery on the target hardware. If a configured contact never reports, the driver falls back to travel-time estimation and records a "not reporting" note rather than declaring a movement failure — but it will not observe the real door. The zero-contact, relay-only topology is the default and the most common install; it needs no contact feedback at all.

7 Program the project

Use specific state events for automation and Garage State Changed when one program should respond to every transition. Garage Command Blocked captures configuration, integration, Test Mode, and supported-topology blocks. Strict unlicensed control is intentionally silent; read License Status for that condition.

Use Navigator Press Action to choose Toggle, Open, Close, Stop, or Disabled. Toggle opens from Closed or Closing and closes from Open, Opening, Partially Open, or Stopped. In Unknown, failed, or conflicting states, Unknown State Toggle Action decides what a tap does. It defaults to Pulse Relay, which sends one momentary pulse on the primary output — the correct behavior for a one-relay opener whose supervised state is permanently Unknown on a relay-only install, so a Navigator tap is never dead. Select Stop instead for multi-relay or track systems that must not guess a direction, or Open/Close to force a specific direction.

Three starting points, wired with this driver's own events, commands, and variables:

  • When Garage Door Left Open fires → announce on the kitchen touch screen and turn on the driveway lights; read Left Open Notices to escalate only on a repeat.
  • When Garage Door Opened fires and IS_MOVING is false → run a "someone's home" scene once the door has settled.
  • On a "Goodnight" event → call Close Garage Door. With Close Warning Delay (s) set, Garage Close Warning fires first, so a chime or light can run before the door actually moves.

8 Supervision and alerts

Expected Open Time (s) and Expected Close Time (s) supervise every commanded or inferred movement. An endpoint contact ends supervision immediately. At timeout, the driver either estimates an unobserved endpoint or fires a failure event when the configured contacts should have proved it.

Left Open Time (mins) starts when the state leaves Closed. Set it to zero to disable. Left Open Repeat Count adds a bounded number of notices at the same interval. Returning to Closed cancels the timer and resets the count.

Close Warning Delay (s) fires Garage Close Warning, waits the configured seconds, then issues the close output. Open, Stop, Integration disable, Test Mode, or a new close request cancels or replaces a pending warning. The door does not enter Closing until the relay command is actually sent.

9 Test without moving the door

  1. Set Test Mode to On. Garage Status confirms that every physical relay output is blocked.
  2. Run Simulate Door Closed, Simulate Door Open, Simulate Door Partially Open, and Simulate Sensor Conflict.
  3. Confirm the matching Navigator icon, variables, events, announcements, and customer-facing automation.
  4. Run Reset Garage State to return to Unknown and clear simulated contacts, warnings, and command history.
  5. Set Test Mode to Off before observed physical commissioning.

Simulations require Test Mode. Under Strict licensing they also require a validated controller license. Contact feedback remains active during Test Mode so wiring can be checked without allowing a relay command.

12 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation built on documented Control4 relay, contact-sensor, button-link, and UI-button contracts. It does not bundle another vendor's encrypted runtime, source code, brand assets, trial system, or license. Driver engineering, Control4 integration, documentation, visual design, QA, licensing, updates, and support are provided by IntegrateIT.

The garage runtime does not send garage state, customer identity, project identity, or Control4 credentials to a device vendor. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

Lenient mode allows commissioning without an activated key and keeps the License Status visible. Strict mode blocks all driver control until the Ops Portal has minted and validated a key for that controller. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.

Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

D Diagnostics and self-test

Every IntegrateIT driver carries two read-only Actions for the field. Run Diagnostics prints a report of what the driver has already observed — version and Lua runtime, license mode and cached activation, update channel and any staged build, every armed timer with its interval, which dealer-supplied properties are still empty, and the last few Status messages. It probes nothing, sends nothing, and changes nothing, so it is safe on a live job. Run Self-Test checks the shared layer itself — string and URL encoding, version comparison, the non-finite number guard, the timer registry, and the persistence store — and ends with SELF-TEST PASS or a per-check failure. It stays local: no network, no device commands.

Neither Action is license gated, on purpose: you reach for them when a site is broken, and the license may be the broken thing. Values are never printed — a key or secret is reported only as set or NOT SET, so the output is safe to paste into a support ticket. Both print to the Lua output window (Composer → the driver's Lua tab).
