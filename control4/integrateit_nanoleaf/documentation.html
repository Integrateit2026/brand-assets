1 Start here

IntegrateIT Nanoleaf brings one Nanoleaf light — Light Panels, Canvas, Shapes, Elements, or Lines — into Control4 over the vendor's local Open API (the documented on-device REST API rooted at /api/v1). There is no cloud hop: the driver talks straight to the device on the LAN, so control is fast and keeps working when the internet is down. Once it is in a project you can drive power, brightness, hue/saturation color, white color temperature, and effect selection by name from keypads, room actions, and scenes, while a background poll reads the device's own state back into Control4 variables and events.

The Open API is plain, unencrypted HTTP, and the auth token rides in the URL path. Keep the device on a trusted LAN segment. The driver refuses a non-LAN destination unless Allow WAN Nanoleaf is explicitly set to Yes.
Ready for controlled commissioning. The package, Lua 5.1 runtime, pairing flow, Open API framing, state parsing, reachability model, LAN guard, license gate, persistence, and documentation pass automated QA against the Control4 API simulator (hardwareStatus: simulation-verified). A qualified dealer must still complete a fresh install and an observed light test against a real Nanoleaf device on the target controller — this release is not bench-tested on physical hardware.

What you get

  • Power On, Power Off, Toggle Power, Set Brightness (1-100), Set Color (Hue 0-360 + Saturation 0-100), and Set Color Temperature (1200-6500 K white)
  • Select Effect by name, with a List Effects action that enumerates every effect on the device
  • Documented pairing built in: hold the power button, run Pair (Claim Token), and the driver claims and stores the auth token itself
  • A configurable state poll that publishes POWER, BRIGHTNESS, HUE, SAT, CT, EFFECT, and DEVICE_ONLINE
  • Turned On / Off, Effect Changed, and Went Online / Offline events for Composer programming
  • LAN-only destination guard, an auth token that is never written to the log, and MAC-locked IntegrateIT licensing
  • One driver instance per device — add another instance for each Nanoleaf

2 The feedback contract

This driver reports only what the device tells it, and it tells you plainly how it knows:

  • State is polled, not pushed. The driver reads the all-in-one GET /api/v1/<token>/ on the Poll Interval (default 5 s). A change made from the Nanoleaf app or a physical button appears on the *next* poll, not instantly — anything claiming instant feedback would be faking it. Refresh State polls immediately when you need it now.
  • Boot adoption is silent. The first poll after a (re)start adopts the device's current power and effect *without* firing Turned On/Off or Effect Changed — those fire only on a real change from a value already known. A controller restart wipes what the driver remembered: Device Status reads Unknown, POWER returns to its 0 default and EFFECT to empty, and the first poll re-primes them silently.
  • Reachability is truthful. Any HTTP response — even a 401 — proves the device is alive and fires Went Online; no response at all (code 0) fires Went Offline and sets DEVICE_ONLINE false. A control write is a reachability check too: a device that dies mid-command flips to Offline immediately instead of waiting for the next poll.
  • Toggle is an assumption when state is unknown. The Open API has no toggle verb, so Toggle Power inverts the last polled power. If power has never been observed it turns the light on (documented default) — a Toggle from Unknown is an assumption, not an observation.
  • The driver never invents state values: BRIGHTNESS, HUE, SAT, and CT are the device's own reported numbers, read from the documented {"value":N} shape regardless of JSON key order.

3 Wire and commission

  1. Find the Nanoleaf's IP address (router client list or the Nanoleaf app) and reserve it in your router's DHCP table so it never changes.
  2. Add IntegrateIT Nanoleaf to the device's room. Enter Nanoleaf IP Address. Leave Nanoleaf Port at 16021 for the panel line.
  3. Pair. Hold the device's power button ~5-7 s until the LED flashes, then run Pair (Claim Token) within 30 s. The driver POSTs the claim, stores the returned token in the password-typed Auth Token property, and starts polling. You never handle the token yourself.
  4. Run Test Connection — it prints the device's name, model, and firmware and confirms the stored token works.
  5. Run List Effects and paste one printed name verbatim into the Effect property — the driver sends it to the device exactly as typed.
  6. Wire the commands into Programming (see below); optionally react to the events or read the variables.
  7. Optionally enter a License Key. The default Lenient (recommended) mode commissions without one.
  8. Prove it. Run Power On, or set Brightness and run Set Brightness — watch the light react and Device Status read Online — On, NN%.
One driver instance controls one Nanoleaf device. Add a second instance, with its own IP and its own pairing, for each additional Nanoleaf.

4 On the wire

Every request is plain JSON over HTTP to http://<ip>:<port>. The auth token is a path segment of every authenticated URL (/api/v1/<token>/…), which makes the URL itself a secret — so the transport never logs a URL, only the method and the sub-path *after* the token. Any body-carrying request declares Content-Type: application/json.

PurposeRequestBody / result
Claim token (pairing)POST /api/v1/new (no token)none → {"auth_token":"…"}
Poll state (paired)GET /api/v1/<token>/all-in-one device info + state
Reachability probe (unpaired)GET /api/v1/ (no token)any HTTP response = reachable
PowerPUT /api/v1/<token>/state{"on":{"value":true}} / {"on":{"value":false}}
BrightnessPUT /api/v1/<token>/state{"brightness":{"value":N}}
ColorPUT /api/v1/<token>/state{"hue":{"value":H},"sat":{"value":S}}
Color temperaturePUT /api/v1/<token>/state{"ct":{"value":K}}
EffectPUT /api/v1/<token>/effects{"select":"Name"}
List effectsGET /api/v1/<token>/effects/effectsListthe effect-name array

Replies the driver acts on: 200 on a read, any 2xx on a write (the state write answers 204); 401 on an authenticated call means the token was rejected (re-pair), while during pairing both 401 and 403 mean the pairing window is not open; code 0 is no response at all (Offline). After a successful write the driver schedules a fast follow-up poll (~400 ms) so published state catches up quickly — the write itself returns no state inline. An effect name is JSON-escaped before it goes on the wire, so a quote in the name can never break out of the payload.

Three ways these wire into Composer programming:

  • When your Movie scene runs → Select Effect. Set the Effect property to the effect name, then call Select Effect (or Set Color / Set Color Temperature) so one Control4 event drives the panels.
  • When Effect Changed fires → read EFFECT and announce it. Because the poll also sees changes made from the Nanoleaf app, Control4 reacts to what the panels actually show, not only to what it commanded.
  • When Went Offline fires → notify. DEVICE_ONLINE dropping to false means the panels left the network (moved IP, unplugged) — surface it before someone taps a dead keypad.

Control commands are gated by the license: under Strict enforcement an unlicensed controller writes nothing to the device — but polling, pairing, Test Connection, and List Effects stay live, because reading your own device is not a licensed feature. The default Lenient (recommended) mode allows commissioning while License Status carries the nag.

Device Status holds exactly one of: Unknown, No Nanoleaf IP set, Blocked: <reason>, Not paired — hold the power button, then run Pair (Claim Token), Offline (no response), Online — …, Token rejected (HTTP 401) — re-pair …, or Nanoleaf error (HTTP <code>).

Print Configuration writes IP:port, whether a token is set (its length only, never the value), the poll interval, the WAN flag, the color/brightness/CT settings, and the effect to the Lua output window. It never prints the token or the license key.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation of Nanoleaf's published local Open API. It does not bundle another vendor's runtime, source code, brand assets, trial system, or license. Nanoleaf and the Nanoleaf product names are trademarks of Nanoleaf; IntegrateIT is not affiliated with Nanoleaf, and this driver is not a Nanoleaf product. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

Nothing leaves the LAN. The driver talks only to the Nanoleaf device on your network — there is no cloud service, no vendor account, and no telemetry. Nanoleaf state, project identity, and Control4 credentials are never sent to a device vendor. The auth token lives in the password-typed Auth Token property; because the Open API carries it in the URL path, the driver never logs a URL — even in Debug Mode, lines show the method and the sub-path after the token only, and Print Configuration prints the token's length, not its value. The Open API has no login or encryption of its own, so LAN access is the whole security model of this device — one more reason to keep it on a trusted segment. Forget Token clears the stored token locally; it stays valid on the device until you revoke it via the vendor's Delete User endpoint or a device reset (this version does not send the device-side revoke).

Lenient (recommended) mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks all device control until the Ops Portal has minted and validated a key for this controller; polling and pairing continue either way. Installing this package does not itself mint or activate a controller license. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.
