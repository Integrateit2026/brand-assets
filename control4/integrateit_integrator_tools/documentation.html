1 Start here

IntegrateIT Integrator Tools is a headless dealer utility that puts the handful of maintenance operations that are one click from an unhappy client behind a deliberate two-step gate, and writes an evidence trail of every one. It exposes three project-labelled privileged tasks; each is armed by a Request and authorized by a separate Confirm, and — outside Immediate mode — only the Confirm fires the matching Control4 event your own programming acts on. Every request, supersession, expiry, denial, authorization, lock change and configuration change is appended to a persistent ring-buffer audit log on the controller, and — when you configure a webhook — POSTed to your own endpoint as JSON. It has no bindings and no Navigator tile.

The division of labour is the whole point: this driver authorizes and records, it does not act. It cannot restart a service, reset a room, or erase credentials — it holds no such capability by design. The destructive work lives in your Composer programming bound to *Task 1/2/3 Authorized*, where you can read it. Use the slots for the operations you never want performed by reflex: wiping a paired-device list, re-running a destructive sync, restarting services during business hours, resetting a room a homeowner finished configuring an hour ago.

The confirmation step is operational friction, not authentication. Anyone who can reach ComposerPro on this project can run the Actions; what the second step buys you is that the destructive click is never the *first* click, and that the log records who claimed it. Operator Name is dealer-entered free text recorded verbatim — attribution, not verified identity.
Simulator-verified, pending hardware acceptance. The package, Lua 5.1 runtime, all three confirmation regimes, the maintenance lock, the ring buffer and its reboot persistence, the webhook path, the license gate, and this documentation pass automated QA in the LuaJIT simulator. A qualified dealer must still install on the target controller and confirm — against real programming — that each Authorized event runs the intended work and that the webhook reaches the intended endpoint.

What you get

  • Three dealer-labelled privileged tasks (Task 1/2/3 Label), each authorized as its own Control4 event
  • Three confirmation regimes — Two-Step Confirm, Code Confirm (a one-time code printed to the Lua output window), and Immediate for unattended programming
  • A bounded confirmation window (10–900 s) that expires on its own schedule so an armed request never waits indefinitely
  • Maintenance Lock that refuses every privileged request until a dealer releases it, and survives reboots
  • A persistent ring-buffer audit log (5–200 entries) recording requests, authorizations, denials, expiries, lock and config changes — survives reboots and driver updates
  • Optional audit webhook: every entry POSTs as JSON, plus an on-demand full-log Export
  • MAC-locked IntegrateIT licensing on every privileged path; read-only diagnostics stay available unlicensed

2 The authorization contract

This is a gate and a ledger. It is honest about the three things it deliberately cannot do:

  • It never performs the task. Authorizing a slot fires *Task N Authorized* and writes an audit entry — nothing more. If no programming is bound to that event, authorizing produces a log line and an event and nothing else happens, which is exactly what an unprogrammed slot should do. The dangerous half of every operation stays in the project where you can read it.
  • It cannot authenticate. The confirmation step is friction, not identity. Operator Name is stamped verbatim on every entry because the driver records what the dealer claims — it does not verify it. Read the log as "who said they did this", not proof.
  • It cannot make the log durable by itself. The audit log lives in driver PersistData on this controller. It survives reboots and driver updates, but it is bounded by Audit Log Size and is lost if the driver is removed from the project — anyone with project access to remove and re-add the driver discards it. The webhook is the off-controller copy; configure it when you need durable retention.

Three rules protect the ledger, and none can be turned off:

  • Clearing the log is itself a privileged, confirmed operation and leaves a tombstone. Even in Immediate mode, Request Audit Log Clear is forced back to a two-step confirmation — a one-Action unconfirmed wipe of the accountability record is the one thing this driver must never allow. The clear writes a tombstone entry the instant it fires, so the log is never silently empty.
  • Weakening the gate is recorded, and never retroactive. Changing Confirmation Mode discards any pending request — one raised under one regime must not be completable under another — and writes the new mode to the log. Retargeting the Audit Webhook URL is logged too: the fact it changed, never the URL, which can carry a token.
  • An armed request never survives a reboot. The lock and the log persist; a pending request deliberately does not. Confirming across a restart would authorize work whose window — and whose operator — no longer exists.

3 Wire and commission

This is a headless driver — no bindings, no Navigator tile, no wiring.

  1. Add IntegrateIT Integrator Tools to a room.
  2. Label the three tasks for this project — Task 1 Label, Task 2 Label, Task 3 Label. The label appears in Pending Request, in the audit log, and in the webhook payload, so write it the way you want to read it a year later. Defaults are Restart System Services, Reset Room Configuration, Clear Stored Credentials.
  3. Choose Confirmation Mode: - Two-Step Confirm (default) — Request, then Confirm. The right answer for most projects. - Code Confirm — Request prints a one-time six-character code to the Lua output window; type it into Confirmation Code, then Confirm. The alphabet drops look-alike glyphs (no B/8, I/1, O/0, S/5, Z/2) and the code is matched case-insensitively, so a code read off the screen round-trips first time. A fresh code is drawn for every request and is not reproducible across driver loads. Use it when several people hold Composer access and the confirming person must have deliberately read the driver's own output. - Immediate (no confirm) — authorizes a task slot on request with no confirmation window armed, for unattended programming that needs the audit trail without a human in the loop. Still fully logged. Clearing the audit log ignores this and always confirms.
  4. Set Confirmation Window (sec) — 10–900, default 60 — how long an armed request stays confirmable. Editing it while a request is pending applies to the *next* request; a live window keeps its original schedule.
  5. Set Operator Name to whoever is working the project. It is stamped verbatim on every audit entry; left blank, entries record unattributed.
  6. Optional: set Audit Webhook URL to receive each entry as a JSON POST, and Audit Log Size (5–200, default 25) for on-controller depth.
  7. In Programming, react to Task 1/2/3 Authorized and perform the actual maintenance work there.
  8. Prove it: Request Task 1, watch Pending Request arm and *Authorization Requested* fire, then Confirm Pending Request and watch *Task 1 Authorized* fire, Last Authorization update, and Audit Entries climb. Run Print Audit Log to read the trail back.

4 The audit webhook payload

When Audit Webhook URL is set, every entry POSTs as JSON the moment it is written. The driver reads only the HTTP status code of the reply — a 2xx marks Audit Delivery delivered, anything else marks it failed and keeps the entry in the local log. Nothing in the response body is parsed, so a hostile or truncated reply cannot affect the controller.

Per-entry POST body:

{"driver":"integrateit_integrator_tools","version":"0.1.0",
 "controller":"<controller MAC>",
 "entry":{"at":"2026-07-20 14:03:11","event":"authorized",
          "detail":"Restart System Services","operator":"Dana"}}

Export Audit Log posts the whole log as one document with exported_at, count, and an entries array of that same entry shape; with no URL set it prints a note to the Lua output window and posts nothing. Every dealer-entered string (labels, operator, detail) is escaped before it enters the JSON, so a stray quote cannot corrupt the payload. Delivery is fire-and-forget: a failed POST is reported in Audit Delivery, not queued or retried — Export Audit Log re-sends the whole log on demand.

The driver is all events and variables — there is no Navigator surface to program against. Bind the real work to the per-task events; use the lifecycle events to track state.

Recipes:

  • Restart services on a confirmed request — On *Task 1 Authorized*, run your service-restart macro. The Request/Confirm pair guarantees the restart was a deliberate two-step act, and the log names who claimed it.
  • Notify when a request is armed — On *Authorization Requested*, send a push or flash a keypad LED so a second person knows a privileged task is on the clock.
  • Track pending state without sticking — Latch a boolean on *Authorization Requested* and release it on *Authorization Cleared* and each *Task N Authorized*. Because a three-wrong-codes discard fires *Authorization Cleared* (not only *Denied*), the latch never gets stuck open.

Every privileged path is license-gated: under Strict enforcement an unlicensed controller arms nothing, authorizes nothing, and cannot move the lock. Lenient mode allows commissioning with the License Status nag.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT utility. It bundles no other vendor's runtime, source, brand, trial, or license — it authorizes and records maintenance work you program yourself, and drives no third-party device or cloud.

Nothing leaves the controller unless you configure the audit webhook. When you do, each audit entry — timestamp, event, the dealer-entered task label and operator name, the driver slug and version, and the controller MAC — POSTs as JSON to the endpoint you chose and nowhere else. The Audit Webhook URL can carry a token, so it is deliberately never written to the audit log and never printed by any diagnostic; the log records only that the webhook was set, changed, or cleared. There are no device passwords or vendor credentials in this driver. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks every privileged path — requests, confirmations, lock changes, audit clears, exports — until the Ops Portal has minted and validated a key for this controller; the read-only diagnostics (Print Audit Log, Print Configuration) stay available either way so an unlicensed controller can still be inspected. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means

Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

v0.1.1 current2026-07-26
  • Documentation rebuilt to the IntegrateIT commissioning-guide standard: uniform sections, honest contracts, verified claim-by-claim against the code.
  • **Confirmation codes are now seeded per driver load.** Lua 5.1 starts `math.random` from a fixed sequence unless seeded, so the "one-time" code was identical on every controller and every reload — guessable without ever seeing one. Seeded from wall clock + process clock + controller MAC + a persisted nonce that bumps each boot, so two reloads inside the same second still diverge.
  • **Immediate mode can no longer clear the audit log unconfirmed.** Immediate applies to the three task slots only; `Request Audit Log Clear` always arms a Two-Step confirmation. A one-Action unconfirmed wipe of the accountability record was the worst thing this driver could do.
  • **Discarding a request after three wrong codes now fires `Authorization Cleared`.** It previously fired only `Authorization Denied`, leaving programming that latches pending on Requested/Cleared stuck on the one path that discards a live request.
  • **Confirmation-mode and audit-webhook changes are now audited.** Weakening the confirmation regime, or retargeting the audit egress off this controller, are exactly what the trail exists to name. The webhook URL itself is not logged — it can carry a token — only that it was set, changed, or cleared.
  • Catalog honesty: Immediate mode's removal of the confirmation step for task slots, and the fact that the local log dies with the driver, are now stated in `limitations`.
