1 Start here

IntegrateIT Gemini Assistant puts Google Gemini answers inside Control4 programming. There is no device to find or wire: the driver opens outbound HTTPS (TCP 443) from the controller to generativelanguage.googleapis.com and calls the official Gemini API — the public v1beta unary generateContent endpoint documented at ai.google.dev/api. Set the Prompt property from any programming event, fire Ask Gemini, and the model's answer lands in the RESPONSE variable with a Response Received event, ready to route to an announcement, a notification, a touch-screen field, or on to another driver.

This is a paid cloud service, not a device. Every Ask is a real, billable call to Google against the customer's own Gemini API key, and the answer is generated by Google's models — it can be wrong, incomplete, or blocked by Google's safety filters. Never wire a life-safety or security decision to a generated answer.
Ready for controlled commissioning. The package, Lua 5.1 runtime, request framing, JSON escaping both ways, the bounded RESPONSE variable, the timeout + stale-response guard, the busy / rate guard, the safety-block and token-cap handling, key redaction, license semantics, timer hygiene, and this documentation all pass automated QA against the Control4 API simulator with a modeled Gemini endpoint. A qualified dealer must still run a fresh install and an observed Ask against the live Gemini service, on the target controller, with a real key — the live service is not attached to this release-candidate.

What you get

  • One Ask Gemini command that sends the Prompt property to the configured model and publishes the answer to the RESPONSE variable
  • Bring-your-own-key: the customer's own Gemini API key from Google AI Studio, sent only in the x-goog-api-key request header — never in a URL, never in a variable, never in any log line
  • An optional System Instruction that shapes every answer (persona, language, length, tone)
  • A Max Response Tokens cap that bounds answer length and per-request spend, with an honest Response Truncated event when the cap cuts an answer off
  • Response Received, Request Failed, and Response Truncated events, plus a redacted Last Result that names every failure reason
  • A driver-side timeout with a stale-response guard, and a busy / Min Request Interval rate guard so a misfiring programming loop can never flood the API or run up the bill
  • A Test API Key action that proves the key, model, and egress with no tokens consumed

2 Key, data, and cost

This driver is honest about the fact that it is a thin, safe pipe to someone else's paid cloud. Three facts govern it:

  • The key is the customer's. Google's API Terms require the account holder to bring their own key, so Gemini API Key is a password property the customer fills from their own Google AI Studio account. IntegrateIT embeds no key, proxies nothing, and shares nothing. The key travels only in the x-goog-api-key header — it is never placed in the URL, never written to a variable, and never printed, not even with Debug Mode → Print on. Diagnostics show only non-sensitive fields — the model, request/response sizes, and HTTP status — never the key, the prompt, or the answer.
  • Prompt data leaves the LAN. When you Ask, the Prompt and, if set, the System Instruction are sent to Google under the customer's key, and Google returns the answer. That is the whole point of a cloud model, but it means anything you put in the prompt is disclosed to Google under the customer's account — treat it accordingly and keep private data out of prompts you would not send to Google.
  • The customer pays, and the driver caps the bleed. Every Ask is billed to the customer's own Google account at Google's per-token pricing. The driver cannot see or set that price, but it bounds exposure: one request runs at a time, an Ask inside the Min Request Interval window is refused locally, and Max Response Tokens caps output cost per call. Set a real ceiling in the Google Cloud console — the driver's guards stop runaway loops, not a mispriced month.

An answer that Google cut off at the token cap, and a prompt or answer Google blocked, are both surfaced as exactly what they are (see On the wire and Troubleshoot), never dressed up as a clean success.

3 Wire and commission

  1. In Google AI Studio (aistudio.google.com), under the customer's own Google account, create an API key. For production, enable billing on the underlying Google Cloud project — Google may use free-tier traffic to improve its models, so a paid-tier key is the right choice for a customer home.
  2. Add IntegrateIT Gemini Assistant to any room. Paste the key into Gemini API Key (a password property).
  3. Leave Model at gemini-2.5-flash or set the model code you intend to use. Only letters, digits, dots, and dashes are accepted — anything else is refused before any request, so a stray slash or colon can never reach the URL.
  4. Run the Test API Key action. It GETs the model's metadata with the key in the header and prints OK — key accepted; model … is available. on success, consuming no tokens. A failure prints the exact reason (rejected key, model not found, or no network).
  5. Optionally set a System Instruction — a standing instruction sent with every request ("Answer in one short sentence", "Reply in Spanish", a persona). Tune Max Response Tokens to cap answer length and per-request spend.
  6. From programming, write the question into the Prompt property, then fire the Ask Gemini command. When Response Received fires, read the answer from the RESPONSE variable; Last Response shows a short preview and Last Result reads OK (…).
There is no prompt parameter on the command — set the Prompt property first, then fire Ask Gemini. An Ask fired with no key, a malformed model, or an empty prompt fails locally with a Request Failed event and makes no call at all. To prove a full round-trip during commissioning without wiring any programming, set Prompt, run the Ask Gemini Now action from the Actions tab, and watch Last Result turn OK (…).

4 On the wire

Turn on Debug Mode → Print to watch each request in the Lua output window. The log lines carry the model, the HTTP status code, request and response byte counts, and the reason for any local refusal — never the key, the prompt, or the answer.

Ask (POST):

POST https://generativelanguage.googleapis.com/v1beta/models/<model>:generateContent
x-goog-api-key: <the customer's key>
Content-Type: application/json

{"contents":[{"role":"user","parts":[{"text":"<prompt>"}]}],
 "systemInstruction":{"parts":[{"text":"<system>"}]},
 "generationConfig":{"maxOutputTokens":<N>}}

The systemInstruction block is omitted entirely when System Instruction is blank. Any quote, backslash, or control character in the prompt or instruction is JSON-escaped, so any text is a valid request.

Response shapeDriver reading
200, text in candidates[].content.parts[].textAnswer published to RESPONSE (multi-part answers concatenate in order); Response Received fires
200, finishReason: "MAX_TOKENS" with textAnswer published, Response Truncated fires alongside Response Received; Last Result adds cut by token cap
200, finishReason: "MAX_TOKENS" with no textA thinking model spent its whole budget before any visible text — Request Failed, Last Result names the Max Response Tokens cap to raise
200, promptFeedback.blockReason and no candidatesPrompt-level safety block — Request Failed, blocked by safety filter (<reason>)
200, candidate finishReason SAFETY / RECITATION / BLOCKLIST / PROHIBITED_CONTENT / SPII / IMAGE_SAFETY, no partsOutput-level safety block — Request Failed, blocked by safety filter (<reason>) (never a bland "empty response")
non-2xx {"error":{"code","message","status"}}Request Failed, HTTP <code>: <message> (message clipped to one line)
transport failure (code 0)Request Failed, no response (network error)

Test API Key GETs …/v1beta/models/<model> with the same header and reads the returned displayName — a read-only check that proves the key, model, and egress without consuming tokens.

Guards on every Ask: one request is in flight at a time; a second Ask while one is running fails locally with Failed: busy (previous request still running). The Min Request Interval quiet window runs from request start and refuses an Ask inside it with Failed: rate limited (Min Request Interval). The Timeout (s) timer fails a request that never completes, and a sequence guard makes a late answer for that request a no-op — it never fires events out of order or overwrites a newer result.

Recipes, using this driver's actual names:

  • Voice/keypad Q&A — When a keypad button is pressed → set the Prompt property to your question and fire Ask Gemini. On Response Received → announce or TTS the RESPONSE variable.
  • Scheduled one-liner — A morning schedule fires → set System Instruction to "answer in one short sentence", set Prompt to "give today's weather for …", fire Ask Gemini → on Response Received, push RESPONSE to a touch-screen text field or a notification.
  • Handle the honest failures — On Request Failed → read Last Result and announce a fallback or log it. On Response Truncated → the answer is a partial; raise Max Response Tokens or add "answer briefly" to the System Instruction.

Ask is license-gated: under Strict enforcement an unlicensed controller sends nothing and fires no event (silent by design — read License Status). The read-only Test API Key and Print Configuration actions are never gated. The default Lenient mode allows commissioning while the license nag stays visible.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT clean-room driver built to Google's public Gemini API reference (ai.google.dev/api). It bundles no Google runtime, source, brand assets, key, or trial account. Google, Gemini, and Google AI Studio are trademarks of Google LLC; IntegrateIT is not affiliated with Google, and this driver is not a Google product. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

What leaves the controller is exactly what you Ask: the Prompt and optional System Instruction go to generativelanguage.googleapis.com under the customer's own API key, and Google returns the answer. Nothing is sent anywhere else. The key lives only in the Gemini API Key password property, travels only in the x-goog-api-key header, and is never written to a variable or the log — not even in Debug mode. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks the Ask command until the Ops Portal has minted and validated a key for this controller; the read-only Test API Key and Print Configuration actions continue either way. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.

Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.
