1 Start here

IntegrateIT Hebcal turns location-aware Jewish calendar data into dependable Control4 events, variables, and status. It loads a rolling 15-day calendar window, calculates sunset for the selected date, keeps the last successful result through a Director restart, and retries temporary failures without discarding good data.

Ready for controlled testing. The software, package, API contract, malformed-response handling, caching, and licensing paths pass automated QA. Complete a fresh-install test on the target Control4 OS before using timed events in a live project.

What you get

  • Candle Lighting, Early Candle Lighting, Sunset, Havdalah, and Late Havdalah events
  • Hebrew date, Parsha, holiday, Yom Tov, Shabbat, and Omer state
  • US ZIP code or worldwide GeoNames location support
  • Diaspora and Israel calendar schedules
  • Astronomical or fixed-minute Havdalah calculation
  • Offline cache, scheduled refresh, bounded retry, diagnostics, and safe test mode

2 Commission in five minutes

  1. Add IntegrateIT Hebcal to the project. No proxy connection is required.
  2. Choose Location Type. For a US project, enter a five-digit US ZIP Code. Elsewhere, enter a numeric GeoNames ID.
  3. Choose Diaspora Or Israel, then confirm Candle Lighting Offset and the Havdalah Method used by the household.
  4. Run Validate Configuration. Hebcal Status should read Configuration ready and Last Error should read None.
  5. Run Refresh Hebcal Data. Confirm Location, Time Zone, Hebrew Date, Sunset, and the next candle/Havdalah values before writing programming.
The controller clock must be correct. Hebcal timestamps include the configured location's UTC offset, and the driver converts that offset to an absolute instant. An incorrect controller clock will still fire events at the wrong real-world time.

3 How the calendar engine works

Each successful refresh makes two polite, cache-friendly HTTPS requests to Hebcal:

RequestPurposeCoverage
Jewish Calendar APIHebrew dates, holidays, Yom Tov, Omer, Parsha, candles, HavdalahSelected Date plus 14 days
Zmanim APISunset for the exact locationSelected Date

The driver refreshes after startup and then schedules the next normal refresh for 02:05 in controller-local time. If Hebcal or the network is unavailable, good cached data remains visible and retry delays progress through 1, 5, 15, and 60 minutes. A successful retry fires Calendar Recovered.

Timed events use the UTC offset inside Hebcal's ISO timestamp. This keeps Kansas City, Jerusalem, and other locations correct across daylight-saving changes and avoids assuming that the configured city always matches the controller timezone.

5 Test without waiting

  1. Set Test Mode to On.
  2. Enter a real Test Date in YYYY-MM-DD format.
  3. Run Refresh Hebcal Data and review the resulting Hebrew date, observance, Parsha, and zmanim.
  4. Run Simulate Candle Lighting, Simulate Sunset, or Simulate Havdalah.
  5. Watch the project programming execute and confirm the expected variables and events.
  6. Set Test Mode back to Off, then refresh again before handing off the project.

Simulation requires Test Mode. Under Strict licensing it also requires a validated controller license. Early Candle Lighting and Late Havdalah fire with their paired simulation when their configured offsets are greater than zero.

8 Accuracy, privacy, and attribution

Hebcal calculates candle lighting and zmanim from solar-position algorithms and the supplied location. Differences of a minute or two between published calendars can occur. Confirm local rabbinic practice for candle offsets, Havdalah method, Israel/Diaspora rules, elevation considerations, and any community-specific custom.

The driver sends the configured ZIP code or GeoNames ID, date range, and calculation options to Hebcal. It does not send customer names, project names, Control4 credentials, or the IntegrateIT license key to Hebcal.

Calendar content is provided by Hebcal.com under the Creative Commons Attribution 4.0 license. Driver engineering, Control4 integration, caching, licensing, updates, QA, and support are provided by IntegrateIT.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.
