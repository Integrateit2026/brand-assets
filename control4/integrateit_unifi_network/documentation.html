1 Start here

IntegrateIT UniFi Network brings the health of a UniFi deployment into Control4 over Ubiquiti's official Network Integration API — the local HTTPS interface the console itself publishes at /proxy/network/integration/v1 (developer.ui.com/network). No cloud hop, no reverse-engineered endpoints, no vendor-issued credential: the customer mints an API key on their own console and the driver presents it as the stateless X-API-KEY header. Once it is in a Control4 project, the driver reports controller reachability and Network application version, adopted-device counts with online/offline health events, and the presence of up to three named clients — and performs exactly one write: power-cycling a PoE switch port to reboot a stuck camera, AP, or doorbell.

UniFi consoles present a self-signed certificate. With TLS Verification = Off (accept self-signed) (the default) the driver disables certificate verification on the Control4 HTTPS transport — that is what makes a self-signed console reachable, and it is the standard posture for a LAN appliance, but it means the connection is not authenticated by certificate. Keep the console and controller on trusted LAN segments. The strict alternative is TLS Verification = Full (require trusted cert) with a certificate the controller OS trusts. This TLS behavior is verified on hardware — the offline simulator does not model certificates.
Ready for controlled commissioning. The package, Lua runtime, Integration API framing, health and presence polling, pagination safety, the PoE write's guards, the license gate, and this documentation pass automated QA in the Control4 API simulator. A qualified dealer must still complete a fresh install and observe real reachability, device-health, presence, and PoE behavior against a physical UniFi console and controller — certificate handling in particular is a hardware-acceptance item. This driver has not been bench-tested on hardware.

What you get

  • Controller reachability and Network application version from GET /info, with Controller Went Online / Went Offline events and a CONTROLLER_ONLINE variable
  • Site device health — DEVICES_TOTAL / DEVICES_ONLINE / DEVICES_OFFLINE counts — with UniFi Device Went Offline and All UniFi Devices Online edge events
  • Presence for up to three watched client MACs, each a CLIENT_n_ONLINE variable with Came Online / Went Offline events, debounced against brief Wi-Fi drops
  • One guarded control action, Power Cycle PoE Port — off by default, license-gated, and the only write this driver ever performs
  • Setup actions on the Actions tab: Test Connection, List Sites, List Devices, List Clients, Print Configuration
  • A LAN-only destination safeguard, and an API key that lives only in the request header and is never written to the log

2 The feedback contract

This driver reports what the console tells it and nothing more. State is polled, not pushed — the Integration API documents no push channel — so everything updates on the Poll Interval (s) (default 30 s), never instantly.

  • Reachability is owned by /info. Every cycle GET /info decides CONTROLLER_ONLINE; the heavier device and client polls only *confirm* reachability and never mark the console offline. Without that split, a console that answers /info but times out on the larger device list would flap Controller Went Online / Offline every poll.
  • Presence is asymmetric. A watched MAC seen on the clients page reads online immediately. Offline is debounced: the client must be absent for Offline After (polls) consecutive polls before Client n Went Offline fires, so a phone's Wi-Fi power-save nap does not flap your automation.
  • One page per poll, and the driver holds rather than guesses. Device and client scans read up to 200 entries (limit=200) — one page. On a site whose list exceeds one page, truncation is detected from the response envelope (offset + count < totalCount) and the driver refuses to invent state: a watched client absent from the fetched page is held at its last-known presence (never false-declared offline), and device-health change events are suppressed until a full page is scanned again. The deliberate trade-off on such large sites is that a watched client which *truly* leaves may not raise Went Offline until it once again fits inside a single page. A client found on the page is trusted present regardless of truncation.
  • Reachability announces itself; the counters adopt silently. The first /info answer after a driver start is a real transition, so it does fire Controller Went Online (or Controller Went Offline) — expect one on every driver reload. The offline-device count and each watched slot's presence are adopted from their first observation *without* an event, so no device-health or presence event phantom-fires at boot. Clearing a watched MAC drops its CLIENT_n_ONLINE to 0 and forgets its learned state.

3 Wire and commission

  1. On the customer's UniFi console, open the Network app → Settings → Control Plane → Integrations and generate an API key. The key inherits the permissions of the admin who creates it — a read-mostly admin is a good choice unless you intend to use the PoE action.
  2. Add IntegrateIT UniFi Network to the project. Enter Console IP Address (reserve it in DHCP), Console Port (443 on UniFi OS hardware, 11443 on UniFi OS Server), and paste the API Key.
  3. Run Test Connection from the Actions tab — on success it prints OK - Network application <version> and fills Controller Version.
  4. Run List Sites and paste the site's id into Site ID (most consoles have exactly one).
  5. Optionally set Watched Client 1..3 MAC (run List Clients to find MACs — colon, dash, or bare-hex forms all normalize) and tune Poll Interval (s) / Offline After (polls).
  6. For the PoE action only: run List Devices, paste the switch's id into PoE Switch Device ID, set PoE Port Number, and flip Enable PoE Power Cycle to Yes.
  7. Optionally enter a License Key — the driver runs in Lenient mode without one (see Ownership).

The install proves itself when Device Status reads Online — N/M devices up, and — if you set a watched MAC — its CLIENT_n_ONLINE variable tracks the real device coming and going.

API keys exist only on UniFi OS consoles (UDM / UDR / UCG / UX / UniFi OS Server). The legacy self-hosted Java controller has no Integration API and cannot be used, by Ubiquiti's design.

4 Watch it on the wire

Turn on Debug Mode = Print and every HTTP call the driver makes to the console prints to the Lua output window as method + path only — no host, no headers, no body. The X-API-KEY header carries the key and is never shown, so the log is safe to share. These are the only console endpoints the driver ever touches, all under /proxy/network/integration/v1 (the shared license and update check-ins go to the IntegrateIT services named in the reference below, never to the console):

Debug lineCallWhen
GET /infoController reachability + Network versionEvery poll; Test Connection
GET /sitesEnumerate site idsList Sites
GET /sites/<id>/devices?limit=200Device-health roll-upEvery poll (Site ID set); List Devices
GET /sites/<id>/clients?limit=200Watched-client presenceEvery poll (a MAC set); List Clients
POST .../interfaces/ports/<idx>/actionsbody {"action":"POWER_CYCLE"}Power Cycle PoE Port

A non-2xx reply is surfaced, never swallowed: 401 / 403 set Device Status to Auth failed (HTTP …) - check the API Key on any call. Any other code is reported by the call that made it — Test Connection prints FAILED: HTTP … and sets Status, and the PoE write sets Status to PoE cycle failed (HTTP …). A background poll that returns some other error leaves the last good Device Status standing rather than overwriting it with a transient, so check Debug Mode = Print when a poll misbehaves quietly. A dead transfer (code 0) is what marks the console offline — a bare-table OS response is normalized so it can never be misread as code 0 and pin a live console to offline. The legacy /api/s/<site>/… Controller API is community-reverse-engineered and is deliberately never called.

VariableTypeMeaning
CONTROLLER_ONLINEBOOLConsole reachable on the last /info poll

Three ways these wire into Composer programming:

  • When UniFi Device Went Offline fires → text me "an AP or switch just dropped". The health roll-up turns a whole rack's supervision into one event.
  • When Client 1 Went Offline fires and no other watched client is online → run an "everyone left" macro (arm, setback, lights off). Because offline is debounced and truncation-safe, the macro will not misfire on a brief Wi-Fi nap or a large-site page miss.
  • When Controller Went Offline fires → escalate. The gateway that runs the network going dark is worth a push notification of its own.
Power Cycle PoE Port literally cuts and restores power to whatever the port feeds. The powered device — camera, AP, doorbell — reboots and is offline for its full boot time. Never target a port that carries the console's own uplink or a device you cannot afford to drop, and think hard before wiring the action to an unattended trigger.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation of Ubiquiti's published UniFi Network Integration API (developer.ui.com/network). It bundles no Ubiquiti runtime, source code, brand assets, trial system, or license. UniFi and Ubiquiti are trademarks of Ubiquiti Inc.; IntegrateIT is not affiliated with Ubiquiti, and this driver is not a Ubiquiti product. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

Nothing leaves the LAN. The driver talks only to the console IP you configure, over local HTTPS, and a destination safeguard refuses a public or invalid address unless Allow Non-LAN Console is explicitly set to Yes. The API Key lives only in the X-API-KEY request header — it is never placed in a URL and never written to the Lua log, even with Debug on. No device data, customer identity, or project identity is sent to any vendor cloud; the shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

Lenient mode (the default) allows commissioning without an activated key and keeps License Status visible; polling and monitoring always run. Strict mode blocks the one control path — Power Cycle PoE Port — until the Ops Portal has minted and validated a key for that controller; reading health and presence is never gated. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.

Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.
