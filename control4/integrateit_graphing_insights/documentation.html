1 Start here

IntegrateIT Metrics & Insights turns one numeric value in a Control4 project — a temperature, a power draw, a humidity reading, a tank level, anything exposed as a device variable — into a bounded historical ledger with insight variables you can program against and a CSV or JSON export you can chart anywhere. It is headless: no Navigator tile, no bindings, one metric per instance.

The driver samples the value on a fixed interval (or on demand from programming) and keeps it in three fixed-capacity tiers that cascade into one another: each raw sample lands in the recent ring and folds into the open hourly bucket, and each sealed hour folds into a daily bucket. Every tier is a ring with a capacity you set, so the driver's memory — and the bytes it contributes to a project backup — are bounded by configuration rather than by how long the system has run. Nothing grows without a ceiling and nothing rescans history; the cost of a sample never changes. Bucket boundaries come from the controller's local calendar, not epoch arithmetic, which is what keeps a daylight-saving day a single day whether it ran 23, 24, or 25 hours.

Ready for controlled commissioning. The package, Lua 5.1 runtime, the three-tier cascade, local-calendar bucketing, ring eviction, the privacy and persistence modes, CSV/JSON export, the license gate, and this documentation pass automated simulation. This is a Release Candidate: a qualified dealer must still verify sampling, hour and day rollovers, retention wrap, and export against a real controller and a live source before relying on it. Nothing here is bench-tested on hardware.

What you get

  • Samples any Control4 device variable by device id and variable name, on a fixed interval or on demand via Record Sample Now
  • A three-tier bounded ledger: raw samples cascade into hourly buckets, sealed hours fold into daily buckets, each tier a fixed-capacity ring
  • Insight variables — METRIC_VALUE, METRIC_MIN, METRIC_MAX, METRIC_AVG, METRIC_TREND, METRIC_DELTA_1H, SAMPLE_COUNT, LAST_SAMPLE_AT
  • Events on new extremes, significant change, hour and day rollover, source loss, history clear, export, and retention wrap
  • Local-calendar bucket keys, so a DST day is still exactly one day
  • Privacy Mode that drops raw samples (Aggregates Only) or stops capture (Paused); Persist Across Reboot with a live Storage Estimate of the project-backup ceiling
  • CSV or JSON export to the Lua output window or an HTTP endpoint, capped at 500 rows and redacted to match Privacy Mode

2 The sampling contract

This driver measures; it never invents. What it did not sample, it does not know, and it says so rather than filling the gap:

  • Sampling is interval polling, not change subscription. The value is read on the Sample Interval you set — a spike between two reads is never seen. Shorten the interval if that matters, and accept the faster ring turnover that comes with it.
  • Programming can trigger a sample; it cannot hand the driver one. A configured source is the only way a value enters the ledger. Record Sample Now reads that source; with Source Device ID or Source Variable left blank it re-stamps the value already at the head of the ledger, and on a ledger that has never held one it records nothing and says so in Status.
  • Only numbers are recorded. A source variable that does not parse as a number — a thermostat mode name, an empty read — is treated as unavailable, and Source Unavailable fires once per outage, not once per poll.
  • The ledger is append-only. Only the open bucket can still absorb a value, so a sample stamped older than the newest hour the ledger already holds is refused rather than back-filed. In practice this only bites if the controller clock is stepped backward across an hour boundary (a large NTP correction); sampling resumes once the clock passes the previous frontier.
  • Aggregates Only and Paused keep no raw rows. With no per-sample rows by construction, Window Summary and the METRIC_MIN / METRIC_MAX / METRIC_AVG / METRIC_TREND variables describe the most recent hourly bucket, not a rolling window of the last N samples. That substitution is deliberate and labeled as what it is — it is not a live window.
  • The daily tier is folded from sealed hours, never from raw samples, so nothing is counted twice. The consequence: the hour in progress is not yet reflected in the day total. Run Seal Open Buckets first when you need it to be.
  • It renders no charts. The driver produces the numbers and the export; the picture belongs to whatever you feed it to.

3 Wire and commission

  1. Add IntegrateIT Metrics & Insights to a room. It is headless — no Navigator tile, no bindings.
  2. Set Metric Name (and optionally Metric Units, for example F, W, %) so exports and Status read like the thing being measured.
  3. Point it at a source. In Composer, find the device to track and note its device id and the variable name you want; put them in Source Device ID and Source Variable, spelled exactly as Composer shows it (for example CURRENT_TEMPERATURE). Both are required — with either left blank the driver polls nothing, treats that as deliberate rather than a fault (no Source Unavailable), and has no value to record.
  4. Choose a Sample Interval. Shorter intervals fill the recent ring faster — at 30 seconds a 240-sample ring covers two hours; at 15 minutes it covers 2.5 days.
  5. Size the three rings: Recent Samples Kept (12–1440), Hourly Buckets Kept (6–168, where 168 is one week), and Daily Buckets Kept (1–90, where 90 is one quarter). Watch Storage Estimate as you do — it reports the ceiling this configuration can ever reach in a project backup.
  6. Decide Privacy Mode and Persist Across Reboot. The defaults — Full History and Aggregates Only — keep raw samples in memory but persist only the bounded aggregates.
  7. Enter a License Key for production. Without one the driver runs in Lenient mode and nags in License Status.
  8. Prove it. Wait one interval (or run Record Sample Now) and watch Current Value leave None while the lifetime count in Samples Stored climbs to (1 lifetime). Turn on Debug Mode → Print first to watch the seals, evictions, and refused stale samples the driver logs as the ledger runs.

4 The export payload

Both Export to Lua Output and Export to Endpoint emit the same body in the configured Export Format. Every row carries eight columns; CSV leads with that header line, JSON wraps the rows in an envelope naming the metric, units, privacy mode, generation time, and lifetime sample count.

ColumnMeaning
tierday, day-open, hour, hour-open, or sample
keyLocal calendar key (2026-03-08, 2026-03-08 14) for a bucket, or the sample timestamp for a sample row
countSamples folded into the row
min / avg / maxExtremes and mean across the row
first / lastOpening and closing value — what trend and the one-hour delta read
  • Rows emit coarsest-first (daily, then hourly, then raw) and the payload is capped at 500 rows, truncated from the oldest coarse rows first, so an over-long export always keeps the freshest detail.
  • sample rows exist only under Full History. Under Aggregates Only or Paused the export carries no per-sample rows, because the driver never kept any.
  • Export to Endpoint POSTs the body to Export Endpoint URL with text/csv or application/json. Any non-2xx (or a transport failure) is reported in Status and dropped — the driver never retries a whole-ledger send on its own. A blank URL sends nothing.

5 Program the project

The insight variables update on every recorded sample:

VariableTypeMeaning
METRIC_VALUENUMBERThe most recent recorded value
METRIC_MIN / METRIC_MAX / METRIC_AVGNUMBERExtremes and mean across the retained window (see the sampling contract)
METRIC_TRENDSTRINGRising, Falling, or Steady — a move smaller than a tenth of the window's own spread reads Steady, which keeps the trend unit-agnostic
METRIC_DELTA_1HNUMBERCurrent value minus the closing value of the last sealed hour; 0 until an hour has sealed
SAMPLE_COUNTNUMBERLifetime samples recorded, surviving ring eviction
LAST_SAMPLE_ATSTRINGLocal timestamp of the last sample, or None

Three ways these wire into Composer programming:

  • When New Maximum fires and METRIC_VALUE is above your limit → alert. A fresh all-time high on a freezer temperature or a UPS load drives a Control4 notification or scene. The first sample of a ledger sets the extremes silently and does not fire this.
  • When Source Unavailable fires → notify and light a warning. The configured device stopped returning a number; you get one event per outage, not one per poll.
  • On a scene or door event → call Record Sample Now. With a source configured this reads it immediately, marking that moment on the series; with no source configured it re-stamps the value already at the head of the ledger, and records nothing at all while the ledger is still empty.

Control paths are gated by the license: under Strict enforcement an unlicensed controller records, seals, exports, and clears nothing, and License Status carries the reason. The default Lenient mode allows commissioning with the nag.

8 Ownership, privacy, and licensing

This package is original IntegrateIT engineering — a self-contained Control4 driver that samples a device variable you point it at. It bundles no other vendor's runtime, source, brand assets, trial system, or license. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

Metric values stay on the controller. The one exception is Export to Endpoint: when you set Export Endpoint URL, the driver POSTs the export body to exactly that address and nowhere else — leave it blank and nothing ever leaves the LAN. Privacy Mode governs what is kept and therefore what an export can ever carry: Aggregates Only discards raw samples the moment you select it, so they are neither persisted into the project backup nor available to any export. Persisted data rides inside the project backup, and Storage Estimate is the number to size that against. The configured license key lives in the driver's properties and is never written to the log — Print Configuration deliberately omits it.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks recording, sealing, export, and clearing until the Ops Portal has minted and validated a key for that controller. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

D Diagnostics and self-test

Every IntegrateIT driver carries two read-only Actions for the field. Run Diagnostics prints a report of what the driver has already observed — version and Lua runtime, license mode and cached activation, update channel and any staged build, every armed timer with its interval, which dealer-supplied properties are still empty, and the last few Status messages. It probes nothing, sends nothing, and changes nothing, so it is safe on a live job. Run Self-Test checks the shared layer itself — string and URL encoding, version comparison, the non-finite number guard, the timer registry, and the persistence store — and ends with SELF-TEST PASS or a per-check failure. It stays local: no network, no device commands.

Neither Action is license gated, on purpose: you reach for them when a site is broken, and the license may be the broken thing. Values are never printed — a key or secret is reported only as set or NOT SET, so the output is safe to paste into a support ticket. Both print to the Lua output window (Composer → the driver's Lua tab).

Diagnostics reports what the driver has already observed - never probing the network, never printing a secret. Self-Test proves the shared layer locally and ends PASS or FAIL.
v0.1.12026-07-26
  • Documentation rebuilt to the IntegrateIT commissioning-guide standard: uniform sections, honest contracts, verified claim-by-claim against the code.
  • The window no longer collapses when the open hour is sealed. Under Aggregates Only there are no raw rows by construction, so the window came from the open hourly bucket alone — and `Seal Open Buckets` nils it, dropping min/max/average/trend to zero on a ledger still holding good data. It now falls back to the newest sealed hour.
  • The cascade is explicitly append-only. A sample stamped older than the newest hour the ledger holds used to seal the open hour and reopen a past one, which the next live sample sealed again: two rows for one hour, an hourly ring out of chronological order (so both the export and `METRIC_DELTA_1H` read the wrong row), a spurious `Hour Rolled Over`, and a `Current Value` walking backwards. Stale instants are refused now, and the limitation is documented.
  • `Storage Estimate` billed for the raw sample ring whenever persistence was `Full`, even though privacy outranks persistence in `savePersist` and a `Full` + `Aggregates Only` project stores no raw rows at all. The estimate overstated the backup footprint by the whole sample ring.
  • Restored persistence rows are validated, not merely type-checked. "Is a table" was the entire test, so a table-shaped row missing its numeric fields entered the ring and then threw on the first arithmetic that touched it — taking down the next `RecordSample` and leaving a live driver with a dead ledger. Buckets and samples are now field-validated, and `total` is clamped.
  • Tightening Privacy Mode rebuilds the recent ring empty but left the wrap flag set, silently retiring `Retention Limit Reached` for the rest of the driver's life. Fresh headroom re-arms it, as it already did on a retention resize.
v0.1.02026-07-20
  • First cut of the bounded metric ledger: a three-tier cascade (raw samples into an open hourly bucket, sealed hours folded into an open daily bucket) with a fixed-capacity ring behind each tier, so both memory and project-backup footprint are capped by configuration.
  • Local-calendar bucket keys rather than epoch arithmetic, so a daylight-saving day is still exactly one day; a repeated fall-back hour merges into its open bucket instead of duplicating or resurrecting a sealed one.
  • Insight surface: `METRIC_VALUE` / `METRIC_MIN` / `METRIC_MAX` / `METRIC_AVG` / `METRIC_TREND` / `METRIC_DELTA_1H` / `SAMPLE_COUNT` / `LAST_SAMPLE_AT`, plus events for new extremes, significant change, hour and day rollover, source loss, retention wrap, clear, and export.

  • CSV and JSON export, capped at 500 rows and truncated oldest-coarse-first, to the Lua output window or an HTTP endpoint; a rejected send is reported and dropped rather than retried.
  • Licensing: every control path (record, seal, export, clear) is behind `LicenseGate()`.
