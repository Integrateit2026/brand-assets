1 Overview

IntegrateIT Metrics & Insights turns one numeric value in a Control4 project — a temperature, a power draw, a humidity reading, a tank level, anything exposed as a device variable — into a bounded historical ledger with insights you can program against and an export you can chart anywhere.

The driver samples the value on a fixed interval (or on demand from programming) and keeps it in three fixed-capacity tiers that cascade into one another: raw samples land in the recent ring, the recent samples accumulate into an hourly bucket, and each sealed hour folds into a daily bucket. Every tier is a ring with a capacity you set, so the driver's memory — and the bytes it contributes to a project backup — are bounded by configuration rather than by how long the system has been running. Nothing grows without a ceiling and nothing rescans history; the cost of a sample never changes.

Bucket boundaries come from the controller's local calendar, not from epoch arithmetic. That is what keeps a daylight-saving day a single day, whether it ran 23, 24, or 25 hours.

The driver publishes current / minimum / maximum / average / trend / one-hour-delta as Control4 variables and raises events on new extremes, significant moves, hour and day rollovers, source loss, and retention wrap. It renders no charts: it produces the numbers and the CSV or JSON export, and the picture belongs to whatever you feed it to.

2 Install & setup

  1. Add the driver to a room. It is headless — it has no Navigator tile and no bindings.
  2. Set Metric Name (and optionally Metric Units) so exports and Status read like the thing being measured.
  3. Point it at a source. In Composer, find the device you want to track and note its device id and the variable name you want; put them in Source Device ID and Source Variable. Leave both blank for a push-only series driven entirely from programming.
  4. Choose a Sample Interval. Shorter intervals fill the recent ring faster — at 30 seconds a 240-sample ring covers two hours; at 15 minutes it covers 2.5 days.
  5. Size the three rings: Recent Samples Kept, Hourly Buckets Kept, Daily Buckets Kept. Watch the Storage Estimate property while you do — it reports the ceiling this configuration can ever reach in a project backup.
  6. Decide Privacy Mode and Persist Across Reboot (see Notes & limits). The defaults keep raw samples in memory and persist only the aggregates.
  7. In Programming, react to Sample Recorded, New Maximum, New Minimum, Significant Change, Hour Rolled Over, Day Rolled Over, or Source Unavailable, or compare the METRIC_VALUE / METRIC_TREND / METRIC_AVG variables.
  8. Enter a License Key for production. Without one the driver runs in Lenient mode and nags in License Status.

For a push-only series, call Record Sample Now from programming at the moments that matter. With a source configured that action reads the source immediately; with no source configured it re-stamps the last known value so you can mark an event on the series.

4 Notes & limits

  • Storage is bounded by configuration. Each tier is a ring: once it is full the oldest row is overwritten. The first time a tier starts evicting, *Retention Limit Reached* fires once — not once per evicted row. Samples Stored shows what is held right now; Storage Estimate shows the worst case.
  • Project-backup safety. Persisted data travels inside the project backup, so Persist Across Reboot is an explicit choice: Off writes nothing at all, Aggregates Only writes the bounded bucket rings, Full adds the raw sample ring. Storage Estimate is the number to check before you turn on Full with a 1440-sample ring.
  • Privacy Mode outranks persistence. Full History keeps raw samples. Aggregates Only keeps no per-sample rows at all — they are not stored, not persisted, and not exported. Paused stops capture entirely and disarms the sampler. Switching *to* Aggregates Only is retroactive: the raw samples already held are discarded on the spot rather than left to ride along in the next backup.
  • Timezone and DST. Hour and day identity is a local calendar key from the controller's own clock. Spring-forward simply skips an hour key. Fall-back re-enters the hour key it just used, so the repeated local hour merges into a single hourly bucket covering two real hours — its count and sum stay correct, the bucket is just wider. Either way a local day produces exactly one *Day Rolled Over*.
  • The daily tier is folded from sealed hours, never from raw samples, so nothing is counted twice. The consequence is that the hour in progress is not yet reflected in the day total; run Seal Open Buckets first if you need it to be.
  • Sampling is polling, not subscription. A spike between two samples is not seen. Shorten Sample Interval if that matters, and accept the faster ring turnover that comes with it.
  • Only numbers are recorded. A source variable that does not parse as a number is treated as unavailable, and *Source Unavailable* fires once per outage rather than once per poll.
  • Exports are capped at 500 rows and truncate from the oldest coarse rows first, so an export always keeps the freshest detail. A failed endpoint POST is reported and dropped — the driver never retries a whole-ledger send on its own.
  • Clearing is total. *Clear History* wipes memory and the persisted copy together, and the next sample re-establishes the extremes silently (it does not claim a record).

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

V Version history

v0.1.0 current2026-07-20
  • First cut of the bounded metric ledger: a three-tier cascade (raw samples into an open hourly bucket, sealed hours folded into an open daily bucket) with a fixed-capacity ring behind each tier, so both memory and project-backup footprint are capped by configuration.
  • Local-calendar bucket keys rather than epoch arithmetic, so a daylight-saving day is still exactly one day; a repeated fall-back hour merges into its open bucket instead of duplicating or resurrecting a sealed one.
  • Insight surface: `METRIC_VALUE` / `METRIC_MIN` / `METRIC_MAX` / `METRIC_AVG` / `METRIC_TREND` / `METRIC_DELTA_1H` / `SAMPLE_COUNT` / `LAST_SAMPLE_AT`, plus events for new extremes, significant change, hour and day rollover, source loss, retention wrap, clear, and export.
  • Privacy Mode (Full History / Aggregates Only / Paused) outranks Persist Across Reboot (Off / Aggregates Only / Full); tightening privacy retroactively discards raw rows already held. `Storage Estimate` reports the ceiling a configuration can reach in a project backup.
  • CSV and JSON export, capped at 500 rows and truncated oldest-coarse-first, to the Lua output window or an HTTP endpoint; a rejected send is reported and dropped rather than retried.
  • Licensing: every control path (record, seal, export, clear) is behind `LicenseGate()`.
  • Release Candidate, simulation-verified. No representative hardware acceptance yet.
