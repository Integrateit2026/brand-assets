1 Start here

IntegrateIT Future Automation drives the whole Future Automation mechanism family — TV lifts, ceiling hinges, swivel and articulated mounts, picture lifts, and under-bed lifts (CME, CHR, CHRS, CHS, LSM, FSE90, PL, UBL, PIC, PICSPLIT) — over the serial protocol printed in Future Automation's own installation manuals. Move in, move out, stop, home, swivel left/right, preset and memory-position recall, and a guarded store command, with a paced transmit queue so commands never pile into each other. Commands travel over a direct Control4 RS-232 binding or, byte-for-byte identical, through a serial-over-IP gateway on the LAN.

The published protocol is strictly WRITE-ONLY. The mechanism returns nothing over serial — no acknowledgement, no status, no position. Every position this driver shows is assumed from the last command it sent. A wall switch, IR remote, or a hand on the mechanism is invisible to the driver. No software update can add position feedback to this protocol; anything claiming otherwise would be faking it.
Ready for controlled commissioning. The package, Lua 5.1 runtime, token protocol, dual-transport pacing queue, command-set and store guards, LAN destination check, license gate, persistence, and documentation pass automated QA. A qualified dealer must still complete a fresh install and an observed movement test against a real Future Automation mechanism on the target controller.

What you get

  • Move In / Move Out / Stop — the universal tokens every range implements
  • Home, Swivel Left / Right — articulated and swivel ranges
  • Recall Preset and memory positions A / B / C — plus Store Position, guarded behind an explicit enable
  • A configurable inter-command spacing queue so back-to-back commands never collide
  • Two transports, property-selected: the RS-232 serial binding, or a raw-TCP serial-over-IP gateway
  • Honest assumed-position tracking: Command Sent, Mechanism Assumed In / Out / Stopped, and Preset Recalled events with programming variables

2 The write-only contract

Future Automation's control boxes accept commands and say nothing back — the vendor manuals publish no status, query, feedback, or acknowledgement commands anywhere in the range. This driver is deliberately honest about that:

  • The Assumed Position property and ASSUMED_POSITION variable are dead-reckoned from the commands this driver sent — nothing more.
  • After a controller reboot the position restarts at Unknown. No travel is observable across a reboot on a write-only link, so nothing else would be truthful.
  • Swivel commands articulate the mechanism without a dead-reckonable endpoint, so they leave the assumed position untouched.
  • There is no Navigator proxy promising position on purpose. Programming reacts to the events and variables below; position sliders would be fiction.

3 Wire and commission

Serial (recommended — it is the vendor's native interface):

  1. Locate the socket marked RS232 on the mechanism control box: 6-pin RJ11/RJ25 (pin 1 RX, pin 6 TX, pins 3/4/5 ground) or the 9-pin DE-9 variant.
  2. Wire it to a controller or IO-extender RS-232 port: 9600 baud, 8 data bits, no parity, 1 stop bit, no flow control.
  3. Add IntegrateIT Future Automation to the project and bind Mechanism Serial Port (binding 1) to that port in Connections. Leave Transport at Serial (RS-232).

TCP gateway (serial-over-IP):

  1. Wire a serial-over-IP gateway (e.g. a Global Cache unit) to the control box RS232 port and configure the gateway's serial side for 9600 8N1, raw TCP.
  2. Set Transport to TCP gateway (serial-over-IP), Gateway IP Address to the gateway's LAN address, and Gateway Port to its raw serial-bridge port (often 4999).
  3. The driver holds the socket open, reconnects with backoff, and flushes queued commands in order when the link comes up.

Then, either way:

  1. If the mechanism is a simple lift range (PL, LSM and similar), set Command Set to Simple lift (In / Out / Stop) — the driver will refuse swivel/preset tokens the mechanism does not implement.
  2. Run Move Out / Move In / Stop from the Actions tab. Watch the mechanism — the driver cannot.
Future Automation prints this serial protocol in its public installation manuals precisely so control systems can drive the mechanisms; this driver implements that published contract with original IntegrateIT engineering.

4 Tokens on the wire

Each command is a plain lowercase ASCII token terminated by a carriage return, exactly as documented:

Wire bytesMeaningRanges
fa_out + CRDeploy (TV out / lift deployed)All
fa_in + CRRetract (stowed / concealed)All
fa_stop + CRStop motion immediatelyAll
fa_home + CRDrive to home positionArticulated / swivel
fa_left / fa_right + CRSwivel / articulateArticulated / swivel
fa_preset + CRRecall the preset positionArticulated / swivel
fa_a / fa_b / fa_c + CRRecall memory position A / B / CArticulated / swivel
fa_store + CRStore the current position into memoryArticulated / swivel

There is no addressing and no checksum — the link is point-to-point. Command Spacing paces the queue: the driver never writes two *movement* tokens closer together than the configured gap (default 300 ms), and commands issued faster are queued in order, never dropped. Stop is the deliberate exception — because a lift is moving furniture, fa_stop preempts the queue and bypasses the spacing so it halts motion immediately, discarding any pending movement tokens rather than letting them play out after you asked it to stop. The same bytes go to the serial port or the gateway socket, whichever transport is selected.

5 Store Position is guarded

fa_store overwrites a memory position inside the mechanism — an accidental fire from a scene or a mis-tap would silently destroy a calibrated position. So Store Position is refused unless Enable Store Position is Yes:

  1. Drive the mechanism to the position you want (the manual or the mechanism's own remote defines which memory fa_store writes).
  2. Set Enable Store Position to Yes.
  3. Run Store Position once.
  4. Set Enable Store Position back to No.

Typical pattern: fire Move Out when the room powers on, Move In when it powers off, and use Mechanism Assumed Out to sequence what happens after the (assumed) deploy. On a write-only link, give the mechanism its travel time before acting — the driver cannot tell you when travel finishes.

Control commands are gated by the license: under Strict enforcement an unlicensed controller writes nothing to either transport; the default Lenient mode allows commissioning while License Status carries the nag.

9 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation of the serial control protocol Future Automation prints in its public installation manuals. It does not bundle another vendor's runtime, source code, brand assets, trial system, or license. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT. Future Automation's own warranty terms expressly contemplate third-party control software while excluding it from mechanism warranty coverage — control programming remains the dealer's responsibility.

The driver sends mechanism tokens to your serial port or your LAN gateway and nothing anywhere else. TCP destinations are restricted to private LAN addresses with no WAN override. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks all mechanism control until the Ops Portal has minted and validated a key for that controller. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

  • Command Set selector so simple lift ranges refuse articulated/swivel tokens; Store Position guarded behind an explicit enable.
  • Honest assumed-position model for the write-only protocol: Command Sent, Mechanism Assumed In / Out / Stopped, and Preset Recalled events; assumed position resets to Unknown on reboot by design.
  • MAC-locked IntegrateIT licensing (lenient/strict) gating every wire write, including queued tokens at transmit time.
  • Safety: Stop (fa_stop) now preempts the paced queue and the inter-command spacing window instead of waiting behind them. A lift is moving furniture, and a Stop that queued behind pending moves (or sat out a spacing interval up to 2 s) kept the mechanism travelling — and any movement token ahead of it drove it first. Stop now discards the stale movement backlog and transmits immediately on the active transport (serial or gateway), still license-gated. This makes the "stop immediately" contract in the command and protocol docs actually true.
  • Fixed a TCP auto-reconnect gap: a connect attempt that failed by reporting OFFLINE (never having reached ONLINE) cancelled the connect watchdog without scheduling a retry, wedging the gateway at "Not connected" despite the keep-open intent. Failed initial connects now re-arm the reconnect backoff.
