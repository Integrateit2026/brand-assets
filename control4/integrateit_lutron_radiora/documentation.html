1 Start here

IntegrateIT Lutron RadioRA Classic turns one Control4 serial port into two-way command of a legacy Lutron RadioRA Classic (RadioRA 1) system through its RS232 Interface or Chronos System Bridge and Timeclock: dimmer levels with fades, switch on/off with delays, GRAFIK Eye / Sivoia scenes, phantom button presses including one-touch ALL ON / ALL OFF, and live parsing of the feedback the system pushes back — zone changes, the 32-zone map, the phantom LED map, master control presses, and system modes. Every command line follows Lutron's own published RS232 protocol (P/N 044-038 Rev. A).

LEGACY, DISCONTINUED PRODUCT. RadioRA Classic (RadioRA 1) was discontinued by Lutron long ago; the protocol this driver implements is the final 2004 revision and will never change. This driver exists to keep installed RadioRA Classic homes controllable from Control4 — not to suggest new deployments. For current product, use Lutron's supported RadioRA 2 / RA2 Select / RadioRA 3 drivers instead.
Ready for controlled commissioning. The package, Lua 5.1 runtime, command framing against the published examples, feedback parsing, programming-mode hold, command pacing, license gate, persistence, and documentation pass automated QA. A qualified dealer must still complete a fresh install and an observed lighting test against real RadioRA Classic hardware on the target controller.

What you get

  • Direct zone control for zones 1-32: SDL dimmer level 0-100% with optional 0-240 s fade, SSL switch ON/OFF with optional delay, SGS GRAFIK Eye / Sivoia scene
  • Phantom button presses 1-17 (BP) with ON/OFF/TOGGLE, optional fade, and the documented DS delayed-switch flag; All On / All Off actions for buttons 16 and 17
  • Live two-way feedback: LZC zone changes, ZMP zone map, LMP phantom LED map, MBP master control presses, RSM system modes, REV firmware version
  • Per-zone state variables ZONE_01_STATE … ZONE_32_STATE plus Zone On / Zone Off / Zone Changed / Zone Map Updated / Master Control Button Pressed events
  • A Chronos-aware Bridged System property that adds the documented ,S1 / ,S2 suffix and filters feedback to the selected system
  • A paced transmit queue that respects the interface's one-command input buffer and holds automatically while the RadioRA system is in programming mode

2 The feedback contract

This driver never invents state. Zone states come only from what the system reports:

  • LZC,<zone>,<ON|OFF|CHG> — a zone changed locally. CHG means the zone moved from one ON level to another ON level: the driver keeps it On and fires Zone Changed.
  • ZMP,<32 characters> — the full zone map: 1 on, 0 off, X unassigned, position = zone number. Every differing zone updates, then one Zone Map Updated fires.
  • Six reply types drive state: LZC, ZMP, LMP, MBP, RSM, REV. Anything else the interface pushes — raise/lower reports (RBP / RBR / LBP / LBR) among them — lands in Last Feedback and nowhere else: no event, no variable, no zone state.
  • Sending a command claims nothing. The Status line says "commanded, not confirmed" on purpose — the zone map or a zone change tells you what actually happened. Run Request Zone Map after commissioning (and any time you want certainty) to re-prime all 32 states.
  • The protocol reports on/off only. Individual dimmer levels are never reported by RadioRA Classic and cannot be shown — anything claiming otherwise would be faking it.
  • After a controller reboot every zone restarts at Unknown: nothing that happened while the driver was down is observable. Request Zone Map re-primes the truth.
  • The interface's feedback channels are switchable, persistent device state, and the System-Mode channel (RSM) ships off. At startup this driver asserts the channels it depends on — LZCMON / MBPMON / LMPMON / ZMPMON / RSMMON — so live feedback (and the programming-mode hold, which listens for the pushed RSM,PGM,ENT) actually work. Set Feedback Monitoring to Leave As-Is only when another master on the serial link owns that state. This priming is not counted as a command and never appears in Last Command.

3 Wire and commission

  1. Locate the RadioRA RS232 Interface (RA-RS232 / RB-RS232) or Chronos System Bridge and Timeclock (RA-SBT-CHR / RB-SBT-CHR), powered by its supplied transformer.
  2. Wire a controller or IO-extender RS-232 port to the unit's female DB9: 9600 baud, 8 data bits, no parity, 1 stop bit. TX, RX, and GND are the minimum; hardware handshaking is optional per Lutron.
  3. Add IntegrateIT Lutron RadioRA Classic to the project and bind RadioRA RS232 Port (binding 1) to that port in Connections.
  4. Single system: leave Bridged System at Single System. Chronos bridged pair: set it to the system this instance controls — commands gain ,S1 / ,S2 and the other system's feedback is ignored. One instance drives exactly one system; controlling both halves of a bridged pair takes a second instance with its own serial path to the bridge.
  5. Copy the zone numbers, phantom button assignments, and master control numbers from the installer's RadioRA programming records — the protocol cannot discover them.
  6. Run Request Zone Map and confirm the Zone Map property fills in. Then set Active Zone and exercise Set Dimmer Level / Switch On / Switch Off from the Actions tab, watching the map and Zone State react.
The RS232 Interface counts as one master control in the RadioRA system (a Chronos counts as two per system), and the interface only talks to the system it was programmed into. Zone, phantom button, and master control programming all live in the RadioRA system itself.

4 Commands on the wire

Every line is plain ASCII, comma-delimited, CR-terminated, max 22 characters. Examples exactly as this driver transmits them:

Wire lineMeaning
SDL,3,50Dimmer zone 3 to 50%
SDL,5,75,240Dimmer zone 5 to 75% over 240 s
SSL,8,ON,30Switch zone 8 ON after 30 s
SGS,5,2GRAFIK Eye zone 5 to scene 2
BP,2,TOG,10Toggle phantom button 2 over 10 s
BP,5,OFF,120,DSPhantom 5 OFF over 120 s, switches delayed
BP,16,ONALL ON (fade never applies to 16/17)
BP,17,OFFALL OFF
SDL,19,0,S2Bridged: dimmer 19 off in System 2
ZMPIRequest a fresh zone map

The DS flag is only legal with a fade time and fade only applies to phantom buttons 1-15 — the driver enforces both, so an illegal line never reaches the wire. The system ignores the state field on buttons 16/17, which is why All On and All Off always send exactly BP,16,ON and BP,17,OFF.

Command Spacing (ms) paces the queue: the interface buffers exactly one command and ignores input until it finishes (it issues an ! ready prompt, which the driver strips from feedback). Commands issued faster than the configured gap are queued in order, never dropped. When the system enters programming mode (RSM,PGM,ENT) the interface ignores commands entirely, so the driver holds its queue and resumes automatically on exit — this relies on RadioRA System Mode monitoring, which the interface leaves off by default and the driver enables at startup (see Feedback Monitoring).

Three ways these wire into Composer programming:

  • When your Good Night scene runs → All Off. Call the All Off command (or Phantom Button Press with Phantom Button 17) so one Control4 event clears every RadioRA zone assigned to the ALL OFF phantom.
  • When Master Control Button Pressed fires and LAST_MC_BUTTON is 4 → run a Control4 scene. A physical RadioRA keypad press drives Control4 lighting, audio, or shades in return.
  • When Zone On fires and LAST_ZONE is 12 → announce it. Feedback events let Control4 react to what the lights actually did, never to what was merely commanded.

To drive several zones from programming, set Active Zone first, then invoke the zone command — Composer can write the property and call the command back-to-back; the pacing queue keeps the interface happy. For multi-zone scenes, prefer a Phantom Button Press: Lutron's own guide recommends phantom buttons over repeated direct zone commands for smoother, faster system response.

Control commands are gated by the license: under Strict enforcement an unlicensed controller sends no lighting commands to the serial port — only the ungated startup feedback-monitoring priming (LZCMON … RSMMON) still transmits, so feedback parsing stays live, because monitoring what your own lights report is not a licensed feature. The default Lenient mode allows commissioning while License Status carries the nag.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation of Lutron's published RadioRA RS232 Protocol and Programming Guide (P/N 044-038 Rev. A — a freely downloadable document Lutron published precisely so external equipment could drive RadioRA systems). It does not bundle another vendor's runtime, source code, brand assets, trial system, or license. Lutron, RadioRA, GRAFIK Eye, and Sivoia are trademarks of Lutron Electronics Co., Inc.; IntegrateIT is not affiliated with Lutron, and this driver is not a Lutron product. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

The driver sends lighting commands to your RadioRA serial device and nothing anywhere else. The protocol itself has no login, password, or encryption — physical access to the serial port is the entire security model of this legacy product line, which is one more reason the port should live inside your rack. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks all serial control until the Ops Portal has minted and validated a key for that controller; feedback parsing continues either way. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

D Diagnostics and self-test

Every IntegrateIT driver carries two read-only Actions for the field. Run Diagnostics prints a report of what the driver has already observed — version and Lua runtime, license mode and cached activation, update channel and any staged build, every armed timer with its interval, which dealer-supplied properties are still empty, and the last few Status messages. It probes nothing, sends nothing, and changes nothing, so it is safe on a live job. Run Self-Test checks the shared layer itself — string and URL encoding, version comparison, the non-finite number guard, the timer registry, and the persistence store — and ends with SELF-TEST PASS or a per-check failure. It stays local: no network, no device commands.

Neither Action is license gated, on purpose: you reach for them when a site is broken, and the license may be the broken thing. Values are never printed — a key or secret is reported only as set or NOT SET, so the output is safe to paste into a support ticket. Both print to the Lua output window (Composer → the driver's Lua tab).
