1 Start here

IntegrateIT Colour Wheel is a colour picker for Control4 colour-capable lights that anyone can drive. There is no wheel to aim at: there are twelve named hue stops on a ring you walk with two single-shot commands — Next Hue and Previous Hue — so the whole picker fits behind one keypad button, one voice phrase, or one line of programming. Colour reaches up to six bound lights over the Control4 colour proxy contract (SET_COLOR_TARGET with CIE 1931 xy, or a Kelvin white point on the Planckian locus), with an optional level ramp. Every stop publishes its plain-language name in COLOUR_NAME, so an announcement, a keypad label, or a scene never has to depend on the colour itself being visible.

Release candidate. The conversion spine and the proxy framing are verified in simulation against the published Control4 colour proxy contract, but acceptance on a controller with representative colour fixtures is still pending, and SET_COLOR_TARGET handling differs between fixture vendors. Bind only colour-capable or tunable-white loads: a plain dimmer silently ignores a colour target and answers the level ramp only.
Ready for controlled commissioning. The conversion maths (sRGB D65 primaries with the IEC 61966-2-1 transfer curve, the published Planckian-locus approximation), the proxy framing, the accessible stepper, staging, presets in PersistData, the licence gate, and this documentation pass automated QA in the simulator. A qualified dealer must still complete a fresh install and an observed colour test against real colour fixtures on the target controller.

What you get

  • Twelve named hue stops on a perceptually-spaced ring — dense across the reds and ambers where hue discrimination is finest, sparse across the greens — stepped one button at a time, with no two-dimensional wheel to aim at
  • A Colour-Vision-Safe 6 ring that restricts stepping to six hues along the blue-yellow axis, the axis that survives red-green colour deficiency
  • Every colour published by name (COLOUR_NAME) as well as by value, so a decision never has to rest on the colour being seen
  • One conversion spine — hue stop, saturation, custom hex, or Kelvin — resolving to a single CIE xy chromaticity plus a brightness, so no two readouts can disagree
  • Custom Colour (Hex) accepting #RRGGBB and #RGB, raising an *Invalid Custom Colour* event on bad input and falling back cleanly to the hue stop
  • Full Colour (CIE xy) and Colour Temperature (2000-6500 K) modes across up to six bound lights, at a configurable transition rate
  • Four presets stored in PersistData that survive a controller reboot
  • MAC-locked IntegrateIT licensing with Lenient or Strict enforcement

2 The feedback contract

This driver sends colour; it does not measure it. When you apply, it writes a CIE xy chromaticity (or a Kelvin white point) to every wired light and assumes the fixture obeyed. It has no way to confirm that, and it never pretends to.

  • A non-colour-capable light silently ignores SET_COLOR_TARGET. Nothing errors, nothing in the room changes. Bind only colour or tunable-white loads; a plain dimmer takes the optional level ramp and nothing else.
  • Reported Colour is a passive readout, never a control signal. A bound light can report LIGHT_COLOR_CHANGED / LIGHT_COLOR_CHANGING; the driver records it into Reported Colour and stops. It never re-applies from a report, so it does not detect or correct a fixture that has drifted — reconciling would ping-pong our send against the fixture's report forever, and rounding between our xy and the fixture's native space guarantees it never settles.
  • The driver never repaints a room on its own. Boot, a Director restart, or editing Number of Lights, Transition Rate (ms), or Accessible Palette refreshes the readouts only. Colour goes out when a colour property is edited (with Apply On Change = Yes), a stepper runs, Apply Colour runs, or a preset is recalled — never behind the homeowner's back.
  • The name is the guarantee, not the colour. Colour-Vision-Safe 6 improves separation, it does not promise it: under dichromacy Amber and Yellow — and Cyan, Azure and Blue — differ mainly in lightness and can still be confused. The one thing this driver always gets right is the published name. COLOUR_NAME is always correct, so no decision has to rest on the colour being seen — anything claiming the colour itself is guaranteed distinguishable would be faking it.

3 Wire and commission

  1. Add IntegrateIT Colour Wheel to a room. In Connections, bind each colour-capable light to Light 1 … Light N (up to six).
  2. Set Number of Lights to how many you wired. Bindings above that number are never driven.
  3. Choose a Colour Mode: Full Colour picks a hue from the ring and sends CIE xy; Colour Temperature sends a white point on the Planckian locus between 2000 K and 6500 K.
  4. Set Accessible Palette. Use Colour-Vision-Safe 6 when the operator has a red-green colour deficiency, or whenever the choice needs to survive being described over the phone.
  5. Set Transition Rate (ms) for the fade, and Set Light Level to decide whether the driver also ramps each light to Brightness (%) or leaves level to your other programming.
  6. In Programming, put the accessible controls on hardware: Next Hue on a keypad button, Brighter / Dimmer on a rocker, Warmer / Cooler on another pair. Each is a single command with no parameters, so a one-button remote, a voice scene, and a touch panel all drive the same picker.
  7. Optionally enter a licence key (see Ownership) — the driver runs in Lenient mode without one.
  8. Prove it: run Apply Colour, or step Next Hue, and watch a bound light change while Colour Name updates. Then run Announce Colour to hear the picker read the colour back by name.

4 On the wire

Every apply sends SET_COLOR_TARGET to each wired binding, and RAMP_TO_LEVEL too when Set Light Level is Yes. What travels depends on the mode:

ModeParameters on SET_COLOR_TARGET
Full ColourLIGHT_COLOR_TARGET_X / _Y = CIE 1931 xy, LIGHT_COLOR_TARGET_COLOR_MODE = 0, RATE = transition ms
Colour TemperatureLIGHT_COLOR_TARGET_X = Kelvin, _Y = 0, LIGHT_COLOR_TARGET_COLOR_MODE = 1, RATE = transition ms

The level ramp is RAMP_TO_LEVEL with LEVEL = Brightness (%) and TIME = the transition rate. Lights report back with LIGHT_COLOR_CHANGED / LIGHT_COLOR_CHANGING carrying LIGHT_COLOR_CURRENT_X / _Y / _COLOR_MODE, which the driver reads into Reported Colour and never answers.

Colour Temperature mode carries the Kelvin value in the target X parameter with colour mode 1, per the proxy contract. Fixtures that accept only CIE xy should be driven in Full Colour mode instead.

5 Program the project

ActionWhat it does
Apply ColourPush the current selection to every wired light.
Next Hue / Previous HueStep one named stop along the active ring, wrapping at the ends. Switches to Full Colour and clears Custom Colour (Hex) — a hue press is an explicit request for a named stop.
Warmer / CoolerStep Colour Temperature (K) by 250 K, clamped to 2000-6500. Switches to Colour Temperature mode.
Brighter / DimmerStep Brightness (%) by 10, clamped to 1-100. Only reaches a fixture when Set Light Level is Yes.
Save Preset / Recall PresetStore or restore the whole selection in the slot named by Preset Slot. A recall applies even when Apply On Change is No — recalling is itself the request.
Announce ColourPrint the current colour — name, hex, chromaticity, brightness — to the Lua window and Status. Works unlicensed because it drives nothing.
Print ConfigurationPrint the full picker configuration, including whether the selected preset slot is filled.

Events: *Colour Applied*, *Hue Stop Changed*, *Colour Mode Changed*, *Preset Saved*, *Preset Recalled*, *Invalid Custom Colour*.

Variables: COLOUR_NAME, COLOUR_HEX, COLOUR_HUE, COLOUR_SATURATION, COLOUR_BRIGHTNESS, COLOUR_KELVIN, COLOUR_CIE_X, COLOUR_CIE_Y, COLOUR_MODE.

  • One-button colour cycle. Bind a keypad button to Next Hue. Each press walks the active ring and fires *Hue Stop Changed*; speak COLOUR_NAME on that event so a voice scene names the new colour.
  • Accessible scene by name. On *Colour Applied*, push COLOUR_NAME and COLOUR_HEX to a keypad label or an announcement — the colour stays legible even to someone who cannot see it.
  • Guard a typed colour. Watch *Invalid Custom Colour* to learn that a hex did not parse and the driver fell back to the hue stop; light a "check the hex" indicator instead of leaving the operator guessing.
Custom Colour (Hex) contributes hue and saturation only — its value is ignored on purpose so Brightness (%) owns level and dimming never shifts the hue. Saturation (%) = 0 is white (the D65 point) whatever hue stop is selected, and a grey custom hex resolves to Custom White.

6 Read status at a glance

ReadoutWhat it means
Colour NamePlain-language name of the current colour — a named stop, Custom Azure, or 2700 K Warm White. Starts at Not applied.
Colour HexThe current chromaticity rendered as sRGB hex at full value. A preview only, gamut-clipped at the Kelvin extremes; the xy sent to the light is never clipped. Starts at Not applied.
Colour PointThe CIE xy actually sent (plus Kelvin, in Colour Temperature mode). Trust this over Colour Hex for what the fixture receives. Starts at Not applied.
Reported ColourWhat a bound light last reported. Passive — the driver never re-applies from it. Starts at No report.
StatusThe last thing that happened: Idle, an apply line, Staged … - run Apply Colour, or a caveat (a bad hex, or Set Light Level is No so no level was sent).
License StatusActivated, or Lenient during commissioning. Enter a key before selecting Strict enforcement.

The nine variables mirror the readouts for programming and always agree with each other, because they come from the one resolved sample — drive automation from COLOUR_MODE, COLOUR_NAME, and COLOUR_KELVIN with confidence. Print Configuration dumps the whole picker state — lights, rate, mode, ring, selection, last applied, last reported, and which preset slot is filled — to the Lua output window, and never prints the license key.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation of the documented Control4 colour proxy contract (SET_COLOR_TARGET / RAMP_TO_LEVEL on a LIGHT_V2 binding). The conversion maths are public standards — sRGB D65 primaries with the IEC 61966-2-1 transfer curve, and the published cubic approximation of the Planckian locus. It bundles no other vendor's runtime, source, brand assets, trial system, or license. Driver engineering, Control4 integration, the accessible design, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

Nothing leaves the LAN. The driver sends colour targets to your bound Control4 lights and reads their colour reports back; no colour, project identity, or Control4 credential is sent to any device vendor or off-controller service. Presets live in this controller's PersistData, which is not carried in a Composer project export — restoring a project onto a different controller starts with four empty slots. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below; the license key is never logged.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks every path that drives a light — Apply, the steppers, Save / Recall Preset — until the Ops Portal has minted and validated a key for that controller; Announce Colour and Print Configuration stay available either way, because they read the picker without touching a light. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

D Diagnostics and self-test

Every IntegrateIT driver carries two read-only Actions for the field. Run Diagnostics prints a report of what the driver has already observed — version and Lua runtime, license mode and cached activation, update channel and any staged build, every armed timer with its interval, which dealer-supplied properties are still empty, and the last few Status messages. It probes nothing, sends nothing, and changes nothing, so it is safe on a live job. Run Self-Test checks the shared layer itself — string and URL encoding, version comparison, the non-finite number guard, the timer registry, and the persistence store — and ends with SELF-TEST PASS or a per-check failure. It stays local: no network, no device commands.

Neither Action is license gated, on purpose: you reach for them when a site is broken, and the license may be the broken thing. Values are never printed — a key or secret is reported only as set or NOT SET, so the output is safe to paste into a support ticket. Both print to the Lua output window (Composer → the driver's Lua tab).

  • Documentation rebuilt to the IntegrateIT commissioning-guide standard: uniform sections, honest contracts, verified claim-by-claim against the code.
v0.1.12026-07-20
  • **Next Hue / Previous Hue were dead buttons under a custom hex.** `Custom Colour (Hex)` outranks the hue stop in the resolve spine, so a step moved the property, fired *Hue Stop Changed*, and pushed the same colour — the picker announced a stop the room did not show. A step now retires the override and says so; pressing a hue button is an explicit request for a named stop.
  • **Property echoes applied a second time.** `C4:UpdateProperty` calls back into `OnPropertyChanged` on a controller, which the simulator's stub does not model. A preset recall writes six watched properties before its own deliberate apply — seven colour pushes and seven *Colour Applied* events for one press, 42 proxy commands across six lights. Internal writes now run under a re-entrancy guard that `OnDevicePropertyChanged` honours.
  • **A recall of a legacy or truncated preset could error mid-restore.** `PersistData` outlives the code that wrote it; stored fields went straight to `UpdateProperty`, where a nil throws and a `tostring(nil)` leaves the literal string "nil" in a dealer's property. Every field is now coerced and clamped, and a non-table slot reads as empty.
  • **A custom hex named itself with its hex code.** "Custom #4488CC" is a value, not a name, and a speakable name is this driver's entire accessibility premise. Custom colours now name themselves by nearest named stop ("Custom Azure"); the exact value stays in `COLOUR_HEX`.
  • **Brighter / Dimmer were silently invisible with `Set Light Level` = No.** Brightness only reaches a fixture through the level ramp. The step is still recorded and published, but `Status` now admits no level was sent instead of reporting a colour push.
  • **The Colour-Vision-Safe 6 claim overclaimed.** Six hues on the blue-yellow axis survive red-green deficiency far better than the full ring, but they are not mutually distinguishable under dichromacy — Amber/Yellow and Cyan/Azure/Blue differ mainly in lightness. Catalog copy, limitations, and documentation now say what is true, and name the published `COLOUR_NAME` as the guarantee that actually holds. Two further real limitations documented: the hue-step/hex interaction, and that presets are controller-local because `PersistData` is not carried in a project export.
