1 Start here

IntegrateIT UniFi Protect brings your UniFi Protect cameras' activity into Control4 programming over Ubiquiti's official Protect Integration API — local HTTPS on the UniFi OS console, authenticated by a console-scoped API key you mint yourself (developer.ui.com/protect, spec v7.1.87). No cloud hop, no Ubiquiti account linkage, no Site Manager proxy: the driver talks only to the console on your LAN. It runs two read loops — a camera poll that tracks the inventory and per-camera reachability, and an event poll that reads Protect's motion, smart-detection, and doorbell feed — and turns each into a Composer event with LAST_* variables carrying the camera name.

Events only. This driver surfaces what Protect sees to Control4 programming. It does not show video in Navigator, provision RTSPS streams, take snapshots, or drive PTZ — Navigator camera viewing is out of scope. The event feed is also polled, not pushed (see the contract below), so an event surfaces up to one poll interval late.
Release candidate — verified against the Control4 API simulator, not yet bench-tested. The package, Lua runtime, the Integration API transport (base path, X-API-KEY auth, self-signed-cert TLS posture), camera and event parsing against the official v7.1.87 schema shape, per-event dedup, license gating, the LAN guard, and this documentation all pass automated QA. A qualified dealer must still complete a fresh install and an observed event test against a real UniFi console and cameras on the target controller.

What you get

  • Motion Detected / Motion Ended per camera from Protect's event feed
  • Smart detections — a generic Smart Detection plus Person / Vehicle / Package / Animal Detected, with the type in LAST_SMART_TYPE
  • Doorbell Ring events from G4/G5 doorbells, with LAST_RING_CAMERA
  • Camera inventory (CAMERA_COUNT / CAMERAS_CONNECTED) and Camera Online / Camera Offline on real connection-state transitions
  • Console Online / Console Offline reachability events and a CONSOLE_ONLINE variable
  • A Watched Cameras filter to scope event firing to specific camera ids
  • Diagnostic actions — Test Connection, List Cameras, Print Configuration
  • LAN-only destination guard, an API key that is never written to the log, and MAC-locked IntegrateIT licensing

2 The events-only contract

This driver reports what Protect tells it and nothing more. It reads two endpoints and never fabricates a camera, a state, or an event the console did not report.

  • No media, ever. There is no video, stream, snapshot, or PTZ path in this driver — not disabled, absent. It is an event bridge for programming; anything claiming otherwise would be faking it.
  • The event feed is polled, not pushed. Protect publishes motion / smart-detect / ring events on a WebSocket subscription (GET /v1/subscribe/events). This version polls that path over plain HTTPS every Event Poll (s) (default 3 s) instead of holding a WebSocket, so an event surfaces up to one interval late. A console that answers the path only after a WebSocket upgrade rejects the poll — the driver says exactly that in Event Feed and does not pretend events are flowing. Realtime WebSocket push is planned, not in this version.
  • Camera-offline trails reality. Camera Online/Offline derive from the per-camera connection state reported on the Camera Poll (s) cadence (default 30 s), so a drop is observed up to one camera-poll interval after it happens.
  • CONNECTING is not "down". The console reports CONNECTED, CONNECTING, or DISCONNECTED. Only the two settled endpoints move the published state and fire an event; a transient CONNECTED→CONNECTING→CONNECTED blip (adoption, reconnect) fires nothing, and an unparsable state is never treated as a transition.
  • The camera poll owns the offline verdict. On the wire, Console Offline is declared only by the camera poll's definitive REST endpoint (GET /v1/cameras). The event poll targets a WebSocket endpoint a healthy console can silently drop, so it may only confirm the console is reachable — it never declares it offline, and a transient event-poll drop can't flap Console Offline/Online. The one path outside the camera poll is the LAN guard: a blocked console address marks the console offline from either loop, because nothing was sent at all.
  • A camera is known by its id until inventory names it. Event LAST_* variables carry the camera's name once the camera poll has learned it; until then they carry the raw id. The first observation of any camera adopts its state silently — no boot-time flood of Online/Offline events.

3 Wire and commission

  1. On the console, sign in to UniFi OS → Settings → Control Plane → Integrations → Create API Key. Copy the key immediately — UniFi shows it once. It is console-scoped and sent only as the X-API-KEY header.
  2. Reserve the console's IP address in the router's DHCP table so it cannot move out from under the driver.
  3. Add IntegrateIT UniFi Protect to the project. Set Console IP Address and API Key; leave Console Port at 443 unless you changed it. The address must be on the LAN — a public or routed host is refused unless you deliberately set Allow WAN Console to Yes.
  4. Run the Test Connection action. It calls GET /v1/meta/info and prints the Protect application version the console answered with; Console Status then reads Online — Protect <version>.
  5. Run List Cameras. It prints every camera's id, name, and state. To scope events to specific cameras, paste their ids (comma-separated) into Watched Cameras; leave it empty for all cameras.
  6. In Programming, add reactions to the events below and read the LAST_* variables for the camera name. Trip a real camera and confirm Motion Detected fires, then Motion Ended follows — that proves the whole path end to end.
  7. For production, enter a License Key and run Activate License Now. License Enforcement ships as Lenient (recommended), which lets an unactivated driver fire events while License Status carries the nag; Strict withholds every event until a key is activated against this controller.

4 Protocol on the wire

Every request is HTTPS to the console on the official local base path, with the API key as the only credential. Turn on Debug Mode → Print to watch each call in the Lua output window — method and path only; the key is never shown.

Base path: https://<console>:<port>/proxy/protect/integration

CallPurpose
GET /v1/meta/infoTest Connection — reads applicationVersion
GET /v1/camerasCamera inventory + per-camera state (the authoritative reachability and online/offline source)
GET /v1/subscribe/eventsThe event feed, polled over HTTPS for add / update frames

Event frames are envelopes {"type":"add"|"update","item":{…}} whose item is a discriminated union; the driver keys off the literal type constant (motion, ring, smartDetect…), so JSON key order never matters and a truncated body yields no events at all. A motion frame carrying an end timestamp is what fires Motion Ended; smart frames carry smartDetectTypes.

HTTP statusThe driver's reading
200Parsed normally
401 / 403The console answered but refused the key — check API Key
400 / 404 / 405 / 426 (event feed)This console serves events only across a WebSocket upgrade; reported in Event Feed, camera online/offline keep working
0 (no response)Transport failure. On the camera poll this is the Console Offline verdict; on the event poll it only marks the feed offline, never the console

UniFi consoles ship a self-signed certificate, so the driver relaxes TLS verification by default (ssl_verify_peer / ssl_verify_host off). Set Verify TLS Certificate to Yes only for a console presenting a certificate the controller can validate. On very old OS builds without the modern URL API the driver falls back to a legacy HTTP path that cannot relax verification and may fail against a self-signed console.

Three ways these wire into Composer programming:

  • When Doorbell Ring fires → announce and turn on the entry lights. Read LAST_RING_CAMERA to name which door on a multi-doorbell site.
  • When Person Detected fires after dark → run a "driveway arrival" scene. Gate on LAST_SMART_CAMERA to react only for the camera you mean.
  • When Camera Offline fires → notify the homeowner and log LAST_OFFLINE_CAMERA. Pair it with Camera Online to auto-clear the alert.

Composer event delivery is the licensed product, so every event above — including Console Online/Offline — is held back under Strict enforcement on an unlicensed controller; the read loops still run and the state variables (CONSOLE_ONLINE, CAMERA_COUNT, …) still track, so Status stays honest. Lenient mode fires everything and keeps License Status carrying the nag. Refresh Cameras and Poll Events Now force either loop immediately.

CONSOLE_ONLINE (with the Console Online/Offline events) is the live reachability signal — program against it, not against the text property. Console Status is painted by Test Connection, by the LAN guard, and by a missing console IP; the pollers do not repaint it. On a console you never ran Test Connection against it stays at Unknown even while the driver is polling it happily, so run Test Connection when you want that line refreshed. Print Configuration writes the console, poll intervals, watched-camera filter, TLS/WAN posture, and camera count to the Lua output window — the API key appears only as a character count, never its value.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation of Ubiquiti's published Protect Integration API (developer.ui.com/protect). It bundles no Ubiquiti runtime, source code, brand assets, trial system, or license. UniFi and UniFi Protect are trademarks of Ubiquiti Inc.; IntegrateIT is not affiliated with Ubiquiti, and this driver is not a Ubiquiti product. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

The driver talks only to the UniFi console on your LAN. Nothing goes to Ubiquiti's cloud, api.ui.com, or the Site Manager proxy — a non-LAN console address is refused outright unless Allow WAN Console is set to Yes. The API key lives only in the request header and is never written to the log, not even with Debug Mode on; Print Configuration shows its length, never its value. No camera, event, project, or Control4 identity is sent to any device vendor.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks all Composer event delivery until the Ops Portal has minted and validated a key bound to this controller by MAC; the read loops and state variables keep running either way. Installing this package does not itself mint or activate a controller license, and the shared IntegrateIT license and update services use the controller identity, driver slug, version, configured key, and update channel as documented in the reference below. Self-update is check-and-stage, never silent: with Automatic Update Check on Daily the driver reads the version manifest, reports a newer build in Update Available, and only downloads the .c4z into the controller's driver store when you run Download & Stage Update — you still apply it from Composer.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

D Diagnostics and self-test

Every IntegrateIT driver carries two read-only Actions for the field. Run Diagnostics prints a report of what the driver has already observed — version and Lua runtime, license mode and cached activation, update channel and any staged build, every armed timer with its interval, which dealer-supplied properties are still empty, and the last few Status messages. It probes nothing, sends nothing, and changes nothing, so it is safe on a live job. Run Self-Test checks the shared layer itself — string and URL encoding, version comparison, the non-finite number guard, the timer registry, and the persistence store — and ends with SELF-TEST PASS or a per-check failure. It stays local: no network, no device commands.

Neither Action is license gated, on purpose: you reach for them when a site is broken, and the license may be the broken thing. Values are never printed — a key or secret is reported only as set or NOT SET, so the output is safe to paste into a support ticket. Both print to the Lua output window (Composer → the driver's Lua tab).
