1 Start here

IntegrateIT Paradox EVO turns one Control4 serial port into a two-way bridge to a Paradox Digiplex/EVO security panel through the APR3-PRT3 Printer Module's published ASCII protocol (Paradox doc ASCII-EP00): license-gated area arm and disarm, live zone open/close events the panel pushes on its own, per-area status variables, trouble events with the documented descriptors, and PRT3-to-panel link supervision.

CONVENIENCE INTEGRATION ONLY — NOT AN ALARM PATH. This driver is a convenience integration and is NOT a listed alarm-signaling, monitoring, or life-safety path. It must never replace the panel's keypads, listed communicators, or central-station monitoring. It also NEVER disarms on its own: the only thing that ever sends a disarm frame is the explicit Disarm Area command.
Ready for controlled commissioning. The package, Lua 5.1 runtime, frame formats, RA/RZ reply parsing, system-event decoding, backpressure handling, license gate, user-code secrecy, persistence, and documentation pass automated QA against the published protocol. Nothing here is bench-tested: a qualified dealer must still complete a fresh install and an observed arm/disarm plus event test against a real EVO panel and PRT3 on the target controller.

What you get

  • Arm Area in Regular / Force / Stay / Instant mode, and Disarm Area, for areas 1-8
  • Quick Arm Area with no code (panel One-Touch feature required)
  • Zone Opened / Zone Closed events driven by the panel's own pushed system events
  • AREA_1_STATUS … AREA_8_STATUS variables plus a parsed Area Status readout with alarm / trouble / memory / not-ready / programming / strobe flags
  • Trouble Started / Trouble Restored events (AC failure, battery, bell, clock, TLM, fire loop, zone tamper)
  • Panel Link Lost / Panel Link Restored from the PRT3's COMM&ok / COMM&fail heartbeat
  • On-demand Refresh Area Status and Refresh Zone Status sweeps over a paced queue that honors the PRT3's buffer-full (!) backpressure

2 Safety boundary

Do not build life-safety or security-critical automation on this driver. It is a convenience layer over an unauthenticated serial protocol; the panel, its keypads, and its listed communicators remain the system of record for alarm signaling, monitoring, and life safety. Nothing this driver does is a listed alarm path.

This driver settles the safety questions before they are asked:

  • Not an alarm path. No function here is listed alarm-signaling, monitoring, or life-safety. Those stay on the panel and its listed communicators — always.
  • Never auto-disarm. Exactly one code path builds a disarm (AD) frame — the explicit Disarm Area command — and no received event, timer, schedule, or state change can invoke it. A disarm you program into the project is a deliberate dealer decision. The Area Disarmed event is report-only.
  • An alarm is never suppressed. Every edge into alarm fires Area In Alarm, including the very first observation and including a panel event scoped to area 000 (all-areas / global) that has no single area to pin it to.
  • The user code is a write-only secret. It is embedded in arm/disarm frames because the protocol carries it inline; it is never printed to the log, never placed in a Control4 variable, and masked (AA001A******) everywhere it is displayed. Print Configuration reports only whether a code is set and its digit count.
  • The wire is plaintext. The PRT3 ASCII protocol has no session authentication and no encryption — physical access to the serial run is effectively authority over the panel. Keep the RS-232 run inside the protected premises and treat it as a trusted segment.

3 Wire and commission

  1. Connect the APR3-PRT3 to the panel combus (red / black / green / yellow) per the Paradox instructions.
  2. In PRT3 programming, set section [016] option [1] ON (serial port enabled), option [4] ON (Home Automation usage), and options [5] and [6] OFF (ASCII protocol). Set the baud rate with options [2] and [3] (2400 / 9600 / 19200 / 57600).
  3. Wire a Control4 controller or IO-extender RS-232 port to the PRT3's 9-pin serial port: 8 data bits, no parity, 1 stop bit, no flow control, at the baud you programmed.
  4. Add IntegrateIT Paradox EVO to the project and bind PRT3 Serial Port (binding 1) to that port in Connections, matching the baud.
  5. Watch Panel Link flip to OK — the PRT3 announces COMM&ok at startup when it is talking to the panel.
  6. Enter a panel user code with arming rights in User Code, pick the Area and Arm Mode, then test Arm Area / Disarm Area from the Actions tab with someone at a keypad. Last Command shows the masked frame and the PRT3's &OK echo clears Last Error — that echo means the PRT3 accepted the frame, not that the area armed.
  7. Set Area Count / Zone Count to match the panel, then run Refresh Area Status and Refresh Zone Status and watch Area Status and the AREA_1_STATUS … AREA_8_STATUS variables fill in with what the panel actually reports. That is the proof the whole path works.
Areas 5-8 and zones 49-96 exist only on EVO96 / EVO192 panels. Quick Arm requires the panel's One-Touch arming feature.

4 Frames on the wire

Everything is uppercase ASCII terminated by a carriage return (ASCII 13), exactly per Paradox's published protocol:

Wire frameMeaning
AA001A123456Arm area 1, Regular mode, user code 123456
AA003S12Arm area 3, Stay mode, 2-digit code (codes are 1-6 digits, sent as-is with no padding)
AQ002FQuick arm area 2, Force mode — no code
AD001123456Disarm area 1 with user code
RA001Request area 1 status
RZ048Request zone 48 status

The PRT3 echoes the first five characters of each command followed by &OK or &fail. Because that echo carries only the command's first five characters, it never contains the user code and is safe to surface verbatim in Last Error. A bare ! means the PRT3's receive buffer was full and the frame was not accepted — the driver re-queues that exact frame and retries after the spacing gap, up to three attempts on the wire before it gives up and fires Command Failed. COMM&ok / COMM&fail report the PRT3-to-panel combus link.

An RA reply carries seven positional status characters: arm state (D/A/F/S/I), zone-in-memory (M), trouble (T), not-ready (N), in-programming (P), in-alarm (A), strobe (S). An RZ reply carries five: zone state (C/O/T/F), in-alarm, fire alarm, supervision lost, low battery.

The panel also pushes system events unprompted as GxxxNyyyAzzz (event group, event number, area). That push stream — not polling — is what drives the driver's zone, arming, alarm, and trouble events. For example G001N005A006 means zone 5 in area 6 opened.

Command Spacing paces the queue (default 150 ms) so back-to-back commands never overrun the PRT3's buffer; commands issued faster are queued in order, never dropped.

Three ways these wire into Composer programming:

  • When someone disarms at a panel keypad, Area Disarmed fires → run a "welcome home" scene. Feedback events let Control4 react to what the panel actually did, never to what was merely commanded.
  • When Zone Opened fires and LAST_ZONE_OPENED is 3 → announce the garage door is open. The pushed zone stream drives automation without any polling.
  • On a "Goodnight" event → call Arm Area. The command carries no parameters: it always acts on whatever the Area and Arm Mode properties currently hold, so set both (Stay, for a goodnight) before the command runs. To drive more than one area from programming, set Area first and then call the command — the paced queue keeps the PRT3 happy.

Poll replies establish state silently on first observation (a baseline sweep does not fire an event for every area or zone it primes); pushed panel events and real known-to-known transitions fire. Some disarms are reported only through the panel's special-event group (G022) — a WinLoad, one-touch stay/instant, or voice-module disarm emits no ordinary disarm event, so the driver treats those as a genuine disarm and fires Area Disarmed, and the area variable never reads a stale Armed. The one G022 sub-event that merely cancels an alarm is not a disarm and only clears the alarm flag.

Control commands are gated by the license: under Strict enforcement an unlicensed controller writes nothing to the serial port, and frames already queued when enforcement flips to Strict are dropped rather than fired late. Pushed panel events still update state and fire either way, because reporting an alarm is never a licensed feature and is never withheld.

Area Status always mirrors the area named in the Area property, so switching Area re-points the readout; an area the panel has not reported yet reads Unknown. After any reload every area, zone, and the panel link restart at Unknown — nothing about the live panel is knowable across a reboot, so the driver waits for the PRT3's startup COMM&ok, the pushed event stream, and a refresh sweep to rebuild the picture. The lifetime Commands Sent counter is the one value that survives.

Print Configuration writes the panel link, per-area states, sweep sizes, and the IntegrateIT identity to the Lua output window. It reports only whether a User Code is set and its length — never the code, and never the license key.

8 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation of Paradox's published APR3-PRT3 ASCII serial protocol (the Printer Module exists precisely so home-automation systems can integrate with Digiplex panels). It does not bundle another vendor's runtime, source code, brand assets, trial system, or license. Paradox, Digiplex, and EVO are trademarks of Paradox Security Systems Ltd.; IntegrateIT is not affiliated with Paradox, and this driver is not a Paradox product. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

The driver sends security commands to your PRT3 and nothing anywhere else. The panel user code stays on the serial wire — never in logs, variables, or displays. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks all serial control until the Ops Portal has minted and validated a key for that controller; pushed panel status keeps flowing either way. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.
