1 Start here

IntegrateIT Support Surface puts one support button in the project. It is a Control4 experience button (uibutton proxy 5001) that opens a page you choose — your help desk, your contact form, your service-request portal — inside the Control4 WebView on touchscreens and in the mobile apps. That is the whole job. Everything else in the driver exists to make that one button honest and predictable: a strict HTTPS validator, a live privacy disclosure, no inbound command bridge, and a graceful message when the page is down.

This is a convenience surface, not a monitored support channel or an SLA. The button opens a web page; the optional reachability check is a single GET that proves the server answered — never that the page rendered, and never that a person is reading the request. Treat it as a shortcut to your support path, not a guarantee of one.
Simulator-verified release candidate. The package, Lua 5.1 runtime, URL validator, privacy disclosure, reachability state machine, edge-triggered events, license gate, and persistence pass automated QA. A qualified dealer must still confirm the button on a physical touchscreen and in the mobile apps against the real destination page before handoff. This driver is not bench-tested on hardware.

What you get

  • One Navigator experience button that opens a dealer-configured HTTPS page on touchscreens and in the mobile apps.
  • A strict HTTPS-only validator that names its refusal reason in Destination Status and fires Support URL Rejected instead of pushing a bad URL.
  • No hidden tracking: the URL opens exactly as entered unless you opt in to Send Controller Identity, which appends one disclosed c4mac parameter. Contact details never leave the controller.
  • A read-only Privacy Disclosure property recomputed from the live configuration, plus a Print Privacy Disclosure action.
  • No inbound WebView bridge: a page rendered in this surface has nothing here to drive Control4 with.
  • An optional reachability check (On Open or Hourly) with edge-triggered Support Destination Unreachable / Restored events and a dealer-authored offline message.
  • Support Contact Name, Support Phone, and Support Email published as the SUPPORT_CONTACT variable for announcements and dashboards.
  • MAC-locked IntegrateIT licensing that gates events and monitoring, never the support page itself.

2 What the surface knows

The driver never claims more than it can observe.

  • It supplies a URL, and only a URL. Rendering, scrolling, form input, and accessibility inside the page are the Control4 WebView's behavior and the page's own responsibility. This driver's entire job is to hand Navigator one validated HTTPS address.
  • Reachability is one GET and one status code. A code of 0 (no answer) reads Unreachable — the support page did not answer; 200–399 reads Reachable (HTTP <code>); a 4xx/5xx reads Destination error (HTTP <code>) and is treated as unreachable, because to the person tapping the button a broken page is indistinguishable from a down one. The check proves the server answered; it cannot prove the page rendered correctly.
  • Hourly is blind between checks. It probes once shortly after boot (or after you switch to Hourly) and then once an hour, so an outage that starts and ends between two checks is never observed and raises no event.
  • The probe never carries identity. It fetches the address exactly as entered — never the c4mac parameter, even when Send Controller Identity is on — so the driver never beacons the controller MAC on its own schedule. The status code is identical either way.
  • No inbound bridge. Only a button press (SELECT / DO_CLICK) on binding 5001 is handled; every other proxy command is debug-logged and dropped. A page loaded in this WebView — including a compromised third-party one — has nothing here to reach Control4 through.

3 Wire and commission

  1. Add IntegrateIT Support Surface to the room where the support button belongs.
  2. In that room's Navigator properties, set the *Support* experience button Visible, then Refresh Navigators. The button does not appear until it is made visible and Navigators are refreshed — do this first so every later step can be confirmed from a real Navigator.
  3. Enter your Support URL. It must be a full https:// address with a fully qualified host, e.g. https://support.example.com/help.
  4. Run Validate Support URL. Destination Status should read Validated — HTTPS destination accepted; if not, it names exactly what was wrong (see the validation table below).
  5. Fill in Support Contact Name, Support Phone, and Support Email. These never leave the controller — they publish to the SUPPORT_CONTACT variable so programming can announce a working fallback when the page is down.
  6. Choose Reachability Check: On Open (default) probes the page on each press, Hourly probes in the background, Off makes no request to the page at all, ever.
  7. Write your Offline Message — what a client should hear or see when the page cannot be reached.
  8. Leave Send Controller Identity on No unless the destination genuinely needs to know which site is calling and you have told the client.
  9. Prove it: press the button on a touchscreen. The chosen page opens, Last Opened stamps the time, Support Surface Opened fires, and with Reachability Check on On Open, Destination Status moves to Reachable (HTTP 200). (A press never probes under Hourly — that verdict lands about five seconds after arming and then hourly — and Off never probes at all.)

5 What the validator refuses

The URL goes through a deliberately strict validator before Navigator ever sees it. A refusal writes Rejected: <reason> into Destination Status, sets SUPPORT_URL_VALID to 0, publishes an empty Effective URL, and fires Support URL Rejected — a diagnosable button rather than one that silently opens garbage.

Three starting points, wired with this driver's own events and variables:

  • When Support Destination Unreachable fires → announce SUPPORT_MESSAGE on the kitchen touch screen and show SUPPORT_CONTACT, so the client gets a working phone or email instead of a blank page.
  • When Support Destination Restored fires → clear that "support is down" notice.
  • When Support Surface Opened fires → optionally push a note to the dealer that a client tapped support. The press itself is only ever recorded in Last Opened and this event, both local.

Read SUPPORT_CONTACT on any dashboard as the always-available fallback even when SUPPORT_URL_VALID is 0. Under Strict enforcement an unlicensed controller fires no events and runs no reachability monitoring — but the button still opens the support page, because cutting a client off from their own support contact is not something a license state should do.

9 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation built on documented Control4 UI-button, WebView, and HTTP contracts. It does not bundle another vendor's runtime, source code, brand assets, trial system, or license. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

What leaves the controller is narrow and disclosed: the optional reachability GET of your own support page (the driver reads only its HTTP status code), the opt-in c4mac parameter on the opened URL when you enable Send Controller Identity, and the shared IntegrateIT license and update services, which use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below. Support Contact Name, Support Phone, and Support Email stay on the controller and are never transmitted. The license key is never written to the log. The read-only Privacy Disclosure property states all of this, recomputed from the live configuration, so you can show a client exactly what their support button does.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks the events and the reachability monitoring until the Ops Portal has minted and validated a key for that controller — but never the support page itself. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.
