1 Overview

IntegrateIT Network Agent answers one question, for the handful of devices you actually care about: *is it there, and is it answering promptly?* You name up to six peers — a switch, an AV receiver, an NVR, a head-end server, an access point — and the driver checks each one by opening a single outbound TCP connection to a shared agent port, sending one fixed handshake frame, and closing. The result lands as the Reachable Peers property, the NA_PEERS_REACHABLE / NA_ALL_REACHABLE / NA_LAST_PEER / NA_LAST_RESULT variables, and a Peer Reachable / Peer Unreachable / Peer Degraded event you can program against.

It is deliberately small. The driver has exactly one frame it can emit, so there is no command channel, no shell, no file transfer, and no way to make it do anything to a peer other than ask whether it is up. It probes only the addresses you type in — there is no discovery and no subnet enumeration — and a per-minute budget caps how many probes can be launched, so a sweep can never turn into a scan. Addresses are masked in the log by default and the shared secret is never logged at all.

This is a headless diagnostic: it publishes health for programming and dashboards. It does not restart, reconfigure, or remediate anything.

2 Install & setup

  1. Add the driver to a room. It has no Navigator tile — everything happens in Properties, Actions, and Programming.
  2. Set Number of Peers to how many hosts you want watched, then fill in Peer N Address for each (a reserved LAN IPv4 like 192.168.1.51, or an mDNS name like rack-switch.local). Peer N Label is optional and only affects how the peer reads in status, events, and logs.
  3. Set Agent Port to the port every peer is probed on. One port serves all peers, because they all answer the same IIT-NA/1 handshake.
  4. Enter a Shared Secret if your peers verify one. The driver sends it base64-encoded in each probe so a peer can tell an authorized probe from stray traffic.
  5. Tune the timing: Probe Timeout (s) is how long a probe waits for anything at all, and Slow Response Threshold (s) is the line between Reachable and Degraded. The threshold is clamped below the timeout, so setting it too high yields half the timeout rather than a setting that quietly never fires.
  6. Leave Probe Interval (min) at 0 for on-demand only (the default — nothing goes on the wire until you ask), or set minutes to sweep automatically.
  7. In Programming, react to Peer Unreachable / Peer Degraded to raise an alert, or to All Peers Reachable to clear one. Compare NA_LAST_PEER to know which peer the event was about.

### The IIT-NA/1 handshake {#protocol}

The driver sends one line and reads one line:

->  IIT-NA/1 PING <sequence> <token>
<-  IIT-NA/1 PONG <sequence>

<token> is the base64 of Shared Secret, or - when no secret is set. A reply counts only when the protocol tag matches and the sequence echoes the probe that is currently in flight, so a late reply from an earlier probe can never settle the current one. Anything else on the socket is ignored.

A peer that does not implement IIT-NA/1 is still useful: if it accepts the TCP connection, that alone proves it is up, and the driver reports it Reachable (connect only) when the probe window closes.

4 Notes & limits

  • Allowlist, not a range. The only reachable targets are the Peer N Address slots inside Number of Peers. Lowering that number takes the higher slots out of service immediately, including any probe already in flight on them.
  • LAN-only by default. A private-range IPv4 (10/8, 172.16-31, 192.168/16, 169.254/16), a bare hostname, or an mDNS .local name is accepted. A public IPv4, a routable FQDN, a bare-decimal or 0x numeric host, and any IPv6 literal are refused with a Peer Rejected event and nothing on the wire. Non-canonical octets (010.0.0.0) are refused too, because a resolver would read the leading zero as octal and land somewhere public. Set Allow WAN Peers to Yes only when you genuinely intend to probe off-LAN.
  • Rate limited on purpose. Max Probes Per Minute is a hard ceiling. An over-budget probe is refused and raises Probe Rate Limited rather than queueing, so a large sweep degrades into fewer probes instead of a burst. Lowering the ceiling takes effect immediately, not on the next minute.
  • Degraded is about latency, Reachable is about existence. A peer that connects fast and answers fast is Reachable; one that connects or answers only after Slow Response Threshold is Degraded; a peer that connects but never speaks the protocol is Reachable on the connect alone. Only a peer that never connects at all is Unreachable. Responsiveness is graded against that threshold rather than reported as a millisecond figure, because the driver has no monotonic clock accessor.
  • Retargeting is safe. Editing a Peer N Address while its probe is in flight withdraws the probe silently — no Unreachable event is invented for a host the driver stopped watching. Its verdict resets to Unknown until the next probe.
  • Bounded inbound. At most 512 bytes are retained per peer while a reply assembles, and only complete newline-terminated lines are evaluated. A chatty peer cannot grow driver memory or force a verdict.
  • Redaction. With Log Address Redaction on Redacted (default), addresses in the log and in Last Probe are masked (192.168.x.x, or the first two characters of a hostname). Switch to Full while commissioning if you need the exact target in the log.
  • Statistics persist. The probe / ok / failed / rate-limited totals survive a controller reboot. Use Clear Statistics to reset a baseline.
  • No TLS. The probe is plain TCP; the shared secret is base64-framed, not encrypted. Treat it as a tamper hint on a trusted LAN segment, not as a cryptographic credential.

5 Troubleshooting

SymptomLikely causeFix
Every peer reports UnreachableWrong Agent Port, or a firewall between the controller and the peersConfirm the port from the controller's segment, e.g. nc -vz <peer> <port>.
A peer is always "Reachable (connect only)"The host accepts TCP but does not implement IIT-NA/1Expected. Point Agent Port at a port the peer really serves, or accept connect-only evidence for that peer.

Turn on Debug Mode → Print to watch each probe, the verdict, and the reason in the Lua output window. Addresses stay redacted there unless Log Address Redaction is set to Full, and the shared secret is never printed under any setting.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.

Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

V Version history

v0.1.0 current2026-07-20
  • First cut: bounded LAN reachability diagnostics for 1-6 explicitly allowlisted peers.
  • IIT-NA/1, an original single-frame probe protocol — the driver can only ever emit PING, so there is no remote command channel, shell, or discovery path.
  • Authenticated probes: a base64 shared-secret token on every frame, and a reply is accepted only when the protocol tag and the in-flight probe sequence both match.
  • LAN-only destination guard with canonical-IPv4 parsing (non-canonical octets, numeric hosts, routable FQDNs, and IPv6 refused), overridable per-install by Allow WAN Peers.
  • Per-minute probe budget with a Probe Rate Limited event; a bounded 512-byte inbound buffer; redacted address logging by default and a shared secret that never reaches the log.
  • Verdicts: Reachable, Degraded (answered past the slow threshold), Reachable-connect-only (host accepts TCP but does not speak IIT-NA/1), Unreachable. Sweeps raise Probe Sweep Complete and All Peers Reachable.
  • Cumulative probe statistics persisted across controller reboots, resettable from the Actions tab.
  • Release Candidate, simulation-verified. Representative peer acceptance on a controller is still pending.
  • A settling probe closes its own socket, and the controller reports that close as OFFLINE a moment later. That OFFLINE was landing on the NEXT probe and settling a perfectly reachable peer as Unreachable — a false negative on every second consecutive probe, with no peer involvement at all. The driver now owns the close it asked for and refuses to read it as evidence; a genuine drop still settles immediately.
  • Changing the Agent Port while a probe was in flight left the old probe running and filed its timeout verdict against the new port. It is now withdrawn, like an address change already was.
  • Switching Allow WAN Peers back to No left an already-launched off-LAN probe on the wire until its timeout. The destination guard now bites the moment it is switched on.
  • An mDNS name typed in mixed or upper case ("Rack-Switch.LOCAL") was refused as a routable internet host. DNS labels are case-insensitive and the suffix test now is too.
  • Documented two real limitations that were missing: verdicts (unlike the statistics) do not survive a reboot, and a mid-probe reconfiguration withdraws the probe without a verdict.
