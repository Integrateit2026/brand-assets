1 Start here

IntegrateIT Mode Integration is a house-mode state machine for Control4. It holds one current mode — Home, Away, Night, Vacation, Guest, or any list of modes you name — and publishes that mode to the rest of the project as three Composer variables (MODE_NAME, MODE_INDEX, PREVIOUS_MODE), a read-only Current Mode property, and a single generic Mode Changed event. Instead of scattering the same "when the house goes to Night…" logic behind a dozen keypad buttons and schedule events, you write that programming once and key it off this driver. There is no device protocol and no cloud service behind it — the driver is original IntegrateIT logic that runs entirely on the controller.

This driver owns experience state only. It changes no lights, locks, or thermostats itself — it decides what mode the house is in and fires an event; your project programming is what reacts. Nothing happens physically until you write that programming.
Simulation-verified, ready for controlled commissioning. The package, Lua 5.1 runtime, the finite-state machine (atomic transitions, recursion prevention, validation, wrap-around advance, persistence), the license gate, and this documentation pass automated QA in the LuaJIT simulator. A qualified dealer must still add the driver to a real project and confirm a live keypad-to-mode-to-scene cycle on the target controller. It is not bench-tested against hardware.

What you get

  • Dealer-defined modes from one comma-separated Available Modes list — up to twelve, in your order, index 1 first
  • The active mode exposed as MODE_NAME, MODE_INDEX, and PREVIOUS_MODE variables plus a read-only Current Mode property for keypad LED binding
  • A generic Mode Changed event and a Mode Change Blocked event, so one set of programming keys off every transition
  • Discrete Set Mode 1–4 actions (with optional Mode Slot overrides), Advance to Next Mode (wraps around), and Set to Default
  • Atomic transitions with recursion prevention: re-selecting the current mode is a silent no-op that never re-fires programming
  • The selected mode persists across a controller restart, with a Restore Last Mode on Boot policy you set
  • Print Configuration for a branded diagnostic dump, and MAC-locked IntegrateIT licensing (Lenient or Strict)

2 What this driver knows

The driver's entire truth is the mode you last selected. It observes nothing about the physical house, so it never claims to — everything a mode "means" for the lights or locks lives in your programming, not here.

  • Atomic. A transition writes Current Mode, MODE_NAME, MODE_INDEX, PREVIOUS_MODE, and the persisted copy as one indivisible step, then fires Mode Changed last. Programming never observes a half-applied state, and a listener that loops back into the driver mid-write is refused re-entry.
  • Recursion-safe. Selecting the mode the house is already in is a deliberate no-op: it sets the Status line to Mode already <name> and fires nothing. Multiple triggers — a keypad, a schedule, a geofence — can all assert the same mode without double-running scenes.
  • Persistent, and silent on boot. The selected mode is saved and restored across a controller restart. The restore sets every variable but does not fire Mode Changed — a reboot never re-triggers scenes for the mode already in force. Set Restore Last Mode on Boot to No to always boot to the Default Mode instead.
  • Validated, and de-duplicated. Only a name that is a member of Available Modes can be selected; anything else fires Mode Change Blocked and changes nothing. The list is trimmed of surrounding spaces, blank entries are dropped, and duplicate names collapse to the first occurrence — a repeated token would otherwise strand Advance to Next Mode on a mode it could never leave.

3 Wire and commission

  1. Add IntegrateIT Mode Integration to the project, in a room or Comm the programming can reach. It has no Navigator UI of its own.
  2. In Properties, set Available Modes to your ordered, comma-separated list — for example Home,Away,Night,Vacation,Guest. The first entry is index 1. Up to twelve are parsed; blanks are dropped, each is trimmed, and duplicates are collapsed.
  3. Set Default Mode to the mode the house should rest in. It must be one of the Available Modes; if it is not, the first available mode is used.
  4. Choose Restore Last Mode on Boot: Yes restores the mode in force before a restart, No always boots to the Default Mode.
  5. (Optional) Use Mode Slot 1–4 to pin a specific mode to the discrete Set Mode 1–4 actions regardless of list order. Leave a slot blank to have that action follow the Nth entry of Available Modes.
  6. (Optional) Enter a License Key. Without one the driver runs in Lenient mode; see Ownership, privacy, and licensing.
  7. Prove it: from the Actions tab run Advance to Next Mode and watch Current Mode and MODE_NAME change while a Mode Changed event fires. Run Print Configuration to dump the parsed mode list to the Lua output window.

4 Program the project

Every row below is a Composer Action — bind it to a keypad button, a schedule, or automation. Each mode-changing action is gated by the license: under Strict enforcement without a valid key it is silently ignored, no event fires, and License Status carries the reason. Print Configuration is the one exception — it is a read-only diagnostic and always runs.

The discrete Set Mode 1–Set Mode 4 actions address only the first four modes (or their Mode Slot overrides). Modes 5 through 12 are still fully usable — reach them with Advance to Next Mode, Set to Default, or programming that requests the mode by name. There is no dedicated Set Mode 5…Set Mode 12 action.

Two events to program against:

  • Mode Changed (id 12) — fires on every real transition. Read MODE_NAME and PREVIOUS_MODE inside the handler to branch.
  • Mode Change Blocked (id 13) — fires when a requested mode is not in Available Modes, or an empty slot was selected. It does not fire for a Strict-unlicensed block — that path is silent by design; watch License Status for that.

Variables published for programming and keypad LED feedback:

VariableTypeMeaning
MODE_NAMESTRINGThe active mode's name
MODE_INDEXNUMBERThe active mode's 1-based position in Available Modes. A Mode Slot override reports the mode's real list position, not the slot number
PREVIOUS_MODESTRINGThe mode active before the most recent change; blank after a boot restore

Current Mode is also a read-only property — read it in programming or bind it to a keypad LED.

Three ways this wires into real programming, keying off the driver's own names:

  • When Mode Changed fires and MODE_NAME is Away → lock the doors, set back the thermostat, arm the cameras. The keypad button that requested Away holds no scene logic; the Mode Changed handler does.
  • When Mode Changed fires, MODE_NAME is Night, and PREVIOUS_MODE is Home → run the go-to-bed lighting sweep — but skip it when the house was already Away, so a late arrival home doesn't trigger the bedtime scene.
  • When a "Goodnight" keypad is pressed → call Set Mode 3. One button requests the mode; every Night behavior in the house keys off the resulting Mode Changed, so you write it once.

Because re-asserting the current mode fires nothing, you can safely let several triggers drive the same mode. Editing Available Modes or Default Mode on a live system re-indexes cleanly and, if the active mode was removed, falls back to a valid mode silently — that reconfigure refreshes the variables without firing programming and runs even on an unlicensed Strict controller, because refreshing state is not a control action.

7 Ownership, privacy, and licensing

This package is an original IntegrateIT finite-state machine built on documented Control4 variable, property, event, and action contracts. It bundles no other vendor's runtime, source code, brand assets, trial system, or license. Driver engineering, Control4 integration, documentation, QA, licensing, updates, and support are provided by IntegrateIT.

Nothing about your house leaves the controller. The driver has no device connection and no cloud dependency — mode names, the selected mode, and the persisted copy live only in the project and its persistent store. The one network path is the shared IntegrateIT license and update service, which uses the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below; the license key lives in a property and is never printed to the log.

Lenient mode (the default) allows commissioning without an activated key and keeps License Status visible with a nag. Strict mode silently blocks every mode change until IntegrateIT has minted and validated a MAC-locked key for that controller — state refreshes on reconfigure still run, because they touch nothing physical. With Automatic Update Check left at Daily the driver polls its update manifest and stages a newer package for a dealer to finish installing (in-place staging needs Control4 OS 3.3.1 or newer); installing this package does not itself mint or activate a license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means
LicensedBound to this controller and activated.
Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.
Bound elsewhereThe key is active on another controller. Unbind it in the Ops Portal to move it here.
Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

D Diagnostics and self-test

Every IntegrateIT driver carries two read-only Actions for the field. Run Diagnostics prints a report of what the driver has already observed — version and Lua runtime, license mode and cached activation, update channel and any staged build, every armed timer with its interval, which dealer-supplied properties are still empty, and the last few Status messages. It probes nothing, sends nothing, and changes nothing, so it is safe on a live job. Run Self-Test checks the shared layer itself — string and URL encoding, version comparison, the non-finite number guard, the timer registry, and the persistence store — and ends with SELF-TEST PASS or a per-check failure. It stays local: no network, no device commands.

Neither Action is license gated, on purpose: you reach for them when a site is broken, and the license may be the broken thing. Values are never printed — a key or secret is reported only as set or NOT SET, so the output is safe to paste into a support ticket. Both print to the Lua output window (Composer → the driver's Lua tab).
