1 Start here

IntegrateIT Lifestyle Buttons is an on-controller logic driver: it puts six lifestyle modes and a Reset on their own Control4 Navigator experience pad, with no wire, port, or external device to bind. Exactly one of the seven buttons is lit at any moment — the mode the house is currently in, or Reset when it is in none of them. Tap a mode and the driver enters it and fires the matching programming events; tap Reset and it returns to the resting state. What each mode does to lights, shades, audio, and climate is your Composer programming; the driver owns the selection, and that selection can reach the whole house.

Ready for controlled commissioning. The package, Lua 5.1 runtime, the state engine, Navigator icon states, the Repeat Press / debounce / loop-guard logic, the boot-and-persist policy, the license gate, and this documentation pass automated QA in the LuaJIT simulator. A qualified dealer must still install on a real controller and confirm Navigator button acceptance and idle/active icon rendering on the target hardware — this build is a release candidate and has not been bench-tested.

What you get

  • Seven Navigator experience buttons — six modes (Gather, Unwind, Focus, Refresh, Quiet, Away) plus Reset — with mutually exclusive state and one visibly lit button
  • A configurable Repeat Press policy — Ignore (idempotent), Re-activate, or Toggle Off — for what a press on the already-lit mode does
  • Per-button Press Debounce (ms) that collapses the SELECT + DO_CLICK pair Navigator can send for a single tap
  • Two independent loop guards — re-entrancy refusal and a counting window — that refuse runaway programming with Activation Blocked rather than following it
  • Generic Mode Activated / Mode Deactivated / All Modes Reset events plus discrete Mode 1-6 Activated events for per-lifestyle programming
  • ACTIVE_MODE, ACTIVE_MODE_INDEX, PREVIOUS_MODE, MODE_ACTIVE, and LAST_CHANGE variables, and a Boot Mode policy whose state survives a controller restart

2 State, not loads

This driver owns the selection, never the loads. It changes no light, shade, thermostat, or audio zone on its own — every physical effect is dealer-written programming hanging off its events, and that programming can have broad, whole-house consequences.

It also never invents what the house is doing. There is no feedback path from your loads back into this driver: when a mode activates it fires the event and trusts your programming to carry it out. The lit button and the ACTIVE_MODE variable are authoritative about the driver's state — the lifestyle it last selected — not proof that every load obeyed. Anything claiming the driver knows the house physically reached a lifestyle would be faking it.

Everything around the state change is therefore deliberately conservative:

  • Activation and reset are separate, explicit paths — nothing is inferred. A mode ends because another mode started, because Reset ran, or because its slot was configured away; each of those fires Mode Deactivated so your programming can clean up after itself.
  • Idempotent by default. Under Repeat Press = Ignore, pressing the already-active mode writes no state, fires no activation, and re-runs no programming — it raises Repeat Press Ignored and nothing else, so a scene that takes twenty seconds to settle is never restarted by a leaning finger. The same contract applies to Reset when the house is already at rest.
  • Runaway programming is refused, not followed (see the two loop guards under Program the project).
Because a mode press can drive lights, HVAC, locks, and away scenes across the whole house, review the programming behind every mode — and the Reset scene — before handover. The driver makes the selection safe to run; it does not make the programming safe.

3 Wire and commission

  1. Add IntegrateIT Lifestyle Buttons to the room that should carry the pad. Seven experience buttons appear in Navigator — Gather, Unwind, Focus, Refresh, Quiet, Away, and Reset. Make them visible and Refresh Navigators so every later step can be confirmed from a real Navigator.
  2. Set Modes Enabled to how many of the six slots the project actually uses. A press on a slot above that count is refused — Status reads not enabled and an Activation Blocked event fires instead of the mode activating.
  3. Set Mode 1 Label … Mode 6 Label and Reset Label to this household's names. These rename the mode in Status, the variables, and your programming only — the Navigator button captions are fixed in the driver package and do not follow the labels.
  4. Choose the press semantics: Repeat Press (Ignore by default) and Press Debounce (ms) (400 by default — leave it on unless you are debugging).
  5. Choose the restart behaviour: Boot Mode (Restore Last by default) and Fire Events on Boot (No by default, so a controller restart does not re-run every scene in the house).
  6. Optional: tune Loop Guard Limit (default 8) and Loop Guard Window (s) (default 10), or set the limit to 0 to disable the guard entirely.
  7. In Composer Programming, write what each mode should do — react to Mode 1 Activated … Mode 6 Activated per mode, Mode Activated for anything common to all of them, and All Modes Reset for the return-to-normal scene.
  8. Optional: enter a License Key — the driver runs in Lenient mode without one.
  9. Prove it: press Gather (or run Activate Mode 1). Its button lights, Reset goes dark, Active Mode reads Gather, ACTIVE_MODE_INDEX becomes 1, and Mode 1 Activated fires. Press Reset and the pad returns to the resting label with Reset lit again.

4 Program the project

ActionWhat it does
Activate Mode 1 … 6Enter that lifestyle. Deactivates whichever mode was on.
Advance to Next ModeMove to the next enabled slot, wrapping past the last back to the first. From the resting state it lands on slot 1, and it targets mode slots only — never Reset. The one exception: with Modes Enabled = 1 under Repeat Press = Toggle Off, the wrap lands on the already-active slot and toggles the house back to rest.
Reset All ModesLeave every mode; the house returns to the resting state and Reset lights up.
Print ConfigurationPrint the slots, labels, press policy, loop-guard counters, and boot policy to the Lua output window.

Events: Mode Activated, Mode Deactivated, All Modes Reset, Repeat Press Ignored, Activation Blocked, and Mode 1 Activated … Mode 6 Activated.

Three ways these wire into Composer programming:

  • When Mode 1 Activated fires → run the Gather scene. Write one branch per slot off Mode 1 Activated … Mode 6 Activated: dim the lights, unmute the audio, set the thermostat — whatever that lifestyle means in this house.
  • When Mode Activated fires → do the common work. Anything every lifestyle shares (log it, push a notification) hangs off the generic event; read ACTIVE_MODE_INDEX to branch. Pair it with Mode Deactivated and PREVIOUS_MODE to undo the outgoing mode.
  • When All Modes Reset fires → restore the everyday baseline. Bind a keypad or a schedule to Reset All Modes for one-touch return-to-normal, or to Advance to Next Mode to cycle the house through its enabled lifestyles from a single button.

Loop protection, two independent guards:

  • Re-entrancy. Director dispatches driver events synchronously, so programming that reacts to Mode Activated by activating another mode lands while the driver is still inside the first change — the classic runaway. That request is refused, raises Activation Blocked, and never recurses.
  • Counting window. Loop Guard Limit activations are allowed inside one Loop Guard Window (s); the rest of that window is refused with Activation Blocked, and the window then re-opens on its own. The guard counts activations from every source — Navigator, programming, keypads, schedules — so a legitimately busy sequence can trip it. Raise the limit, or set it to 0 to disable.

Control is license-gated. Under Strict enforcement an unlicensed controller changes no mode and returns before any event — including the Activation Blocked refusal — so nothing in your programming runs; the only sign is the Status line Unlicensed - control disabled (see License Status). One path still corrects the driver's own state while unlicensed: reducing Modes Enabled below the active slot clears it back to rest and darkens its button, but withholds Mode Deactivated and All Modes Reset, so a Composer property edit can never run the whole-house programming every control path refuses. The default Lenient mode allows commissioning while License Status carries the reminder.

5 Read status at a glance

SurfaceTypeWhat it holds
Active ModepropertyThe active mode's label, or the Reset Label when the house is at rest.
Last ChangepropertyThe last change as a sentence: label, source, and timestamp. The sources are Navigator, Programming, boot, configuration, and Modes Enabled reduced; a Toggle Off press carries the press source with a (toggle off) suffix.
ACTIVE_MODESTRING varThe same label as Active Mode.
ACTIVE_MODE_INDEXNUMBER var0 at rest, 1–6 for the active slot. The stable value to branch on — it does not change when a mode is renamed.
PREVIOUS_MODESTRING varLabel of the slot active before the last change (the Reset Label when that was rest).
MODE_ACTIVEBOOL var1 when any mode is active, 0 at rest — the driver writes the BOOL as 1/0, which is what Composer compares against.
LAST_CHANGESTRING varThe timestamp of the last change only — the descriptive sentence lives on the Last Change property, not here.

Program your logic off ACTIVE_MODE_INDEX (numeric, stable) rather than the label, which the household can rename at will; MODE_ACTIVE is the clean "is any lifestyle on" test.

The lit button is authoritative and is re-pushed on every change, including after a controller restart, so Navigator never disagrees with the variables. The active mode is stored in the driver's persistent data and survives a restart: Boot Mode = Restore Last reinstates it, and with the default Fire Events on Boot = No it comes back silently — the state returns without every scene re-firing. A persisted slot that has since been configured above Modes Enabled restores to the resting state instead. If an activation throws mid-publish, Status reads Activation error rather than a false success line.

7 Ownership, privacy, and licensing

This package is an original IntegrateIT implementation built on documented Control4 uibutton-proxy, variable, and programming contracts. It bundles no other vendor's runtime, source code, brand assets, trial system, or license. Driver engineering, Control4 integration, documentation, visual design, QA, licensing, updates, and support are provided by IntegrateIT.

The driver drives no external device and binds no port; it sends no mode state, customer identity, project identity, or Control4 credentials to any device vendor. Mode state lives only in Control4 variables, the read-only properties, and the driver's persistent data. Print Configuration never prints the license key. The shared IntegrateIT license and update services use the controller identity, driver slug, version, configured license key, and update channel as documented in the reference below.

Lenient mode allows commissioning without an activated key and keeps License Status visible. Strict mode blocks every lifestyle control path — activate, reset, and advance — until the Ops Portal has minted and validated a key for that controller. Installing this package does not itself mint or activate a controller license.

L Licensing

This driver is licensed per controller. Each license key locks to one controller's MAC address the first time it activates, exactly like other professional Control4 vendors.

  1. Generate a key for the customer in the IntegrateIT Ops Portal → Licenses.
  2. Paste it into the driver's License Key property in Composer.
  3. On activation the key binds to this controller; the License Status property shows Licensed.

Enforcement. License Enforcement defaults to Lenient (recommended): the driver works the moment it is wired, so you can stage and verify a job before a key is minted, and a paid site keeps running if the license server is ever unreachable. License Status still nags until a key activates. Set it to Strict to disable all control until a valid key binds.

License StatusWhat it means

Not activated, Lenient modeNo valid key yet. Control still works in Lenient mode; enter a key for production.

Revoked / InvalidContact IntegrateIT. Under Strict enforcement control stays disabled until a valid key is entered.
Replaced the controller? Click Unbind in the Ops Portal. The next controller to activate with the key becomes its new home. The driver re-checks on boot and every 12 hours, and keeps working through brief internet outages (it re-validates when the relay is reachable again).

U Automatic updates

The driver checks IntegrateIT for a newer version on boot and once a day. There is no need to re-add the driver. When an update is available the Update Available property shows the new version and the driver fires its Update Available event.

  1. The driver flags Update Available: vX.Y.Z in its properties (or run the Check for Update Now action).
  2. Run the Download & Stage Update action. The new .c4z is fetched onto the controller.
  3. In Composer, right-click the device, then choose Update Driver. Your settings, bindings, and programming are preserved.
Tip: wire the Update Available event to a notification so you know the moment a new build ships.

D Diagnostics and self-test

Every IntegrateIT driver carries two read-only Actions for the field. Run Diagnostics prints a report of what the driver has already observed — version and Lua runtime, license mode and cached activation, update channel and any staged build, every armed timer with its interval, which dealer-supplied properties are still empty, and the last few Status messages. It probes nothing, sends nothing, and changes nothing, so it is safe on a live job. Run Self-Test checks the shared layer itself — string and URL encoding, version comparison, the non-finite number guard, the timer registry, and the persistence store — and ends with SELF-TEST PASS or a per-check failure. It stays local: no network, no device commands.

Neither Action is license gated, on purpose: you reach for them when a site is broken, and the license may be the broken thing. Values are never printed — a key or secret is reported only as set or NOT SET, so the output is safe to paste into a support ticket. Both print to the Lua output window (Composer → the driver's Lua tab).
